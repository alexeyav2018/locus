# Словарь предметной области

Единственный источник терминов. Слова отсюда используются **одинаково** в коде
(имена классов, полей, таблиц), в интерфейсе и в разговоре. Если для понятия
нужно новое слово — оно добавляется сюда, а не заводится по месту.

Ведущий язык — русский: на нём идёт разговор, интерфейс и артефакты OpenSpec.
Столбец **«В коде»** обслуживает код и базу; правило образования имён таблиц,
полей и связей из него — в разделе [«Имена в коде и в базе»](#имена-в-коде-и-в-базе),
объяснение неочевидных имён — в разделе
[«Почему шесть имён не дословны»](#почему-шесть-имён-не-дословны) и в
[ADR-0025](adr/0025-imena-terminov-v-kode.md).

## Библиотека — общая на систему

| Термин | В коде | Значение |
| --- | --- | --- |
| **Рубрикатор** | `Taxonomy` | Дерево классификации задач произвольной глубины. Общий на всю систему, под Администратором. |
| **Раздел** | `Section` | Внутренний узел рубрикатора. Несёт теоретические материалы; задач и отметок владения не несёт. |
| **Тема** | `Topic` | Лист рубрикатора. Несёт задачи и отметки владения. Единица измерения по оси рубрикатора. |
| **Тема-приёмник** | `TopicReceiver` | Тема, на которую при перестройке рубрикатора переезжают задачи и отметки владения другой Темы. Роль в операции, а не отдельная сущность: приёмником законна любая Тема, остающаяся листом **после** операции, включая создаваемого потомка при углублении и родителя при снятии его единственной Темы. Выбирает Администратор; сама система приёмника не назначает ([ADR-0007](adr/0007-pravka-rubrikatora.md)). |
| **Задача** | `Problem` | Отдельная математическая задача: PDF с условием, PDF с решением, номер и разметка — Темы (1..n, только листья), Методы (1..n), Характеристики (0..n), Часть (ровно одна). Существует независимо и переиспользуется. Различается только номером: имени и подписи у Задачи нет — система не знает её текста ([ADR-0050](adr/0050-zadacha-razlichaetsya-tolko-nomerom.md)). |
| **Черновик сборки** | `AssemblyDraft` | Временный исходник, из которого Администратор собирает PDF Задачи: картинка или PDF-сборник, загруженный в форму Задачи. Принадлежит загрузившему, чужому не виден; лежит в рабочей папке сервера, а не в хранилище файлов; живёт до сборки — после сохранения Задачи удаляется, брошенный убирается попутно по сроку и при старте. Не часть библиотеки: у Задачи остаётся только итоговый PDF — собранный либо, если PDF-черновик взят целиком, он сам байт в байт ([ADR-0044](adr/0044-sborka-pdf-zadachi.md), [ADR-0049](adr/0049-odno-pole-fajla-na-slot-zadachi.md)). |
| **Рамка** | `CropFrame` | Прямоугольник, которым Администратор при сборке PDF Задачи обводит на странице Черновика сборки нужный кусок — мышью или пальцем. Кусок ложится в результат отдельной страницей; с одной страницы можно взять несколько кусков. Хранится долями ширины и высоты показанной страницы, а не точками. Способ обрезки выбирает система: векторная страница обрезается сужением видимой области (скрытое за рамкой остаётся в файле), скан и картинка — растром ([ADR-0045](adr/0045-obrezka-kuska-stranicy.md)). |
| **Метод** | `SolutionMethod` | Приём решения («разложение на множители», «теорема о пропорциональных отрезках»). Плоский общий словарь: метод сквозной для разных Тем. Единица измерения по оси методов. |
| **Характеристика** | `Characteristic` | Особенность задачи («наличие формул приведения», «двойной угол»). Используется только для поиска, в измерении владения не участвует. |
| **Часть** | `ExamPart` | Принадлежность задачи к первой или второй части ЕГЭ. В первой части ответ — целое число или конечная десятичная дробь, во второй — произвольное выражение. Используется только для поиска и подбора. |
| **Теоретический материал** | `TheoryMaterial` | Текст, формулы или ссылки по теме. Крепится к любому узлу рубрикатора — и к Разделу, и к Теме. |

## Личный контур — у каждого учителя свой

| Термин | В коде | Значение |
| --- | --- | --- |
| **Ученик** | `Student` | Карточка школьника. Объект учёта, а не пользователь системы. Принадлежит ровно одному учителю. |
| **Выбытие** | `withdrawn` | Состояние Ученика, переставшего заниматься: скрыт из списков и форм выдачи по умолчанию, но не удалён — прежние Задания, Работы и Владение сохраняются. Обратимо («вернуть»). Хранится только текущее значение, истории выбытий нет. |
| **Группа** | `Group` | Именованный список учеников одного учителя. Способ адресовать пачку заданий одним действием. |
| **Задание** | `Assignment` | Набор задач, выданный **одному** ученику, со сроком сдачи. Переиспользуемых шаблонов заданий нет. |
| **Раздача** | `AssignmentBatch` | Одно действие выдачи, породившее несколько Заданий (например, группе из двенадцати человек). Помнит общее происхождение, но не переиспользуется и повторно не выдаётся. |
| **Работа** | `StudentWork` | Присланное учеником решение задачи: обязательный скан или фотография, бинарный вердикт учителя и свободное текстовое примечание. |
| **Владение** | `Mastery` | Отметка учителя о том, владеет ли ученик Методом в рамках Темы. Ставится на паре «Тема × Метод». Шкала: `неизвестно`, `не владеет`, `владеет неуверенно`, `владеет`. Хранится только текущее значение и только с суждением: `неизвестно` — отсутствие строки ([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)). Построено в `mastery-marks`; распределения и пробелы — `mastery-views`. |
| **Занятие** | `Lesson` | Хранимое правило встреч Учителя с одним Учеником **или** одной Группой: дата первой встречи, время начала, длительность и вид — разовое или еженедельное. День недели еженедельного — день его первой встречи; без последней даты оно идёт бессрочно. Правка еженедельного действует с указанной даты: если до неё встречи были, Занятие делится на два ([ADR-0047](adr/0047-zanyatie-pravilo-vstrechi-vychislyayutsya.md)). |
| **Встреча** | `Meeting` | Занятие на конкретную дату с учётом его Поправки: отменённая, перенесённая, с неявкой или как по правилу. Не хранится, а вычисляется из Занятий и Поправок при показе — как «не сдано» по Заданию. |
| **Плановая дата** | `plannedDate` | Дата, на которую Встречу даёт правило Занятия. Остаётся ключом Встречи и после переноса: перенесённая Встреча показывается на новом месте, а плановая дата говорит, откуда она пришла. |
| **Поправка Встречи** | `MeetingAdjustment` | Хранимое исключение из правила на паре «Занятие × плановая дата»: отмена, перенос (дата, время, длительность) и неявка. «Как по правилу» — отсутствие строки; Поправка, в которой ничего не осталось, удаляется. Отмена исключает перенос и неявку ([ADR-0048](adr/0048-popravka-vstrechi-na-pare-zanyatie-data.md)). |
| **Неявка** | `absent` | Пометка «Ученик не пришёл» на Встрече. Бывает только у Встречи с Учеником (не с Группой), только у наступившей и не у отменённой ([ADR-0048](adr/0048-popravka-vstrechi-na-pare-zanyatie-data.md)). |
| **Расписание** | — | Название раздела интерфейса, где Учитель видит неделю Встреч и ведёт Занятия (`/schedule`). Сущностью не является: в коде есть только Занятие и Встреча. |

## Пользователи и роли

| Термин | В коде | Значение |
| --- | --- | --- |
| **Пользователь** | `User` | Учётная запись входа. Имеет произвольный набор ролей; при входе получает объединённый функционал всех своих ролей. |
| **Роль** | `Role` | Набор прав, а не режим работы. Активная роль не выбирается. |
| **Администратор** | `Role.ADMINISTRATOR` | Роль, владеющая общим: рубрикатор, словари, задачи, теория. Единственная, кому доступны разрушительные операции над библиотекой. |
| **Учитель** | `Role.TEACHER` | Роль, владеющая личным: ученики, группы, задания, работы, отметки владения, занятия. Библиотеку читает и использует. |

## Перечисления

Значения перечислений называются здесь по той же причине, что и сами термины:
имя, придуманное по месту, разойдётся со словарём молча.

| Перечисление | Значение по-русски | В коде |
| --- | --- | --- |
| `ExamPart` | первая часть ЕГЭ | `FIRST` |
| | вторая часть ЕГЭ | `SECOND` |
| `MatchMode` | все сразу | `ALL` |
| | любое из | `ANY` |
| `TheoryScope` | без теории | `NONE` |
| | только Темы задач | `TOPICS` |
| | вместе с Разделами | `TOPICS_AND_SECTIONS` |
| `Verdict` | верно | `CORRECT` |
| | неверно | `INCORRECT` |
| `MasteryStatus` | неизвестно | `UNKNOWN` |
| | не владеет | `NOT_MASTERED` |
| | владеет неуверенно | `UNCERTAIN` |
| | владеет | `MASTERED` |
| `Role` | Администратор | `ADMINISTRATOR` |
| | Учитель | `TEACHER` |

`UNKNOWN` и `NOT_MASTERED` — **разные** значения и одно другим не подменяется:
первое означает «сюда не ходили», второе — суждение учителя
([ADR-0012](adr/0012-shkala-vladeniya.md)). В базу `UNKNOWN` не пишется:
это отсутствие строки отметки, а простановка `UNKNOWN` строку удаляет
([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)).

У `Verdict` третьего значения нет: Работа без вердикта — «не проверена»,
и это отсутствие вердикта, а не значение перечисления
([ADR-0014](adr/0014-proverka-bez-avtomatiki.md),
[ADR-0038](adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)).

## Имена в коде и в базе

Имя в базе выводится из имени класса механически — выбирать нечего:

| Что | Правило | Пример |
| --- | --- | --- |
| **Таблица** | имя класса в `snake_case`, единственное число | `Problem` → `problem`, `AssignmentBatch` → `assignment_batch` |
| **Таблица, чьё имя зарезервировано в SQL** | то же плюс завершающее подчёркивание | `User` → `user_`, `Group` → `group_` |
| **Поле** | в Java `camelCase`, в базе то же имя в `snake_case` | `solutionPdf` → `solution_pdf` |
| **Внешний ключ** | имя целевой таблицы плюс `_id`; при нескольких ссылках на одну таблицу впереди уточнение роли | `topic_id`, `author_user_id` |
| **Связующая таблица** | имена связываемых таблиц через подчёркивание; первой — та сущность, которой связь принадлежит | `problem_topic`, `problem_solution_method` |
| **Значение перечисления** | `SCREAMING_SNAKE_CASE` | `NOT_MASTERED` |
| **Пакет предметной области** | английское имя ведущего термина строчными | `ru.locus.problem`, `ru.locus.taxonomy` |

Подчёркивание в `user_` и `group_` — не опечатка и не список исключений,
а правило: `USER` и `GROUP` зарезервированы в PostgreSQL, и таблица с таким
именем потребовала бы двойных кавычек в каждом запросе. Следующее
зарезервированное слово (`order_`, `check_`) разрешается тем же способом,
не пополняя перечень, который некому помнить.

## Почему шесть имён не дословны

Разбор с отвергнутыми вариантами — в
[ADR-0025](adr/0025-imena-terminov-v-kode.md); здесь коротко, чтобы имя
не выглядело случайным и его не «исправили».

| Имя | Причина |
| --- | --- |
| `Problem`, не `Task` | `Task` в английском почти синоним `Assignment` — а это **Задание**, сущность из другой колонки границы общего и личного. `Problem` — обычное слово для задачи из сборника. |
| `SolutionMethod`, не `Method` | `Method` в Java занято: так называется метод класса. `Solution`, а не `Decision`: solution — решение задачи, decision — решение как выбор. |
| `Taxonomy`, не `Rubricator` | В английском «rubricator» — средневековый переписчик; классификационная схема так не называется. `Taxonomy` — именно иерархическая классификация. |
| `ExamPart`, не `UsePart` | Официальная аббревиатура ЕГЭ — USE, но `USE` в коде читается как глагол «использовать» и занято в SQL. Экзамен в системе один, уточнять какой — незачем. |
| `AssignmentBatch`, не `Distribution` | `Distribution` занято другим смыслом: агрегат владения есть распределение по статусам ([ADR-0013](adr/0013-agregaciya-raspredelenie.md)), построено в `mastery-views`. `Batch` — множество, порождённое одним действием. |
| `StudentWork`, не `Submission` | `Solution` исключён — слово закреплено за эталонным решением Задачи; голое `Work` в коде ничего не значит. |

**Идентификаторы бэклога именами в коде не являются.** `openspec/backlog.md`
пользуется историческими именами работ, и три из них с принятым здесь
расходятся: `rubricator-tree` и `rubricator-restructure` при `Taxonomy`,
`submission-review` при `StudentWork`. Идентификаторы не переименовываются —
на них ссылаются в тексте, и они не переиспользуются
(`openspec/backlog.md:80`). Прочие (`problem-catalog`, `mastery-marks`,
`mastery-views`, `mastery-history`, `students-groups`, `theory-materials`,
`assignments`, `topic-merge`, `method-edit-impact`, `teacher-proposes`)
с именами словаря совпадают.

## Слова, вышедшие из употребления

Термины из чернового словаря, которые больше не используются. Оставлены здесь,
чтобы их не завели заново. Имён в коде у них нет и быть не должно.

| Было | Стало | Почему |
| --- | --- | --- |
| **Выдача** | **Задание** | После отказа от шаблонов ([ADR-0016](adr/0016-zadaniya-bez-shablonov.md)) «задание» и «выдача» схлопнулись в одну сущность; держать два слова незачем. |
| **Тип**, **подтип** | **Раздел**, **Тема** | Двухуровневая структура заменена деревом ([ADR-0006](adr/0006-rubrikator-derevo.md)). Кроме того, «тип задания» путался с «Заданием» — тем, что получает ученик. |
| **Ответ** | **Работа** | Ученик ничего не присылает в систему; в математике «ответ» — это число, и путаница была бы неизбежной. |
