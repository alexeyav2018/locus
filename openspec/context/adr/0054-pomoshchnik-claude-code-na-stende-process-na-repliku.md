# ADR-0054. Помощник — Claude Code на стенде по ключу API владельца, процесс на одну реплику; между репликами ничего не работает, сервер MCP внутри приложения

> Запись со статусом `Принято` не переписывается. Если решение изменилось —
> заводится новая запись, а у этой меняются только `status` и `superseded_by`.

## Контекст

Редакция 3 ([ADR-0053](0053-redakciya-3-strategii-pomoshchnik.md)) ставит
в центр помощника — внешнюю модель, которая переписывает лист в текст
и действует в Локусе. Модель — не часть Локуса, к ней нужно обращаться.
Два пути: вызывать API модели из Локуса напрямую, написав свой агентный
цикл на Java (инструменты, история, повторы, пределы), либо запускать
готового агента — Claude Code без интерфейса (`claude -p`), которому Локус
отдаёт инструменты по протоколу MCP.

Три действующие записи стоят на пути:

- [ADR-0017](0017-net-uvedomlenij.md): фоновых процессов нет, система
  целиком «запрос — ответ». Реплика помощника длится десятки секунд
  и минуты — дольше HTTP-запроса; что-то работает после того, как ответ
  странице отдан.
- [ADR-0020](0020-stek.md): одно приложение, одна база, никаких очередей
  и микросервисов. Сервер MCP — ещё одна сетевая поверхность; где ей жить?
- [ADR-0051](0051-ekspluataciya-stenda-vne-repozitoriya.md): эксплуатация
  стенда вне репозитория. Установка агента и ключ — чьё дело?

П4 [strategy.md](../strategy.md): разработчик один, второй оснастки держать
некому. Свой агентный цикл — именно вторая оснастка.

## Решение

1. **Помощник — Claude Code без интерфейса** (`claude -p`), установленный
   на стенде **закреплённой версии**, с ключом API владельца из окружения
   Локуса. Локус запускает его **процессом на одну реплику** и завершает
   по её концу; **между репликами на стенде не работает ничего**. Сеанс
   разговора возобновляется флагом возобновления — историю держит Claude
   Code, Локус хранит идентификатор сеанса и свои записи реплик.
2. **Уточнение ADR-0017.** Планировщика, очередей и процессов, стартующих
   сами, по-прежнему нет. Единственная работа, которая начинается запросом
   пользователя и переживает его, — **реплика помощника**: ограничена
   пределом времени и шагов (числа — из `agent-spike`, в конфигурации),
   одна на учителя одновременно, при старте Локуса незавершённая помечается
   прерванной — как брошенные черновики по [ADR-0044](0044-sborka-pdf-zadachi.md).
   Ничего другого под это уточнение не подпадает: формулировка узкая
   намеренно — расширить проще, чем сузить.
3. **Уточнение ADR-0020.** Сервер MCP, через который помощник действует
   в Локусе, живёт **внутри того же приложения** (Java SDK MCP, транспорт
   HTTP на loopback), не отдельным сервисом. Приложение остаётся одним.
4. **Внешних зависимостей две:** хранилище файлов и модель через Claude
   Code. При недоступности второй помощник недоступен **с названной
   причиной**, остальная система работает. Отсутствие команды, расхождение
   версии с закреплённой, отсутствие ключа Локус не роняют — страница
   помощника говорит почему.
5. **Установка Claude Code и ключ — эксплуатация,** у владельца, вне
   репозитория. **Конфигурация агента** — рабочее место, разрешения,
   навыки — в репозитории и выкладывается с версией Локуса
   ([ADR-0057](0057-lichnost-i-kletka-pomoshchnika-navyki-dokumenty.md)).

## Причины

- Claude Code даёт агентный цикл, клиент MCP, историю разговора и пределы
  готовыми. Свой цикл — месяцы работы одного разработчика и вторая оснастка
  тестов; П4 это запрещает.
- Процесс на реплику — самая узкая форма отступления от «ничего между
  запросами»: границы процесса совпадают с границами реплики, остановить —
  значит убить процесс, после перезапуска ничего не висит.
- Сервер MCP внутри приложения — потому что инструменты зовут сервисы под
  личностью учителя ([ADR-0056](0056-pomoshchnik-vtoroj-klient-servisnogo-sloya.md)).
  Отдельный процесс должен был бы либо видеть базу мимо сервисов, либо
  ходить в Локус по HTTP с собственной авторизацией — второй клиент
  авторизации и второе место для тихой ошибки границы.

## Отвергнутые альтернативы

### Свой агентный цикл на Java через API модели

Отклонена: П4. Клетку — разрешения, инструменты, пределы — пришлось бы
писать и проверять самим, а это ровно то, что у Claude Code уже есть.

### Тёплый процесс агента между репликами

Один процесс на учителя, реплики через стандартный ввод. Отклонена сейчас:
нарушает «между репликами ничего не работает» ради экономии старта,
а по деньгам не экономит — история уходит модели в каждой реплике
в любом случае. Вернуться, если старт процесса окажется заметен учителю.

### Сервер MCP отдельным процессом или stdio-мостом

Отклонена: второй процесс, которому нечего держать, и дублирование
авторизации (см. причины).

### Очередь реплик с планировщиком

Несколько реплик на учителя, исполнение по очереди. Отклонена: это и есть
фоновый процесс ADR-0017; одна реплика на учителя делает очередь ненужной,
а учителю всё равно нечего делать, пока помощник не ответил.

### Внешний клиент (настольное приложение модели, мессенджер) с MCP Локуса

Отклонена: аккаунт у третьей стороны, чужое приложение на планшете,
разговор вне Локуса — то есть не личные данные учителя в системе,
а неизвестно чьи. Учитель разговаривает со своей страницы Локуса.

## Последствия

- `architecture.md`: «Общая форма» получает одно исключение, «Внешние
  зависимости» — вторую. ADR-0017 и ADR-0020 остаются в силе и читаются
  вместе с этой записью.
- Стенду нужны закреплённая версия Claude Code и ключ. Формат вывода
  и флаги команды — чужие и меняются: версия закрепляется, тест-двойник
  команды держит именно её (`agent-runner`).
- Каждая реплика платная по ключу владельца. Стоимость и время показываются
  учителю; пределы берутся из измерений `agent-spike`.
- **Данные уходят за пределы стенда.** Фото листов и текст задач —
  библиотечный материал — отправляются в API модели; это принято. Работы
  учеников — персональные данные детей — помощнику **не отдаются**:
  инструментов личного контура в первой очереди нет, и появление каждого
  такого инструмента — отдельное решение о том, что из личного уходит
  наружу.
- Один помощник на учителя одновременно: вторая реплика до конца первой
  отклоняется.
