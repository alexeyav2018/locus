# ADR-0010. Словарь Методов — плоский и общий

## Контекст

Методы решения, названные учителем, ведут себя по-разному. «Теорема о
пропорциональных отрезках в прямоугольном треугольнике» осмысленна только в
планиметрии. «Сведение к квадратному уравнению» и «разложение на множители»
встречаются и в тригонометрических уравнениях, и в показательных, и в
логарифмических. Первоначально предполагалось, что словарь методов привязан
к разделу; примеры показали, что это неверно как общее правило.

## Решение

Словарь Методов — один плоский, общий на всю систему. Метод не принадлежит
Теме и не дробится по разделам. При разметке задачи система показывает методы,
уже встречавшиеся в этой Теме, а полный список — по отдельному действию.

## Причины

- Метод описывает **приём**, а приём кочует между разделами. Рубрикатор
  описывает **раздел математики**, и там иерархия уместна
  ([ADR-0006](0006-rubrikator-derevo.md)); несимметричность осознанная.
- При дроблении по разделам «разложение на множители» превратилось бы в три
  одинаковые по смыслу записи с разными идентификаторами, статистика по нему
  разложилась бы по ним, и объединить их потом было бы уже нельзя — история
  отметок к тому моменту распределена.
- Сквозной метод даёт знание, которого иначе не получить: владение приёмом
  в одном разделе и невладение им в другом видно только при общем словаре
  ([ADR-0011](0011-otmetka-na-pare.md)).

## Отвергнутые альтернативы

### Словарь методов внутри каждого раздела

Отклонена: расщепляет одинаковые по смыслу методы и делает статистику по
приёму невозможной.

### Показывать при разметке весь словарь целиком

Отклонена по эргономике: при сотне методов форма разметки превращается
в свалку, и учитель начинает выбирать наугад.

## Последствия

- Словарь ведёт Администратор ([ADR-0005](0005-roli-administrator-uchitel.md));
  он же отвечает за то, чтобы в нём не заводились дубли по смыслу.
- Фильтрация списка по Теме требует знать, какие методы уже встречались
  в задачах этой Темы, — это запрос по разметке, а не по справочнику.
- Правка методов у размеченной задачи может оставить ячейку владения без
  единой задачи; поведение не определено, элемент бэклога `method-edit-impact`.
