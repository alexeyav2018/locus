# ADR-0062. Навык ведения бэклога — универсальный, знает номер формата файла и мигрирует несовместимый бэклог только с согласия пользователя; формат проверяется скриптом навыка

## Контекст

Очередь `openspec/backlog.md` ведётся по личному навыку `backlog-maintenance`
(`~/.claude/skills/`, версия 1.1), написанному для очереди дефектов
библиотеки: лексикографический ключ «класс → стоимость → связи →
ломающесть», связи прозой в карточке, один статус ✅. Очередь Локуса
с `backlog-stage-column` (08.09.2026) живёт иначе: порядок задают две
колонки дуг, «Зависимость» и «Не позже», класс и стоимость лишь
предпочитают среди допустимых порядков, значений «Статуса» семь, карточка
постройки устроена не как карточка дефекта. Отличия описаны прозой
в разделе 1 самого бэклога, а `CLAUDE.md` называет навык единственным
источником правил.

Навык и файл разошлись молча, и проверить их соответствие нечем. Копий
навыка две, и они тоже разошлись: в `opentest-skills` у элементов ещё
есть номера. По документации Claude Code личный навык перекрывает проектный
с тем же именем («personal over project»), так что проектная копия
в `opentest-skills` при установленном личном навыке не загружается.

Владелец (26.10.2026): навык нужно доработать и сделать универсальным,
а не заводить проектную копию; начиная работу, навык должен понимать,
может ли он работать с версией этого бэклога, и если не может — сначала,
с согласия пользователя, доработать бэклог.

## Решение

**Метод ведения очереди один — личный навык `backlog-maintenance`, общий
для всех проектов.** Проектных копий и форков нет. Навык описывает очередь,
в которой уживаются постройка и дефекты: порядок — система ограничений
(дуги «Зависимость» и «Не позже» в колонках таблицы запрещают, класс
`Л/Б/Т/Д`, стоимость и ломающесть лишь предпочитают среди допустимых);
карточка двух видов — дефект (симптом, доказательство `файл:строка`, цена,
подходы) и постройка (зачем, основание, что входит, развилки); одна
конвенция отметки о закрытии; общий набор значений «Статуса». Очередь
дефектов без дуг — частный случай: колонки дуг пусты, и порядок задают
ключи предпочтения.

**У файла бэклога есть номер формата**, строкой `<!-- backlog-format: N -->`
в шапке; навык знает, какой номер он умеет. Начиная работу с бэклогом,
навык прогоняет свою проверялку:

- номер совпадает — работает;
- номера нет или он младше — **бэклог не правится**, пока пользователь
  не согласится на миграцию: навык показывает, что изменится, и после
  «да» переводит файл в свой формат по записанной в навыке процедуре
  миграции; без согласия — останавливается, ничего не правя;
- номер старше навыка — навык устарел: ничего не правит и говорит об этом.

**Инварианты файла записаны в навыке разделом и проверяются скриптом
навыка** `check_backlog.py`: ID в дугах существуют, «Зависимость» указывает
выше, «Не позже» — ниже, карточки и строки взаимно однозначны и в одном
порядке, заголовок карточки — зеркало строки таблицы (истина — таблица),
статус в заголовке не стоит, отметка о закрытии одной конвенции, «Статус» —
одно из допустимых значений. Дуга прозой проверяется только чтением.

**В бэклоге проекта метод не пересказывается**: разделы 1–2 хранят факты
этой очереди — происхождение, контракт, доменный инвариант — и ссылку
на навык.

**Проверка уведомляет, но не запрещает.** Помимо проверки при старте
навыка, в Локусе хук `PostToolUse` показывает Claude нарушения в тот же
ход правки бэклога, а `SessionStart` — в начале сессии. В сборку `mvn`
проверка не входит.

## Причины

- Метод в двух местах — тот самый дефект, который элемент чинит:
  `backlog-stage-column` уже однажды разъехался между таблицей
  и карточками именно так. Один навык на все проекты не может разойтись
  сам с собой.
- Номер формата делает несовместимость **видимой до правки**: навык
  старой редакции не испортит файл новой, а новый навык не перепишет
  старый файл молча.
- Миграция по согласию оставляет решение о структуре чужой очереди
  её владельцу: перевод формата трогает весь файл, и делать его попутно
  с другой правкой — значит смешать два пласта в одном коммите.

## Отвергнутые альтернативы

### Проектный форк навыка под своим именем

Метод Локуса жил бы в репозитории и версионировался вместе с ним.
Отклонена владельцем: два метода вместо одного — та же раздвоенность,
перенесённая на уровень навыков; улучшения не переходили бы между
проектами.

### Проектная копия под тем же именем `backlog-maintenance`

Отклонена: личный навык перекрывает проектный, копия не загружалась бы.

### Навык без номера формата, «понимающий» любой файл

Отклонена: навык, молча подстраивающийся под старый файл, снова даёт
два метода — записанный и фактический — без момента, когда они
сверяются.

### Миграция бэклога без вопроса

Отклонена: перевод формата меняет весь документ чужой очереди; это
решение её владельца, а не попутное действие.

### Проверка тестом сборки

Отклонена решением владельца от 08.09.2026: формат очереди — не поведение
системы. Вернуться — если сломанный формат дойдёт до `develop` мимо хука.

### Убрать класс, стоимость и ломающесть из заголовка карточки

Отклонена: дубль, сверяемый проверялкой, больше не разъезжается молча,
а заголовок оставляет карточку читаемой без таблицы.

## Последствия

- Навык живёт вне репозитория Локуса и вне контроля версий: его правка
  не попадает в историю Локуса, а репозиторий хранит только бэклог
  нужного формата и ссылку на навык.
- Бэклог другого проекта с номерами элементов (`opentest-skills`) при
  первой работе нового навыка с ним получит предложение миграции.
- Хуки Локуса вызывают скрипт из каталога личного навыка; на машине без
  навыка хук сообщает, что проверялка не найдена, а не молчит.
- Батч бэклога Локуса читает правило выбора и значения «Статуса» в навыке,
  а не в разделе 1 бэклога.
