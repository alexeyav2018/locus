# ADR-0039. Отметка хранится только с суждением; «неизвестно» — отсутствие строки; при переезде на приёмник отметки сливаются

## Контекст

Шкала владения из четырёх значений ([ADR-0012](0012-shkala-vladeniya.md))
включает `неизвестно` — значение по умолчанию для любой новой пары. При
постройке отметок (`mastery-marks`) пришлось решить три вещи, которых
прежние записи не оговаривали.

**Первое — как хранить `неизвестно`.** Ячейки порождаются употреблением,
а не перемножением словарей (инвариант 4): пар «Тема × Метод», по которым
у ученика есть хотя бы одна задача, всё равно сотни, и почти все они
`неизвестно`. Хранить по строке на каждую — значит держать таблицу, которую
надо пополнять при каждой новой разметке и чистить при каждой правке,
а `countVanishing` при снятии Темы считал бы «отметки», которых учитель
не ставил.

**Второе — что происходит при углублении Темы**, когда Администратор
указывает приёмником **существующую** Тему, а на ней у того же ученика
по тому же Методу уже стоит отметка того же учителя. Задачи в этом случае
просто сливаются в одну метку разметки; у отметок два суждения обязаны
стать одним. [ADR-0007](0007-pravka-rubrikatora.md) отверг слияние
при **снятии** Темы — там получателей несколько; [ADR-0013](0013-agregaciya-raspredelenie.md)
оставил правило слияния «ровно там, где две отметки обязаны стать одной, —
при переезде на Тему-приёмник», но само правило не переписал.

**Третье — что считает справка «по этому методу решено 2 из 6»**
([ADR-0011](0011-otmetka-na-pare.md)). Работа принимается до вердикта
([ADR-0038](0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)), и
непроверенная Работа — это ни «решено», ни «не решено».

## Решение

1. **Строка отметки существует только для трёх значений с суждением**:
   `не владеет`, `владеет неуверенно`, `владеет`. `Неизвестно` — это
   **отсутствие строки**, а не значение в ней. Простановка `неизвестно`
   у ячейки со строкой удаляет строку. Всё, что считает отметки, —
   `countVanishing`, `StudentUsage`, `DictionaryUsage`, будущие
   распределения — считает строки, то есть только суждения.
2. **При переезде на Тему-приёмник отметки сливаются по правилу
   ADR-0013**: если у того же учителя, ученика и Метода на приёмнике
   отметки нет — переезжающая занимает место; если есть и значения
   совпали — остаётся одно; если есть и разошлись — на приёмнике
   становится `владеет неуверенно`. `Неизвестно` в этом правиле
   нейтрально само собой: строки нет — сливать нечего. Правило
   действует только здесь; при снятии Темы отметки исчезают
   без слияния (ADR-0007).
3. **Справка считает только проверенные Работы**: «решено N из M», где
   M — Работы этого ученика на Задачах, размеченных **и** этой Темой,
   **и** этим Методом, у которых есть вердикт, а N — те из них, что
   «верно». Непроверенные Работы в справку не входят. Справка —
   подсказка учителю, а не основание отметки: система по ней ничего
   не выводит ([ADR-0011](0011-otmetka-na-pare.md)).

## Причины

- Отсутствие строки как `неизвестно` — тот же приём, что «не проверена —
  это `verdict IS NULL`» у Работы и «не сдано — не хранится» у Задания
  (инвариант 12): состояние «мы туда не ходили» есть отсутствие данных,
  и не должно выглядеть как данные. Различие `неизвестно` и `не владеет`,
  на котором настаивает ADR-0012, при этом сохраняется: второе — строка.
- Счёт исчезающего при снятии Темы предупреждает о потере **суждений**;
  строка `неизвестно` суждением не является, и считать её значило бы
  завышать предупреждение до бессмысленности.
- Слияние при переезде неизбежно: уникальность пары (учитель, ученик,
  Тема, Метод) не даст двум строкам лечь на одну ячейку, и без правила
  переезд падал бы на ключе или молча терял одну из отметок. Правило
  ADR-0013 — единственное уже обсуждённое; при одном приёмнике оно
  определено однозначно, а его слабость («огрубляет») здесь несущественна:
  случай редкий и касается одной ячейки, а не сводки.
- Непроверенная Работа в справке искажала бы долю: «решено 2 из 6»
  при четырёх непроверенных читается как «четыре провала».

## Отвергнутые альтернативы

### Строка на каждую ячейку-кандидат со значением `UNKNOWN`

Отклонена: требует поддерживать таблицу ячеек при каждой правке разметки
и дерева, а `countVanishing` считал бы пустые строки за суждения.

### При переезде на приёмник с занятой ячейкой — отказ операции

Отклонена: Администратор не видит отметок учителей (ADR-0005) и не смог бы
ни понять причину отказа, ни устранить её; углубление дерева оказалось бы
заблокировано чужими личными данными.

### При переезде оставлять отметку приёмника, переезжающую отбрасывать

Отклонена: тихо теряет суждение, и какое из двух пропадёт, зависит
от направления операции, которого учитель не выбирал.

### Справка по всем Работам, включая непроверенные

Отклонена: см. причины.

## Последствия

- `MasteryStatus.UNKNOWN` остаётся в перечислении для интерфейса и для
  будущих распределений ([ADR-0013](0013-agregaciya-raspredelenie.md)),
  но в базу не пишется; сервис превращает его в удаление строки.
- Распределения по статусам (`mastery-views`) считают `неизвестно` как
  разность между числом ячеек-кандидатов и числом строк.
- Правило слияния живёт в одном месте — в ответе области отметок на
  `NodeContent.moveTopicContent`.
- История отметок по-прежнему не ведётся; `mastery-history`, если
  придёт, эту запись не отменяет.
