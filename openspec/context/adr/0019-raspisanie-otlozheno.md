# ADR-0019. Расписание учителя отложено

## Контекст

Выстраивание расписания — четвёртый из заявленных заказчиком сценариев.
При разборе выяснилось, что с остальной системой он почти не связан:
единственная точка стыковки — что занятие проводится с Учеником или Группой,
которые и так есть.

```
     ЯДРО                              РАСПИСАНИЕ
   +---------------------+          +------------------+
   | задачи, дерево,     |          | занятия,         |
   | методы, задания,    |          | повторы, отмены  |
   | владение            |          |                  |
   +----------+----------+          +---------+--------+
              |                               |
              +------- Ученики / Группы ------+
                    единственная общая точка
```

## Решение

Расписание в первую версию не входит. Делается отдельным этапом после того,
как заработает ядро.

## Причины

- Ничего не ломает и не дорожает от откладывания: связей с ядром нет.
- Объём приличный и обманчивый: календарная механика всегда оказывается сложнее,
  чем выглядит, — переносы, отмены, повторяющиеся занятия, «занятие было, но
  ученик не пришёл».
- Ядро без расписания полезно, расписание без ядра — нет.

## Отвергнутые альтернативы

### Сделать расписание в первой версии

Отклонена заказчиком.

### Сделать урезанное расписание (список занятий без повторов и переносов)

Не рассматривалась: половина календаря обычно хуже, чем его отсутствие, —
учитель всё равно ведёт параллельно свой.

## Последствия

- Термин «Расписание» из чернового словаря пока не используется; вернётся
  вместе с самим разделом.
- Элемент бэклога `schedule`.
- Владелец у занятий будет тот же, что у остальных личных данных учителя.
