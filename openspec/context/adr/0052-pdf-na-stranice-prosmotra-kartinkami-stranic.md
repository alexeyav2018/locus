# ADR-0052. PDF на странице просмотра показывается картинками страниц, отрисованными на сервере

> Запись со статусом `Принято` не переписывается. Если решение изменилось —
> заводится новая запись, а у этой меняются только `status` и `superseded_by`.

## Контекст

[ADR-0042](0042-vtorichnoe-po-knopke-i-vozvrat.md) открыл файлы на странице
просмотра внутри системы: PDF — встроенным просмотром браузера
(`<object type="application/pdf">`) с запасной кнопкой «Открыть PDF». В его
последствиях записано: «встроенный просмотр PDF на телефонах ненадёжен;
запасная кнопка открывает файл как раньше».

Практика опровергла вторую половину. Учитель работает с планшета
(обращение 10.10.2026): браузеры на Android встроенного просмотрщика PDF
не имеют, `<object>` показывает запасное содержимое, а ссылка на PDF
файл не открывает, а **скачивает** — в чужое приложение, вне системы.
Посмотреть условие или решение Задачи в Локусе на планшете нельзя вовсе.

Отрисовка страницы PDF в картинку в системе уже есть: страницу черновика
сборки сервер показывает картинкой JPEG, отрисованной PDFBox
([ADR-0045](0045-obrezka-kuska-stranicy.md)). Но файлы Задач, теории
и Работ лежат в `FileStorage`, у которого операции чтения нет сознательно
([ADR-0021](0021-hranilishche-fajlov.md), `architecture.md`): содержимое
уходило только по подписанной ссылке, прямо из хранилища в браузер.

## Решение

- Страница просмотра показывает PDF **столбцом картинок его страниц**,
  отрисованных на сервере тем же PDFBox. Встроенного просмотра PDF
  (`<object>`, `<iframe>`, `<embed>`) на ней нет. Кнопка «Открыть PDF» —
  сам файл по подписанной ссылке — остаётся рядом.
- Картинка страницы отдаётся приложением по адресу страницы просмотра
  с номером страницы и **по тем же правилам доступа, что и сама страница
  просмотра**: PDF Задач и теории — вошедшим, файлы Работ — только владельцу
  Работы; чужое, несуществующее и страница вне файла — один ответ «нет».
  Это не постоянный адрес файла в смысле ADR-0021: пропуском служит сеанс
  и право на Работу, а не знание ключа, и ключ в адресе не появляется.
- У `FileStorage` появляется **четвёртая операция — прочитать содержимое
  по ключу**. Пользуются ею отрисовка страниц и отдача подписанной ссылки
  файловым хранилищем; права по-прежнему решает сервис выше, хранилище
  не знает владельцев.
- Показывается не больше первых двадцати страниц; у длинного файла страница
  говорит, сколько страниц всего, и остальные — в «Открыть PDF».
- PDF, который не разбирается или закрыт паролем, страница просмотра
  не роняет: она говорит, что показать файл на странице не удалось, и даёт
  «Открыть PDF».
- Встраивание страниц приложения в рамку снова запрещено полностью
  (`X-Frame-Options: DENY`): рамка с того же источника была нужна только
  встроенному PDF.

Остальное из ADR-0042 — вторичное по кнопке, возврат параметром `from`,
изображения картинкой на странице просмотра — не меняется.

## Причины

- `<img>` показывается любым браузером без скрипта и без просмотрщика PDF —
  на Android, iPad и компьютере одинаково; учитель остаётся в системе.
- Отрисовщик уже есть и проверен на рамке сборки: второй, в браузере,
  не появляется, новых зависимостей нет.
- Чтение из хранилища — единственный способ отрисовать файл на сервере:
  обращение сервера к самому себе по подписанной ссылке давало бы то же
  чтение окольным путём и разное поведение двух вариантов хранилища.
  Довод ADR-0021 против чтения («второй путь, которым система в бою
  не пользуется») снят тем, что теперь система им пользуется.
- Двадцать страниц покрывают условие, решение и снимки Работы с запасом,
  а длинный конспект теории не заставляет сервер рисовать сотни страниц
  ради одного открытия.

## Отвергнутые альтернативы

### PDF.js в браузере

Показывает PDF «как есть», с выделением текста и чётким увеличением. Отклонён:
большая чужая библиотека против точечного скрипта из одного файла
([ADR-0041](0041-edinaya-sistema-oformleniya.md)), страница перестаёт
работать без скрипта, а выделение текста учителю при просмотре Задачи
не нужно.

### Оставить `<object>` и сменить текст запасной кнопки

Не решает: на Android файл по ссылке всё равно скачивается и уходит из
системы.

### Отрисовать страницы один раз при загрузке и хранить картинками

Отдача быстрее, но в хранилище появляется второй, производный набор файлов,
который надо заводить, заменять и удалять вместе с исходным, — и переделывать
все уже загруженные файлы. Отрисовка по запросу с проверкой свежести
у браузера проще и обходится без миграции.

## Последствия

- Каждое открытие страницы PDF на сервере читает файл из хранилища
  и отрисовывает страницу; браузер переспрашивает свежесть и получает
  «не изменилось» без отрисовки, пока файл тот же.
- Текст PDF на странице просмотра не выделяется и не ищется; при сильном
  увеличении щипком картинка мягче векторного PDF. Для этого остаётся
  «Открыть PDF».
- Недоступность хранилища теперь видна и на самой странице просмотра PDF,
  а не только при переходе по ссылке.
- Положение ADR-0042 о встроенном просмотре PDF и рамке с того же
  источника больше не действует; ADR-0042 в остальном — в силе.

## Связи

- Уточняет [ADR-0042](0042-vtorichnoe-po-knopke-i-vozvrat.md) (не заменяет):
  меняется только способ показа PDF на странице просмотра и рамка.
- Расширяет [ADR-0021](0021-hranilishche-fajlov.md): у `FileStorage`
  появляется чтение; бакет приватный, наружу файл — по-прежнему только
  по подписанной ссылке.
- Опирается на [ADR-0045](0045-obrezka-kuska-stranicy.md): тот же отрисовщик
  страницы на сервере.
