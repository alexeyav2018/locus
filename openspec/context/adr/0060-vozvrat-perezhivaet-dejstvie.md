# ADR-0060. Возврат from переживает действие страницы; переход прямо по from — только когда следующей страницы нет

> Запись со статусом `Принято` не переписывается. Если решение изменилось —
> заводится новая запись, а у этой меняются только `status` и `superseded_by`.

## Контекст

[ADR-0042](0042-vtorichnoe-po-knopke-i-vozvrat.md) ввёл контекстный возврат
параметром `from` и записал в последствиях: «после действия переход идёт
на раздел по умолчанию, а не обратно по `from`: контекст сохраняется
до действия, а не через него».

Практика разошлась с этой строкой раньше, чем с ней столкнулся учитель:
форма Задачи и страница Встречи уже несут `from` через свои действия
(`problem/form.html`, `ScheduleController.adjust`), и после правки ссылка
«назад» ведёт туда же, куда вела до неё. Сеанс учителя 25.10.2026
показал, чего стоит обратное там, где так ещё не сделано: учитель
из Разговора с Помощником идёт вычитывать черновик, сохраняет его
Задачей — и попадает на страницу Задачи с «← К поиску Задач»; из словарей,
куда его отправила страница черновика, обратно ведёт только кнопка
браузера. Владелец решил (карточка `back-link-gaps`): после заведения
Задачи из черновика — в список черновиков с надписью «Заведена Задача
№ N», а если черновиков не осталось — сразу туда, куда ведёт возврат
списка, обычно в Разговор.

Последнее — переадресация **на сам** адрес из `from`. Такого в Локусе
ещё нет: `ReturnTo` описан как значение, которое «используется только как
`href`, в HTTP-переадресацию оно нигде не попадает».

## Решение

- **Страница, открытая с `from`, сохраняет его через свои действия.**
  Формы страницы и её ссылки на саму себя (выбор узла, записи, фильтр)
  несут `from` дальше, а переадресация после действия ведёт на обычную
  следующую страницу **с тем же `from`**. Ссылка «назад» после действия
  ведёт туда же, куда вела до него.
- **Переход прямо по `from` допустим в одном случае: обычная следующая
  страница пуста по смыслу действия.** Сегодня это одно место — список
  черновиков после утверждения или удаления последнего черновика:
  показывать пустой список ради ссылки «назад» — лишний переход.
  Адрес берётся только проверенный `ReturnTo`, без проверенного —
  раздел по умолчанию той страницы, на которую вёл бы возврат.
- Переадресация по `from` кодирует адрес так, чтобы он ушёл в заголовок
  `Location` тем же, каким пришёл: недопустимые в адресе символы
  кодируются, уже закодированное не трогается.

## Причины

- Связь «откуда пришёл» рвётся именно на действии: до него `from`
  у страницы есть, после — пропадает, и учитель, заведя Метод в словаре,
  не может вернуться к черновику, ради которого его заводил.
- Переадресация на внутренний адрес не открывает дороги наружу:
  `ReturnTo` пропускает только адрес внутри системы, тот же, что уже
  стоит ссылкой «назад» на странице и по которому человек и так перешёл бы.
- Переход прямо по `from` ограничен случаем без следующей страницы:
  в остальных учитель должен увидеть итог действия — изменённую запись,
  оставшиеся черновики, — а не очутиться там, откуда начинал.

## Отвергнутые альтернативы

### Оставить строку ADR-0042 как есть: после действия — раздел по умолчанию

Отклонена: это ровно тот разрыв, на который пожаловался учитель, и форма
Задачи с расписанием от неё уже отошли без записи в журнале — строка
описывала не решение, а прежнее состояние кода.

### После последнего черновика — пустой список с надписью и ссылкой «назад»

Без переадресации по `from` вообще. Отклонена владельцем: лишний переход
на каждый разобранный лист, а показать на пустом списке нечего, кроме
той же ссылки.

### Переход по `from` после любого действия

Отклонена: учитель не видит итога действия — заведена ли запись,
что осталось сделать, — и возврат становится неотличим от «Отмены».

### Хранить «куда вернуться» в сеансе

Отклонена ещё в ADR-0042: ломается при двух вкладках и не переживает
открытие по ссылке.

## Последствия

- Строка последствий ADR-0042 «после действия переход идёт на раздел
  по умолчанию, а не обратно по `from`» больше не действует;
  ADR-0042 в остальном — в силе.
- `from` в адресах растёт вложенно (адрес страницы с `from` сам становится
  чьим-то `from`); предел длины `ReturnTo` обрывает рост, и слишком
  длинный возврат отбрасывается молча — ссылка «назад» ведёт тогда
  на раздел по умолчанию.
- Новая страница с формами, на которую ведут ссылки с `from`, обязана
  нести его через свои формы и показывать «назад»; без этого пробел
  возвращается тихо.
