# ADR-0057. Личность и клетка помощника — токен на реплику и только инструменты Локуса; навыки помощника — документы в репозитории, не спеки, признак готовности навыка — сеанс учителя

> Запись со статусом `Принято` не переписывается. Если решение изменилось —
> заводится новая запись, а у этой меняются только `status` и `superseded_by`.

## Контекст

Помощник — процесс Claude Code на стенде
([ADR-0054](0054-pomoshchnik-claude-code-na-stende-process-na-repliku.md)),
действующий под личностью учителя
([ADR-0056](0056-pomoshchnik-vtoroj-klient-servisnogo-sloya.md)). Процесс
запускает Локус; сессии браузера у процесса нет. Нужно, чтобы инструмент
знал, кто говорит, и чтобы процесс не мог ничего, кроме Локуса: Claude Code
умеет читать файлы, выполнять команды оболочки, ходить в сеть — на стенде
всё это лишнее и опасное.

Поведение помощника — распознать пачкой, подтвердить по одной, Метод завести
только после «да», перечитать перед правкой — не свойство кода, а порядок.
Проверить его тестом нельзя: модель недетерминирована, а оснастка тестов
одна (П4). [ADR-0023](0023-osnastka-sborki.md): требование, которое ничем
не проверяется, в спеки не кладётся — иначе зелёная сборка создаёт
видимость проверки.

## Решение

1. **Личность — токен на реплику.** Локус выпускает токен при старте
   реплики, передаёт процессу через окружение, инструмент MCP узнаёт по нему
   учителя; по завершении реплики токен мёртв. Токен — не пароль
   и не сессия: вне своей реплики им ничего не сделать.
2. **Клетка — только инструменты Локуса.** Процессу разрешены инструменты
   `mcp__locus__*` и ничего больше: ни файлов стенда, ни оболочки, ни сети.
   Рабочее место помощника — папка в репозитории (`agent/`), которую Локус
   разворачивает на учителя; ключ API — в окружении Локуса, не в файлах
   рабочего места. Отдельный пользователь ОС для процесса — желательно,
   но это эксплуатация ([ADR-0051](0051-ekspluataciya-stenda-vne-repozitoriya.md)),
   а не требование репозитория.
3. **Навыки помощника — документы в репозитории** (`agent/CLAUDE.md`,
   `agent/.claude/skills/*/SKILL.md`), **не спеки.** Правятся как текст
   через цикл изменений с `skip_specs: true` и выкладываются с версией
   Локуса: навык называет инструменты, и они должны быть в этой версии —
   сторожит тест по реестру ([ADR-0056](0056-pomoshchnik-vtoroj-klient-servisnogo-sloya.md)).
   **Признак готовности навыка — сеанс учителя** по сценарию, записанный
   в карточке элемента, а не тест.
4. **Навык — вежливость, инструмент — замок.** Всё, что защищает данные,
   держат инструменты и сервисы; навык делает поведение удобным
   и предсказуемым. Нарушение навыка не может испортить данных — если
   может, это дыра в инструменте, а не в навыке.

## Причины

- Токен на реплику — минимальная личность: живёт ровно столько, сколько
  процесс; утечка бесполезна после реплики; авторство действий сохраняется
  за учителем.
- Клетка из разрешений — потому что модель, получившая оболочку, получает
  стенд; инструменты Локуса — единственная поверхность, которую проверяют
  сервисы.
- Навыки вне спек — потому что спеки проверяются, а поведение модели —
  нет (ADR-0023). Честнее признать это и назначить проверкой живого
  учителя, чем писать требования, которых никто не прогонит.

## Отвергнутые альтернативы

### Сессионный cookie учителя процессу

Отклонена: живёт дольше реплики и даёт страницы, а не инструменты;
процесс, умеющий ходить по страницам, — не клетка.

### Долгоживущий ключ на учителя

Как у интеграций. Отклонена: его надо хранить, отзывать и ротировать,
и лежал бы он в файлах рабочего места агента.

### Служебный пользователь «Помощник» с ролью

Отклонена: действия потеряли бы автора, а владельца личных данных
пришлось бы передавать параметром — против [ADR-0027](0027-mehanizm-granicy-obshchego-i-lichnogo.md).

### Навыки как спеки с тест-двойником модели

Отклонена: двойник проверяет разбор вывода, а не поведение; зелёный
тест давал бы ложную уверенность — та же беда, что тихий пропуск тестов
без Docker.

### Поведение навыка в коде

Конечный автомат диалога: Локус сам ведёт «распознай — подтверди — сохрани».
Отклонена: теряет смысл агента и даёт вторую систему — код диалога, —
которую некому писать (П4).

## Последствия

- В репозитории появляется папка `agent/` — исходники помощника, не Java;
  меняется с версией Локуса и выкладывается вместе с ним.
- Тест реестра — единственная автоматическая проверка навыков: выдуманный
  инструмент роняет сборку, плохой порядок действий — нет.
- Приёмка навыков требует времени учителя: `intake-skill`
  и `backfill-skill` закрываются сеансом, а не зелёной сборкой.
- Клетка не защищает от того, что данные библиотеки уходят в API модели, —
  они уходят туда по самому устройству помощника (ADR-0054); клетка
  защищает стенд и личные данные, к которым у помощника нет инструментов.
