# ADR-0021. Файлы — в приватном объектном хранилище за интерфейсом FileStorage

## Контекст

Система хранит два потока файлов: PDF задач и теории — их немного и загружает
их Администратор; сканы ученических работ
([ADR-0015](0015-skany-rabot-hranyatsya.md)) — их много и они растут постоянно,
порядка сотен изображений в неделю. Рассматривался вопрос, нельзя ли
использовать уже оплаченное место на Яндекс.Диске.

## Решение

Файлы хранятся в **объектном хранилище** (S3-совместимом; в рамках выбранной
инфраструктуры — Яндекс Object Storage). Бакет **приватный**, файлы отдаются
по временным подписанным ссылкам.

Доступ к хранилищу спрятан за интерфейсом **`FileStorage`** («положить»,
«получить ссылку», «удалить») с несколькими реализациями — объектное хранилище
для работы, локальная папка для разработки и тестов.

## Причины

- Объектное хранилище — сервисный доступ по ключам сервисного аккаунта, а не
  по личному токену человека; протокол S3-совместимый, значит те же вызовы
  работают с локальным MinIO в тестах и с другим поставщиком при переезде.
- Подписанная ссылка вычисляется локально из ключа, без сетевого обращения:
  при показе списка из пятидесяти задач это заметно.
- Приватность обязательна: PDF с решениями не должны попадать к ученикам, а
  сканы работ — персональные данные детей.
- Интерфейс `FileStorage` делает выбор поставщика обратимым и стоит одного
  интерфейса с парой реализаций.

## Отвергнутые альтернативы

### Яндекс.Диск

Отклонён, хотя место уже оплачено. Причины: файлы оказались бы в личном
аккаунте живого человека (смена пароля, двухфакторная аутентификация или
передача доступа коллеге становятся проблемой); OAuth-токен требует продления,
тогда как ключи сервисного аккаунта статичны; за каждой отдачей файла —
обращение к внешнему API с его задержкой и лимитами, рассчитанными на человека,
а не на программу; проприетарный API вместо S3 привязывает к поставщику.
Экономия при этом иллюзорна: объём измеряется единицами гигабайт.

### Файлы в обычной папке на VPS

Отклонена как основной вариант, но остаётся реализацией `FileStorage` для
разработки. Работает и стоит ноль, однако бэкап целиком на владельце, место
ограничено диском сервера, а при переезде файлы придётся переносить руками.

## Последствия

- Снимки с телефона нужно пережимать при загрузке, иначе объём растёт впустую.
- Публичный бакет или постоянная ссылка на файл — утечка, а не небрежность;
  занесено в `antipatterns.md`.
- Появляется зависимость от внешнего сервиса — единственная в системе
  ([ADR-0017](0017-net-uvedomlenij.md)); при её недоступности недоступны файлы,
  но не данные.
- SDK хранилища не должен просачиваться в сервисный слой: работать только через
  `FileStorage`.
