# ADR-0049. У слота Задачи одно поле файла, и нетронутый PDF ложится в слот байт в байт

## Контекст

[ADR-0044](0044-sborka-pdf-zadachi.md) добавил к готовому PDF Задачи второй
путь — сборку из картинок и страниц PDF — и оставил оба. На форме это
выглядит как два поля выбора файла на каждый слот: «PDF условия» и «или
собрать из картинок и страниц PDF»; то же в блоках замены файла. Учитель,
работая со стенда 08.10.2026 (Locus 1.2.0), не понял, зачем два, и
предложил оставить одно — второе: выбрал файл и ничего с ним не делал —
файл ложится целиком; задал диапазон, обвёл рамкой, добавил ещё файлы —
собирается по заданному.

Строка сборки и так по умолчанию берёт исходник целиком, страницы 1…N
без рамки, поэтому желаемое поведение у второго поля почти есть. Но
«целиком через сборку» сегодня отличается от готового PDF тремя
свойствами, и убранное поле унесло бы их молча:

1. готовый PDF хранится **байт в байт**, собранный — новый файл: страницы
   перенесены, а ссылки, комментарии и закладки — нет;
2. готовый PDF принимается без скрипта, сборка — только со скриптом;
3. готовый PDF держит общий предел загрузки (20 МБ), исходник сборки —
   предел инструмента, крупнее.

## Решение

**У каждого слота Задачи — одно поле файла: поле сборки. Порядок сборки,
который берёт ровно один PDF целиком — все страницы, без рамки, — кладёт
в слот сам исходный файл, без пересборки.** Любой другой порядок
собирается, как прежде.

1. Признак «целиком» вычисляется по порядку сборки, а не задаётся
   переключателем: одна строка, черновик — PDF, страницы с первой
   по последнюю, рамки нет. Картинка целиком по-прежнему становится
   страницей своего размера (ADR-0044) — у неё нет «исходного PDF»,
   который можно было бы положить байт в байт.
2. Без скрипта то же поле уходит с формой готовым файлом: у поля есть имя,
   и скрипт его снимает, перехватывая файл в черновик. Путь без скрипта
   сохраняется; принимает он только PDF — картинку без скрипта собрать
   нечем, и она отклоняется с объяснением, а не ложится в слот PDF.
3. Нетронутый PDF, прошедший через черновик, держит **предел инструмента**:
   он уже принят загрузкой черновика, и тот же файл, взятый не целиком,
   собрался бы без всякого общего предела. Готовый PDF без скрипта
   по-прежнему держит общий.
4. Правило протокола «на слоте либо готовый файл, либо порядок сборки,
   но не оба» остаётся: обычная форма его больше не нарушает, но запрос,
   собранный руками, отклоняется по-прежнему.

## Причины

- Одно действие — одно поле. Основная масса Задач — один готовый PDF или
  одна картинка, и для них сборка ничем не отличается от «приложить»;
  второе поле — лишний выбор на каждой Задаче, на планшете особенно.
- «Хранится таким, каким дал Администратор» (file-storage, ADR-0044,
  «Последствия») остаётся правдой для нетронутого PDF: Администратор
  ничего не собирал — значит, ничего и не пересобирается, ссылки
  и закладки на месте.
- Один предел на одно поле: если бы нетронутый PDF держал 20 МБ, а тот же
  файл со страницами «с 1 по N−1» — предел инструмента, граница прошла бы
  по случайному признаку, которого Администратор не видит.

## Отвергнутые альтернативы

### Одно поле, всегда пересборка

Проще: «целиком» — обычный диапазон 1…N. Отклонено: тихо теряет ссылки
и закладки готовых PDF и ломает «хранится таким, каким дал».

### Два поля, оформленные как один выбор

Переключатель «приложить / собрать» над двумя полями. Отклонено: трение,
на которое пожаловался учитель, — сам выбор, а не его оформление.

### Нетронутый PDF держит общий предел

Сохранило бы ADR-0044 п. 6 буквально. Отклонено по третьей причине:
граница между «целиком» и «почти целиком» прошла бы по пределу, а не по
смыслу; крупный сборник, взятый целиком, пришлось бы резать на диапазоны,
чтобы его приняли.

## Последствия

- Готовый PDF как отдельное поле формы исчезает; как путь без скрипта —
  остаётся тем же полем.
- Нетронутый PDF крупнее 20 МБ теперь ложится в Задачу — раньше его
  отклонял общий предел. Хранилище получает такие файлы наравне
  с собранными из крупных сборников.
- Путь готового PDF начинает проверять, что пришёл PDF, по первым байтам: раньше
  его ограничивал только фильтр выбора файла в браузере.
- ADR-0044 остаётся в силе; его п. 6 уточняется: «готовый PDF Задачи
  держит общий предел» относится к готовому PDF, присланному формой без
  скрипта.
