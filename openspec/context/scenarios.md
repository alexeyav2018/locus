# Рабочие сценарии

Что учитель делает в системе. Именно против этих сценариев пишутся спецификации;
модель данных живёт в коде, а сценарии не живут больше нигде.

Термины — по [glossary.md](glossary.md), правила — по
[domain-model.md](domain-model.md), обоснования — в [adr/](adr/README.md).

Роль указана у каждого сценария: **А** — Администратор, **У** — Учитель.
В первой версии оба набора прав у одного человека, и его рабочий день их
перемешивает, поэтому переключаться между ними не требуется
([ADR-0005](adr/0005-roli-administrator-uchitel.md)).

---

## С1. Наполнить библиотеку задачей (А)

Самая частая операция при старте: у учителя накоплены PDF, их надо перенести
в систему так, чтобы потом находить.

1. Найти или создать в рубрикаторе Тему, к которой относится задача.
2. Завести Задачу: загрузить PDF условия и PDF решения.
3. Разметить: одна или несколько Тем, **минимум один** Метод, при желании
   Характеристики, обязательно Часть ЕГЭ.
4. При выборе Метода система показывает те, что уже встречались в этой Теме;
   полный словарь — по отдельному действию.

Узкое место: разметка — единственный вход в задачу, текста система не знает
([ADR-0008](adr/0008-zadacha-dva-pdf.md)). Плохо размеченная задача потеряна.

## С2. Уточнить структуру рубрикатора (А)

Возникает по мере роста базы: грубая Тема обрастает содержимым и её хочется
разделить.

1. Добавить потомков Теме, на которой уже висят задачи. Тема перестаёт быть
   листом, поэтому система требует указать **Тему-приёмник**, куда переезжают
   её задачи и отметки владения.
2. Разобрать приёмник в своём темпе: переразметить задачи по новым Темам.

Отдельная, редкая и опасная операция — **удаление Темы**: задачи распределяются
поштучно, отметки исчезают, система показывает их количество по всем ученикам
всех учителей ([ADR-0007](adr/0007-pravka-rubrikatora.md)).

## С3. Завести учеников и группы (У)

1. Создать карточки Учеников. Ученик — объект учёта, входа у него нет
   ([ADR-0003](adr/0003-sistema-instrument-uchitelya.md)).
2. Собрать Группы — именованные списки, чтобы не отмечать двадцать галочек
   при каждой выдаче.

## С4. Выдать задание (У)

Основной рабочий цикл начинается здесь. Два режима подбора задач:

**Подбор по пробелам** — ради него система и затевалась:

```
   открыть состояние ученика --> увидеть ячейки "не владеет"
                             --> отобрать задачи по этим парам "Тема x Метод"
                             --> выдать
```

**Подбор по фильтру** — когда тема задана извне (прошли на занятии, готовимся
к контрольной): фильтр по узлу дерева (включая всё поддерево), Методу,
Характеристике, Части.

Дальше:

1. Отобрать задачи, назначить срок.
2. При желании прикрепить теорию, выбрав охват — только Темы этих задач или
   вместе с вышестоящими Разделами.
3. Адресовать: конкретному Ученику или Группе. Во втором случае создаются
   персональные Задания по числу учеников, связанные общей **Раздачей**
   ([ADR-0016](adr/0016-zadaniya-bez-shablonov.md)).

Передача задания ученику происходит **вне системы**.

## С5. Принять и проверить работу (У)

Самый нагруженный экран системы: здесь сходятся файлы, вердикты и отметки.

1. Ученик присылает решение (мессенджер, бумага) — вне системы.
2. Учитель загружает скан или фотографию к **конкретной задаче** задания.
   Загрузка идёт с телефона, файлов может быть несколько
   ([ADR-0015](adr/0015-skany-rabot-hranyatsya.md)).
3. Ставит бинарный вердикт и, при необходимости, текстовое примечание.
4. Система показывает ячейки-кандидаты — Темы задачи, перемноженные на её
   Методы, — каждую с текущим значением и справкой по истории решений
   («по этому методу решено 2 из 6»).
5. Учитель проставляет отметки **выборочно**: только там, где работа дала
   основание. Предзаполнения нет, вердикт на отметки не влияет
   ([ADR-0011](adr/0011-otmetka-na-pare.md)).

## С6. Посмотреть состояние ученика (У)

Везде — распределения по четырём статусам, нигде — одно значение
([ADR-0013](adr/0013-agregaciya-raspredelenie.md)):

| Срез | Что показывает |
| --- | --- |
| По Теме | распределение по её парам «Тема × Метод» |
| По Разделу | распределение по всем ячейкам поддерева |
| По Методу | распределение по всем Темам, где метод встречается |
| Пробелы | перечень ячеек со статусом `не владеет` — вход в С4 |

Состояние `неизвестно` — норма, а не тревога: ячейки заполняются выборочно.

## С7. Посмотреть несданное (У)

«Не сдано» вычисляется на лету — срок прошёл, Работы нет
([ADR-0016](adr/0016-zadaniya-bez-shablonov.md)). Разрезы: по ученику, по
Раздаче («кто из группы не сдал»), по периоду. Уведомлений никому не уходит
([ADR-0017](adr/0017-net-uvedomlenij.md)) — учитель напоминает сам.

---

## Чего в сценариях нет

Ученик не совершает в системе ни одного действия. Расписание отложено
([ADR-0019](adr/0019-raspisanie-otlozheno.md)). Подбор теории по пробелам —
не первая версия. Сравнение учеников по одной контрольной невозможно:
у каждого Задания свой набор задач.
