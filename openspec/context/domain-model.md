# Доменная модель

Что из чего состоит и по каким правилам держится. Термины — по
[glossary.md](glossary.md); обоснования решений — в [adr/](adr/README.md).

Это не описание реализации: здесь нет таблиц, колонок и классов. Здесь правила,
которые при реализации выглядят произвольными ограничениями и потому снимаются
при первом же неудобстве — если не записаны вместе с причиной.

## Граница общего и личного

Главное деление в системе. От него зависит и модель прав, и то, где применяется
фильтр по владельцу.

```
   ОБЩЕЕ (вся система, под Администратором)   ЛИЧНОЕ (у каждого учителя)
   ----------------------------------------   ---------------------------
   Рубрикатор: Разделы и Темы                 Ученики
   Словарь Методов                            Группы
   Словарь Характеристик                      Задания и сроки
   Задачи (PDF + разметка)                    Работы: сканы и вердикты
   Теоретические материалы                    Отметки Владения
```

Практическое следствие, которое легко нарушить не заметив: **фильтр по владельцу
применяется только к правой колонке**. Механически применённый к библиотеке, он
сделает её невидимой; забытый на личных данных — покажет учителю чужих учеников.
Обе ошибки тихие. См. `antipatterns.md`.

## Сущности и связи

```
                        РУБРИКАТОР (дерево)
                Раздел ---- Раздел ---- Тема
                   |           |          |
                   |           +-------- Тема
                   +-- Тема
                        ^
                        | 1..n (только Темы)
                        |
   Теория --- любой ---+                     Метод -----+
   (файл | ссылка)      |                    (плоский    |
   узел дерева          |                     словарь)   |
                        |                                |
                     ЗАДАЧА ------------------------------+ 1..n
                        |  номер, Подпись (может не быть),
                        |  Часть (1|2), Характеристики 0..n
                        |
                        | входит в
                        v
   Ученик <---- ЗАДАНИЕ (срок) <---- Раздача (одно действие выдачи)
      |            |
      |            v
      |         РАБОТА: скан + вердикт + примечание
      |            (по каждой задаче задания)
      |
      +-----> ВЛАДЕНИЕ: (Ученик, Тема, Метод) -> статус
```

Учитель — владелец Ученика, Группы, Задания, Работы и Владения.
Администратор — владелец всего, что в дереве и в библиотеке.

Ученик и Группа построены в `students-groups` — первые сущности личного
контура. Ученик — карточка из имени и владельца, без учётной записи
(сторожит `StudentIsNotAUserTest`); Группа — именованный список Учеников
того же Учителя, имя Группы у одного Учителя неповторимо, у Учеников —
свободно. Задание и Раздача построены в `assignments`: Задание — набор
Задач (ссылки на библиотеку, минимум одна, в порядке выбора), выданный
одному Ученику со сроком и охватом теории (`TheoryScope`); Раздача —
одно действие выдачи Группе, помнящее **имя** Группы на момент выдачи
и дату, а не ключ на неё: Группа удаляется в любой момент
([ADR-0035](adr/0035-udalenie-uchenika-i-gruppy.md)), а происхождение
Заданий — исторический факт. Работа построена в `submission-review`:
решение **одной Задачи одного Задания** — файлы (скан или снимок, хотя бы
один), дата получения, вердикт `Verdict` (может отсутствовать — «не
проверена») и примечание; на паре «Задание × Задача» Работа одна,
вердикт ставится отдельно от приёма и меняется свободно, Работа удаляется
владельцем в любой момент вместе с файлами
([ADR-0038](adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)).
Ученика у Работы нет — он у Задания. Владение построено в `mastery-marks`:
отметка на паре «Ученик × Тема × Метод» у своего владельца, значение из
шкалы `MasteryStatus`; хранится только текущее значение и только
с суждением — `неизвестно` есть отсутствие строки, а простановка
`неизвестно` строку удаляет
([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)). Ставится на экране
приёма по принятой Работе, только на парах из разметки её Задачи,
выборочно и без предзаполнения; к Работе не привязана — Работа удаляется,
отметка остаётся.

## Инварианты

Правила, нарушение которых ломает систему не сразу, а тихо.

1. **Задача привязана минимум к одной Теме и только к Темам.** На Разделе задач
   не бывает никогда ([ADR-0006](adr/0006-rubrikator-derevo.md)).
2. **У задачи минимум один Метод.** Задача без методов не порождает ни одной
   ячейки владения и потому «нема» для статистики
   ([ADR-0009](adr/0009-razmetka-zadachi.md)).
3. **Отметка Владения существует только на паре «Тема × Метод» для ученика.**
   Ни на Разделе, ни на Теме отдельно, ни на Методе отдельно
   ([ADR-0011](adr/0011-otmetka-na-pare.md)).
4. **Ячейки владения порождаются употреблением, а не перемножением словарей.**
   Пара «Тема × Метод» осмысленна, только если существует задача, размеченная и
   этой Темой, и этим Методом. Декартово произведение дало бы десятки тысяч
   пустых ячеек.
5. **Владение по Теме, по Разделу и по Методу — не отметки, а распределения**
   по четырём статусам (`владеет`, `владеет неуверенно`, `не владеет`,
   `неизвестно`). Одного вычисленного значения не существует нигде
   ([ADR-0013](adr/0013-agregaciya-raspredelenie.md)).
6. **Отметку ставит только человек.** Система не выводит владение ни из
   вердиктов, ни из их серии, и не предзаполняет ячейки
   ([ADR-0011](adr/0011-otmetka-na-pare.md),
   [ADR-0014](adr/0014-proverka-bez-avtomatiki.md)).
7. **Хранится только текущее значение отметки.** История не ведётся;
   хронология восстанавливается по Работам ученика
   ([ADR-0012](adr/0012-shkala-vladeniya.md)). Новая простановка затирает
   прежнюю (`MasteryRepository.put` — `INSERT … ON CONFLICT DO UPDATE`),
   а `неизвестно` не хранится вовсе
   ([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)).
8. **Узел дерева имеет ровно одного родителя.** Общего словаря Тем нет
   ([ADR-0006](adr/0006-rubrikator-derevo.md)).
9. **Теория крепится к любому узлу**, включая Разделы, — и ровно к одному,
   а видна на всём его поддереве: выбранная Тема показывает и свои материалы,
   и материалы вышестоящих Разделов, с указанием источника
   ([ADR-0032](adr/0032-teoriya-na-odnom-uzle-i-nasledovanie.md)). Правило
   «только листья» на теорию не распространяется: оно введено ради
   корректности статистики, а у теории статистики нет. Следствие для дерева:
   узел со **своими** материалами не удаляется, но углублению материалы
   не мешают — на Разделе они законны.
10. **Поиск по узлу включает всё поддерево.** Иначе глубокая разметка делает
    задачи ненаходимыми.
11. **Ученик принадлежит ровно одному учителю**
    ([ADR-0004](adr/0004-mnogouchitelskaya-rabota.md)). Построено
    в `students-groups`: владелец — обязательная колонка Ученика и Группы,
    состав Группы держится составными ключами, так что чужой Ученик в Группу
    не попадает и в обход сервиса; у репозиториев нет метода без `UserId`
    (`OwnerIsRequiredByStudentsTest`), а Учитель не видит чужих Учеников
    ни одним запросом (`StudentsAreFilteredByOwnerTest`).
12. **«Не сдано» вычисляется, а не хранится:** срок прошёл и Работы нет.
    Состояние снимается само по факту получения; проставлять и снимать его
    некому и незачем ([ADR-0016](adr/0016-zadaniya-bez-shablonov.md)).
    Построено в `assignments`: в трёх таблицах Задания нет ни одной колонки
    с этим смыслом (сторожит `NotSubmittedIsNotStoredTest`), «сегодня»
    берётся у бина `Clock`, и сдвиг часов меняет состояние без единого
    действия (`NotSubmittedTest`). Вторая половина условия — «Работы нет» —
    спрашивается вопросом `AssignmentWork`, на который отвечает
    `submission-review` (`WorksOfAssignment`): Работа считается с момента
    приёма, вердикт не нужен
    ([ADR-0038](adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md));
    Задание с Работой не «не сдано», удаление последней Работы возвращает
    просроченное Задание в несданные (сторожит `AssignmentWorkAnsweredTest`;
    что вопрос и ответчик названы — `AssignmentWorkDebtTest`).

## Вычисляемое

Всё это считается в момент запроса и нигде не хранится:

| Величина | Из чего |
| --- | --- |
| «Не сдано» по Заданию | срок прошёл, Работы нет |
| Владение по Теме | распределение по статусам её ячеек «Тема × Метод» |
| Владение по Разделу | распределение по ячейкам всего поддерева |
| Владение по Методу | распределение по всем Темам, где метод встречается |
| Пробелы ученика | ячейки со статусом `не владеет` — напрямую, без агрегатов |

## Операции, требующие особого поведения

Обычный CRUD здесь не работает — эти операции затрагивают накопленные суждения
о людях. Подробно в [ADR-0007](adr/0007-pravka-rubrikatora.md).

| Операция | Поведение |
| --- | --- |
| Переименование узла | Свободно. Узел — запись с неизменным идентификатором, имя — его атрибут; история не двигается. |
| Добавление потомков Теме с задачами | Тема перестала бы быть листом, а на Разделе задач не бывает (инвариант 1), поэтому Администратор указывает **Тему-приёмник**: создаваемого потомка (по умолчанию) либо любую существующую Тему. Задачи и отметки переезжают на приёмник в одной транзакции с созданием потомка; без приёмника операция отклоняется. Переезд не подчиняется заморозке задачи ([ADR-0034](adr/0034-perestrojka-silnee-zamorozki.md)). Отметки всех Учителей переезжают без фильтра по владельцу (`MasteryOnNode` → `MasteryRepository.rehomeTopic`); если ячейка на приёмнике у того же Учителя, Ученика и Метода уже занята, две отметки сливаются по правилу ADR-0013: совпали — остаётся одна, разошлись — `владеет неуверенно` ([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)). Построено в `rubricator-restructure`: `TaxonomyService.create(name, parent, receiver)`; переезд отметок — в `mastery-marks` (`MasteryRestructureTest`). |
| Удаление Темы | Отдельная операция «снятие с распределением» (`TaxonomyService.deleteWithDistribution`): Задачи распределяются **поштучно** по другим Темам, приёмник каждой проверяется по состоянию дерева после снятия. Отметки удаляемой Темы не сливаются ни с кем и исчезают (`MasteryOnNode` → `MasteryRepository.deleteByTopic`); Администратору показывается их число по всем ученикам всех учителей — считаются только суждения, `неизвестно` строкой не является ([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)); счёт — `MasteryRepository.countByTopic` без владельца, построен в `mastery-marks` (`MasteryRestructureTest`). Обычное удаление Темы с отметками отклоняется, как и с Задачами. Если соседних Тем нет, задачи поднимаются на родителя, который становится Темой. Узел со своими Теоретическими материалами не снимается: материал переносится обычной правкой ([ADR-0033](adr/0033-teoriya-ne-zamorazhivaetsya.md)). |
| Перемещение узла | Существует только в дереве; при двух уровнях такой операции не было. |
| Удаление Ученика | Допустимо, пока на Ученика не ссылается ни одна запись личного контура — ни Задание, ни Работа, ни отметка Владения; иначе отклоняется с указанием, что держит ([ADR-0035](adr/0035-udalenie-uchenika-i-gruppy.md)). Вопрос «на что ссылается» — `StudentUsage`: `assignments` отвечает («выдано Заданий (N)», `AssignmentsOfStudent`), `submission-review` отвечает («принято Работ (N)», `WorksOfStudent`), `mastery-marks` отвечает («вынесено суждений (N)», `MasteryOfStudent`) — ответы собираются в один отказ; что ответчиков три и все названы, сторожит `StudentUsageDebtTest`. Из Групп Ученик вычёркивается каскадом. Переименование свободно. Группа удаляется в любой момент: она только список. Построено в `students-groups`: `StudentService.delete` через `refuseUnlessUnused`. |
| Перенос срока Задания | Единственная правка выданного Задания: состав, охват теории и адресат после выдачи неизменны ([ADR-0037](adr/0037-zadanie-neizmenno-posle-vydachi.md)). Изменить состав — удалить Задание и выдать новое. Построено в `assignments`: `AssignmentService.changeDueDate`. |
| Удаление Задания и Раздачи | Допустимо, пока ни по одной Задаче Задания нет Работы; Раздача удаляется вместе со всеми своими Заданиями в одной транзакции по тому же условию ([ADR-0037](adr/0037-zadanie-neizmenno-posle-vydachi.md)). Вопрос «есть ли Работа» — `AssignmentWork`, отвечает `submission-review` (`WorksOfAssignment`; сторожат `AssignmentWorkAnsweredTest` и `AssignmentWorkDebtTest`): Работа считается с момента приёма, без вердикта тоже. Ученик и Задачи при удалении остаются. Построено в `assignments`: `AssignmentService.delete` и `deleteBatch` через `refuseUnlessNoWork`. |
| Удаление Работы | Свободно, в любой момент, вместе с файлами из хранилища: по ключу на Работу не ссылается ни одна запись — отметка Владения стоит на паре «Тема × Метод», а не на Работе ([ADR-0038](adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)). Ошибочная загрузка исправляется так: удалить и принять заново; переноса Работы между Задачами и Учениками нет. Задание и Ученик остаются. Отдельный файл удаляется, кроме последнего: Работа без файла не существует. Построено в `submission-review`: `StudentWorkService.delete` и `deleteFile`. |
| Простановка отметки | Только Учителем, только своему Ученику, только на экране приёма по **принятой** Работе и только на паре из разметки её Задачи: ячейка для пары без Задачи не создаётся (инвариант 4). Заполнение выборочное — нетронутые ячейки не меняются; предзаполнения нет, вердикт на отметки не влияет ([ADR-0011](adr/0011-otmetka-na-pare.md)); справка «решено N из M» считает только проверенные Работы ([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)). Построено в `mastery-marks`: `MasteryService.mark`. |
| Удаление Метода | Допустимо, пока на Метод не опирается ни одна Задача и ни одна отметка Владения — по всем Учителям, без фильтра по владельцу (`MasteryOfMethod` → `MasteryRepository.countByMethod`, класс ADR-0036). Построено в `mastery-marks` (`MasteryGuardsTheMethodTest`). |
| Правка Методов у размеченной задачи | Симметрична удалению Темы: ячейка может остаться без единой задачи. Поведение не определено — элемент бэклога `method-edit-impact`. |

## Чего в модели нет

Формулы как данные (всё внутри PDF), эталонные ответы, автоматическая проверка,
уведомления, фоновые процессы, шаблоны заданий, история отметок, роль ученика.
По каждому — запись в журнале с причиной; см. `strategy.md`, раздел не-целей.
