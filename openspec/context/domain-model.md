# Доменная модель

Что из чего состоит и по каким правилам держится. Термины — по
[glossary.md](glossary.md); обоснования решений — в [adr/](adr/README.md).

Это не описание реализации: здесь нет таблиц, колонок и классов. Здесь правила,
которые при реализации выглядят произвольными ограничениями и потому снимаются
при первом же неудобстве — если не записаны вместе с причиной.

## Граница общего и личного

Главное деление в системе. От него зависит и модель прав, и то, где применяется
фильтр по владельцу.

```
   ОБЩЕЕ (вся система, под Администратором)   ЛИЧНОЕ (у каждого учителя)
   ----------------------------------------   ---------------------------
   Рубрикатор: Разделы и Темы                 Ученики
   Словарь Методов                            Группы
   Словарь Характеристик                      Задания и сроки
   Задачи (текст или PDF + разметка)          Работы: сканы и вердикты
   Теоретические материалы                    Отметки Владения
                                              Занятия
                                              Черновики Задачи
                                              Разговоры с Помощником
```

Практическое следствие, которое легко нарушить не заметив: **фильтр по владельцу
применяется только к правой колонке**. Механически применённый к библиотеке, он
сделает её невидимой; забытый на личных данных — покажет учителю чужих учеников.
Обе ошибки тихие. См. `antipatterns.md`.

## Сущности и связи

```
                        РУБРИКАТОР (дерево)
                Раздел ---- Раздел ---- Тема
                   |           |          |
                   |           +-------- Тема
                   +-- Тема
                        ^
                        | 1..n (только Темы)
                        |
   Теория --- любой ---+                     Метод -----+
   (файл | ссылка)      |                    (плоский    |
   узел дерева          |                     словарь)   |
                        |                                |
                     ЗАДАЧА ------------------------------+ 1..n
                        |  номер,
                        |  Часть (1|2), Характеристики 0..n
                        |  текст условия и решения (может не быть);
                        |  у Задачи с текстом оба PDF — отрисовка
                        |  текста, улика хранится рядом
                        |
                        | входит в
                        v
   Ученик <---- ЗАДАНИЕ (срок) <---- Раздача (одно действие выдачи)
      |            |
      |            v
      |         РАБОТА: скан + вердикт + примечание
      |            (по каждой задаче задания)
      |
      +-----> ВЛАДЕНИЕ: (Ученик, Тема, Метод) -> статус
      |
      +<---- ЗАНЯТИЕ (разовое | еженедельное) ----> Группа
             ровно один адресат: Ученик или Группа;
             Встречи вычисляются из Занятий, не хранятся
                 |
                 +-- ПОПРАВКА ВСТРЕЧИ: (Занятие, плановая дата) ->
                     отмена | перенос (дата, время, длительность) | неявка

   ЧЕРНОВИК ЗАДАЧИ --становится--> Задача
   (личный у загрузившего: текст, рамки по Черновикам сборки,
    предложенная разметка, улика; версия — правят двое;
    держит свои Черновики сборки, пока жив)

   Учитель <---- РАЗГОВОР с Помощником (сеанс Claude Code)
                   └── Реплики: запрос, состояние, ответ, причина,
                       токены, стоимость, время
                         └── строки хода: инструмент и аргументы
                 личный; Помощник действует под личностью Учителя
```

Учитель — владелец Ученика, Группы, Задания, Работы, Владения, Занятия,
Поправки Встречи и Разговора с Помощником. Черновик Задачи принадлежит
загрузившему лист, как Черновик сборки.
Администратор — владелец всего, что в дереве и в библиотеке; Задачу
из Черновика Задачи заводит тоже он — помощником или рукой.

Текст Задачи, Черновик Задачи и Разговор — замысел редакции 3
([ADR-0053](adr/0053-redakciya-3-strategii-pomoshchnik.md)). Текст
и Улики построены в `problem-text`: оба текста или ни одного, Улика —
у каждого слота и только при тексте, версия текста — счётчик, правка
со старой версией отклоняется; «без текста» — отсутствие текста, а не
признак (сторожит `TextlessIsNotStoredTest`). Черновик Задачи построен
в `problem-intake` (`ProblemDraft`): тексты условия и решения, строки
сборки по слотам — ссылки на Черновики сборки с диапазоном и Рамкой,
предложенная разметка, сомнительные места и названные новые Методы,
версия и «кем изменён». Заводит его Администратор — строки ссылаются
на Черновики сборки, а их загружает только он; у репозитория `UserId`
во всех методах, кроме двух уборок (`deleteChangedBefore`, `deleteAll`),
составной ключ не даёт строке сослаться на чужой Черновик сборки.
Черновик сборки, на который ссылается живой Черновик Задачи, не удаляется
ни сохранением Задачи, ни уборкой по сроку; сам Черновик Задачи уходит
через неделю от последней правки, а при перезапуске — весь, вместе
с Черновиками сборки ([ADR-0059](adr/0059-chernovik-zadachi-derzhit-chernoviki-sborki.md)).
Его разметка ссылается на библиотеку с каскадом и удалению из неё
не мешает. Разговор, Реплика и строки
хода построены в `agent-runner` (`AssistantConversation`, `AssistantTurn`,
`TurnStep`): личные, у репозитория `UserId` во всех методах, кроме
пометки прерванных при старте (`interruptRunning`, класс
[ADR-0036](adr/0036-voprosy-biblioteki-bez-vladelca.md));
составной ключ не даёт Реплике сослаться на чужой Разговор, а частичный
уникальный индекс — завести вторую «работаю» тому же владельцу. Разговор
заводит любой вошедший — и Учитель, и Администратор, который заводит
Задачи помощником; Разговоры у каждого свои. Страницу разговора построил
`assistant-chat`: файл реплики ложится Черновиком сборки вошедшего. Текст Задачи
необязателен: Задачи с текстом и без сосуществуют в одной библиотеке
без срока, перевод миграцией исключён — распознавание требует вычитки
([ADR-0055](adr/0055-tekst-zadachi-pervichen-pdf-otrisovka.md)).
Черновик Задачи правят двое — Помощник инструментом и учитель на странице
вычитки, — поэтому у него есть версия, а истина о нём — в Локусе,
не в контексте модели ([ADR-0056](adr/0056-pomoshchnik-vtoroj-klient-servisnogo-sloya.md)).

Ученик и Группа построены в `students-groups` — первые сущности личного
контура. Ученик — карточка из имени, владельца и состояния выбытия
(`withdrawn`, по умолчанию — действует), без учётной записи (сторожит
`StudentIsNotAUserTest`); выбытие переключается Учителем в обе стороны
свободно, скрывает Ученика из списка по умолчанию и из адресатов выдачи,
но не трогает Задания, Работы, Владение и членство в Группах
([ADR-0040](adr/0040-vybytie-uchenika-flag.md)); Группа — именованный
список Учеников
того же Учителя, имя Группы у одного Учителя неповторимо, у Учеников —
свободно. Задание и Раздача построены в `assignments`: Задание — набор
Задач (ссылки на библиотеку, минимум одна, в порядке выбора), выданный
одному Ученику со сроком и охватом теории (`TheoryScope`); Раздача —
одно действие выдачи Группе, помнящее **имя** Группы на момент выдачи
и дату, а не ключ на неё: Группа удаляется в любой момент
([ADR-0035](adr/0035-udalenie-uchenika-i-gruppy.md)), а происхождение
Заданий — исторический факт. Работа построена в `submission-review`:
решение **одной Задачи одного Задания** — файлы (скан или снимок, хотя бы
один), дата получения, вердикт `Verdict` (может отсутствовать — «не
проверена») и примечание; на паре «Задание × Задача» Работа одна,
вердикт ставится отдельно от приёма и меняется свободно, Работа удаляется
владельцем в любой момент вместе с файлами
([ADR-0038](adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)).
Ученика у Работы нет — он у Задания. Владение построено в `mastery-marks`:
отметка на паре «Ученик × Тема × Метод» у своего владельца, значение из
шкалы `MasteryStatus`; хранится только текущее значение и только
с суждением — `неизвестно` есть отсутствие строки, а простановка
`неизвестно` строку удаляет
([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)). Ставится на экране
приёма по принятой Работе, только на парах из разметки её Задачи,
выборочно и без предзаполнения; к Работе не привязана — Работа удаляется,
отметка остаётся. Распределения по Теме, Разделу и Методу, а также перечень
пробелов построены в `mastery-views`: `MasteryService.overviewOf`, экран
`/mastery`.

Занятие построено в `schedule`: хранимое правило встреч Учителя ровно
с одним своим Учеником **или** одной своей Группой — дата первой встречи,
время начала, длительность (1–720 минут) и вид, разовое или еженедельное;
у еженедельного может быть последняя дата, без неё оно бессрочно, а день
недели — день первой встречи ([ADR-0047](adr/0047-zanyatie-pravilo-vstrechi-vychislyayutsya.md)).
Свой адресат держат составные ключи в базе, а не только сервис. Встреча —
Занятие на конкретную дату — не хранится, а вычисляется при показе
(`Meetings.between`). Занятие Группы ссылается на Группу ключом: состав
и имя берутся текущие. Выбывшему Ученику новое Занятие не назначается,
прежние показываются с пометкой «выбыл».

Поправка Встречи построена в `schedule-changes` — личный контур, владелец
тот же, что у Занятия; ссылка `(lesson_id, user_id) → lesson(id, user_id)`
не даёт поправить чужое Занятие и в обход сервиса, а каждый метод
`MeetingAdjustmentRepository` принимает `UserId` без исключений. Поправка —
исключение из правила на паре «Занятие × плановая дата»: отмена, перенос
или неявка; «как по правилу» — отсутствие строки
([ADR-0048](adr/0048-popravka-vstrechi-na-pare-zanyatie-data.md)). Отмена
снимает перенос, перенос снимает отмену; неявка — только у Встречи с Учеником,
только у наступившей и не у отменённой, и Встреча с неявкой не уезжает
в будущее. Поправка уходит вместе со своим Занятием каскадом в базе.

## Инварианты

Правила, нарушение которых ломает систему не сразу, а тихо.

1. **Задача привязана минимум к одной Теме и только к Темам.** На Разделе задач
   не бывает никогда ([ADR-0006](adr/0006-rubrikator-derevo.md)).
2. **У задачи минимум один Метод.** Задача без методов не порождает ни одной
   ячейки владения и потому «нема» для статистики
   ([ADR-0009](adr/0009-razmetka-zadachi.md)).
3. **Отметка Владения существует только на паре «Тема × Метод» для ученика.**
   Ни на Разделе, ни на Теме отдельно, ни на Методе отдельно
   ([ADR-0011](adr/0011-otmetka-na-pare.md)).
4. **Ячейки владения порождаются употреблением, а не перемножением словарей.**
   Пара «Тема × Метод» осмысленна, только если существует задача, размеченная и
   этой Темой, и этим Методом. Декартово произведение дало бы десятки тысяч
   пустых ячеек.
5. **Владение по Теме, по Разделу и по Методу — не отметки, а распределения**
   по четырём статусам (`владеет`, `владеет неуверенно`, `не владеет`,
   `неизвестно`). Одного вычисленного значения не существует нигде
   ([ADR-0013](adr/0013-agregaciya-raspredelenie.md)).
6. **Отметку ставит только человек.** Система не выводит владение ни из
   вердиктов, ни из их серии, и не предзаполняет ячейки
   ([ADR-0011](adr/0011-otmetka-na-pare.md),
   [ADR-0014](adr/0014-proverka-bez-avtomatiki.md)). Помощник
   не исключение: инструментов вердикта и отметки у него нет — ни в первой
   очереди, ни позже без новой записи журнала
   ([ADR-0056](adr/0056-pomoshchnik-vtoroj-klient-servisnogo-sloya.md)).
7. **Хранится только текущее значение отметки.** История не ведётся;
   хронология восстанавливается по Работам ученика
   ([ADR-0012](adr/0012-shkala-vladeniya.md)). Новая простановка затирает
   прежнюю (`MasteryRepository.put` — `INSERT … ON CONFLICT DO UPDATE`),
   а `неизвестно` не хранится вовсе
   ([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)).
8. **Узел дерева имеет ровно одного родителя.** Общего словаря Тем нет
   ([ADR-0006](adr/0006-rubrikator-derevo.md)).
9. **Теория крепится к любому узлу**, включая Разделы, — и ровно к одному,
   а видна на всём его поддереве: выбранная Тема показывает и свои материалы,
   и материалы вышестоящих Разделов, с указанием источника
   ([ADR-0032](adr/0032-teoriya-na-odnom-uzle-i-nasledovanie.md)). Правило
   «только листья» на теорию не распространяется: оно введено ради
   корректности статистики, а у теории статистики нет. Следствие для дерева:
   узел со **своими** материалами не удаляется, но углублению материалы
   не мешают — на Разделе они законны.
10. **Поиск по узлу включает всё поддерево.** Иначе глубокая разметка делает
    задачи ненаходимыми.
11. **Ученик принадлежит ровно одному учителю**
    ([ADR-0004](adr/0004-mnogouchitelskaya-rabota.md)). Построено
    в `students-groups`: владелец — обязательная колонка Ученика и Группы,
    состав Группы держится составными ключами, так что чужой Ученик в Группу
    не попадает и в обход сервиса; у репозиториев нет метода без `UserId`
    (`OwnerIsRequiredByStudentsTest`), а Учитель не видит чужих Учеников
    ни одним запросом (`StudentsAreFilteredByOwnerTest`).
12. **«Не сдано» вычисляется, а не хранится:** срок прошёл и Работы нет.
    Состояние снимается само по факту получения; проставлять и снимать его
    некому и незачем ([ADR-0016](adr/0016-zadaniya-bez-shablonov.md)).
    Построено в `assignments`: в трёх таблицах Задания нет ни одной колонки
    с этим смыслом (сторожит `NotSubmittedIsNotStoredTest`), «сегодня»
    берётся у бина `Clock`, и сдвиг часов меняет состояние без единого
    действия (`NotSubmittedTest`). Вторая половина условия — «Работы нет» —
    спрашивается вопросом `AssignmentWork`, на который отвечает
    `submission-review` (`WorksOfAssignment`): Работа считается с момента
    приёма, вердикт не нужен
    ([ADR-0038](adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md));
    Задание с Работой не «не сдано», удаление последней Работы возвращает
    просроченное Задание в несданные (сторожит `AssignmentWorkAnsweredTest`;
    что вопрос и ответчик названы — `AssignmentWorkDebtTest`).
13. **У Задачи с текстом PDF всегда равен отрисовке её текста.** Текст
    первичен: правится текст — PDF перерисовывается Локусом на сервере
    в тот же слот; рукой отрисованный PDF не правится и не заменяется,
    иначе текст и файл разойдутся молча — ученик получит одно, поиск
    найдёт другое. Улика — снимок, с которого текст распознан, — хранится
    отдельно, в своём слоте, и в Задание не уходит
    ([ADR-0055](adr/0055-tekst-zadachi-pervichen-pdf-otrisovka.md)).
    Построено в `problem-text`: отрисовывает `ProblemTextRendering`
    внутри приложения ([ADR-0058](adr/0058-otrisovshchik-teksta-zadachi-v-steke.md)),
    у Задачи с текстом поле слота даёт Улику, а замена PDF слота
    отклоняется сервисом; оба текста или ни одного и Улика только
    при тексте держит и ограничение базы (`TextlessIsNotStoredTest`).

## Вычисляемое

Всё это считается в момент запроса и нигде не хранится:

| Величина | Из чего |
| --- | --- |
| «Не сдано» по Заданию | срок прошёл, Работы нет |
| Владение по Теме | распределение по статусам её ячеек «Тема × Метод» (`MasteryService.overviewOf`, `mastery-views`) |
| Владение по Разделу | распределение по ячейкам всего поддерева (`MasteryService.overviewOf`, `mastery-views`) |
| Владение по Методу | распределение по всем Темам, где метод встречается (`MasteryService.overviewOf`, `mastery-views`) |
| Пробелы ученика | ячейки со статусом `не владеет` — напрямую, без агрегатов (`MasteryService.overviewOf`, `mastery-views`) |
| Встречи недели и дня | Занятия, дающие Встречу в отрезке: разовое — на своей дате, еженедельное — на каждой дате своего дня недели от первой до последней; поверх правила — Поправки: отменённая Встреча остаётся с пометкой, перенесённая показывается на новой дате (в том числе пришедшая из другой недели), а на плановой — строкой «перенесена на …» (`Meetings.between`, `LessonService.week`/`today`, `schedule`, `schedule-changes`) |

## Операции, требующие особого поведения

Обычный CRUD здесь не работает — эти операции затрагивают накопленные суждения
о людях. Подробно в [ADR-0007](adr/0007-pravka-rubrikatora.md).

| Операция | Поведение |
| --- | --- |
| Переименование узла | Свободно. Узел — запись с неизменным идентификатором, имя — его атрибут; история не двигается. |
| Добавление потомков Теме с задачами | Тема перестала бы быть листом, а на Разделе задач не бывает (инвариант 1), поэтому Администратор указывает **Тему-приёмник**: создаваемого потомка (по умолчанию) либо любую существующую Тему. Задачи и отметки переезжают на приёмник в одной транзакции с созданием потомка; без приёмника операция отклоняется. Переезд не подчиняется заморозке задачи ([ADR-0034](adr/0034-perestrojka-silnee-zamorozki.md)). Отметки всех Учителей переезжают без фильтра по владельцу (`MasteryOnNode` → `MasteryRepository.rehomeTopic`); если ячейка на приёмнике у того же Учителя, Ученика и Метода уже занята, две отметки сливаются по правилу ADR-0013: совпали — остаётся одна, разошлись — `владеет неуверенно` ([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)). Построено в `rubricator-restructure`: `TaxonomyService.create(name, parent, receiver)`; переезд отметок — в `mastery-marks` (`MasteryRestructureTest`). |
| Удаление Темы | Отдельная операция «снятие с распределением» (`TaxonomyService.deleteWithDistribution`): Задачи распределяются **поштучно** по другим Темам, приёмник каждой проверяется по состоянию дерева после снятия. Отметки удаляемой Темы не сливаются ни с кем и исчезают (`MasteryOnNode` → `MasteryRepository.deleteByTopic`); Администратору показывается их число по всем ученикам всех учителей — считаются только суждения, `неизвестно` строкой не является ([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)); счёт — `MasteryRepository.countByTopic` без владельца, построен в `mastery-marks` (`MasteryRestructureTest`). Обычное удаление Темы с отметками отклоняется, как и с Задачами. Если соседних Тем нет, задачи поднимаются на родителя, который становится Темой. Узел со своими Теоретическими материалами не снимается: материал переносится обычной правкой ([ADR-0033](adr/0033-teoriya-ne-zamorazhivaetsya.md)). |
| Перемещение узла | Существует только в дереве; при двух уровнях такой операции не было. |
| Удаление Ученика | Допустимо, пока на Ученика не ссылается ни одна запись личного контура — ни Задание, ни Работа, ни отметка Владения, ни Занятие; иначе отклоняется с указанием, что держит ([ADR-0035](adr/0035-udalenie-uchenika-i-gruppy.md)). Вопрос «на что ссылается» — `StudentUsage`: `assignments` отвечает («выдано Заданий (N)», `AssignmentsOfStudent`), `submission-review` отвечает («принято Работ (N)», `WorksOfStudent`), `mastery-marks` отвечает («вынесено суждений (N)», `MasteryOfStudent`), `schedule` отвечает («назначено Занятий (N)», `LessonsOfStudent`) — ответы собираются в один отказ; что ответчиков четыре и все названы, сторожит `StudentUsageDebtTest`. Из Групп Ученик вычёркивается каскадом. Переименование свободно. Построено в `students-groups`: `StudentService.delete` через `refuseUnlessUnused`. |
| Удаление Группы | Свободно, в любой момент ([ADR-0035](adr/0035-udalenie-uchenika-i-gruppy.md)): Ученики остаются, Раздачи помнят имя Группы текстом. Занятия Группы удаляются вместе с ней каскадом в базе, о чём форма удаления предупреждает постоянной строкой; `GroupService` о Занятиях не знает ([ADR-0047](adr/0047-zanyatie-pravilo-vstrechi-vychislyayutsya.md)). Построено в `students-groups`, каскад Занятий — в `schedule`. |
| Правка Занятия | Разовое правится на месте. Еженедельное — **с указанной даты**: Встречи до неё не меняются. Если до этой даты у Занятия Встречи были, оно делится: прежнее заканчивается накануне, новое с тем же адресатом начинается с первого дня нового дня недели не раньше указанной даты. Встреч раньше не было или правится только последняя дата — правка на месте. Адресат не правится: другой адресат — другое Занятие ([ADR-0047](adr/0047-zanyatie-pravilo-vstrechi-vychislyayutsya.md)). Поправки при делении с даты правки переходят к новой части, а Поправки дат, которых правило больше не даёт, снимаются у обеих частей; форма правки об этом предупреждает ([ADR-0048](adr/0048-popravka-vstrechi-na-pare-zanyatie-data.md)). Построено в `schedule`: `LessonService.change`; Поправки — в `schedule-changes`. |
| Удаление Занятия | Свободно, в любой момент. Поправки его Встреч, в том числе неявки, уходят вместе с ним каскадом в базе; подтверждение удаления об этом говорит. Построено в `schedule`: `LessonService.delete`; Поправки — в `schedule-changes`. |
| Выбытие Ученика | Свободно в обе стороны, без ограничений и без каскада: Группы, Задания, Работы и Владение не меняются ([ADR-0040](adr/0040-vybytie-uchenika-flag.md)). Скрывает из списка по умолчанию и из адресатов выдачи; карточка и история остаются доступны. Раздача Группе пропускает выбывших членов, отклоняясь только если действующих не осталось; прямая выдача выбывшему Ученику отклоняется отдельно. Построено в `student-withdrawal`: `StudentService.withdraw`/`restore`, `AssignmentService.issueToStudent`/`issueToGroup`. |
| Перенос срока Задания | Единственная правка выданного Задания: состав, охват теории и адресат после выдачи неизменны ([ADR-0037](adr/0037-zadanie-neizmenno-posle-vydachi.md)). Изменить состав — удалить Задание и выдать новое. Построено в `assignments`: `AssignmentService.changeDueDate`. |
| Удаление Задания и Раздачи | Допустимо, пока ни по одной Задаче Задания нет Работы; Раздача удаляется вместе со всеми своими Заданиями в одной транзакции по тому же условию ([ADR-0037](adr/0037-zadanie-neizmenno-posle-vydachi.md)). Вопрос «есть ли Работа» — `AssignmentWork`, отвечает `submission-review` (`WorksOfAssignment`; сторожат `AssignmentWorkAnsweredTest` и `AssignmentWorkDebtTest`): Работа считается с момента приёма, без вердикта тоже. Ученик и Задачи при удалении остаются. Построено в `assignments`: `AssignmentService.delete` и `deleteBatch` через `refuseUnlessNoWork`. |
| Удаление Работы | Свободно, в любой момент, вместе с файлами из хранилища: по ключу на Работу не ссылается ни одна запись — отметка Владения стоит на паре «Тема × Метод», а не на Работе ([ADR-0038](adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)). Ошибочная загрузка исправляется так: удалить и принять заново; переноса Работы между Задачами и Учениками нет. Задание и Ученик остаются. Отдельный файл удаляется, кроме последнего: Работа без файла не существует. Построено в `submission-review`: `StudentWorkService.delete` и `deleteFile`. |
| Простановка отметки | Только Учителем, только своему Ученику, только на экране приёма по **принятой** Работе и только на паре из разметки её Задачи: ячейка для пары без Задачи не создаётся (инвариант 4). Заполнение выборочное — нетронутые ячейки не меняются; предзаполнения нет, вердикт на отметки не влияет ([ADR-0011](adr/0011-otmetka-na-pare.md)); справка «решено N из M» считает только проверенные Работы ([ADR-0039](adr/0039-otmetka-tolko-s-suzhdeniem.md)). Построено в `mastery-marks`: `MasteryService.mark`. |
| Удаление Метода | Допустимо, пока на Метод не опирается ни одна Задача и ни одна отметка Владения — по всем Учителям, без фильтра по владельцу (`MasteryOfMethod` → `MasteryRepository.countByMethod`, класс ADR-0036). Построено в `mastery-marks` (`MasteryGuardsTheMethodTest`). |
| Правка Методов у размеченной задачи | Симметрична удалению Темы: ячейка может остаться без единой задачи. Поведение не определено — элемент бэклога `method-edit-impact`. |
| Правка Задачи с текстом | Заморозка после первого использования ([ADR-0030](adr/0030-zadacha-zamorazhivaetsya-posle-vydachi.md)) распространяется на текст: Задача, уже выданная в Задании, рукой не правится, как и её PDF, — ни правкой текста, ни загрузкой `.md`, ни записью текста, ни заменой Улики. Опечатка в выданной Задаче исправляется новой Задачей: скачать `.md` и завести по нему; отказ правки называет этот путь ([ADR-0055](adr/0055-tekst-zadachi-pervichen-pdf-otrisovka.md)). Правка текста слота перерисовывает только этот слот и отклоняется, если текст изменился после открытия страницы (версия текста). Задаче без текста текст записывается целиком, и прежние PDF становятся Уликами своих слотов. Построено в `problem-text`: `ProblemService.editText`, `writeText`, `replaceEvidence` (`ProblemTextFrozenTest`). |

## Чего в модели нет

Разбор формул и текста Локусом — текст Задачи хранится строкой,
отрисовывается и показывается, понимает его помощник, утверждает человек
([ADR-0055](adr/0055-tekst-zadachi-pervichen-pdf-otrisovka.md)); эталонные
ответы; автоматическая проверка; уведомления; фоновые процессы — кроме
реплики помощника, которую начинает учитель и которая ограничена пределом
и одна на учителя ([ADR-0054](adr/0054-pomoshchnik-claude-code-na-stende-process-na-repliku.md));
шаблоны заданий; история отметок; роль ученика.
По каждому — запись в журнале с причиной; см. `strategy.md`, раздел не-целей.
