# Design

## Context

Что в коде сегодня:

- `assistant/page.html:98-100` — одно поле `name="file"` у Администратора
  (`th:if="${shell.administrator}"`).
- `AssistantController.start` (`:82-97`) принимает один `MultipartFile`,
  открывает его поток и зовёт `AssistantService.startTurn(target, prompt,
  Optional<TurnAttachment>)`. Обработчик отмечен `@LargeUpload`: общий предел
  (`locus.upload`, 20/100 МБ) не действует, действует предел контейнера
  `spring.servlet.multipart` — 100 МБ на файл, 110 МБ на запрос
  (`application.yaml:25-26`), разбор тела ленивый. Превышение сейчас
  уходит безликой страницей ошибки: своего `@ExceptionHandler` у страницы
  Помощника нет (образец есть — `StudentWorkController.tooLarge`, `:205`).
- `AssistantService.startTurn` (`:111-157`): проверки без файла
  (недоступность, пустота), затем при файле — идущая Реплика, ответчик
  `TurnAttachments.attach(TurnAttachment) → String`, строка ответчика
  через пустую строку после текста учителя, предел 20 000 знаков.
- `AssemblyDraftAttachments.attach` (`:27-31`) — `AssemblyDraftService.upload`
  и строка «Загружен черновик сборки N «имя», страниц: K.».
- `AssemblyDraftService.upload` (`:84-122`): уборка по сроку, поток
  на диск, вид по первым байтам, PDF открывается ради числа страниц,
  строка в базе; отказ убирает файл с диска. Транзакции у метода нет —
  строка заводится одним `insert`.
- Скрипт `locus.js` — точечные разделы по признакам `data-*`; вставки
  из буфера в проекте нет.

## Goals / Non-Goals

**Goals:**
- Четыре поля, номер файла — номер поля; всё или ничего до заведения
  первого Черновика сборки.
- Отказ по пределу — на странице Помощника, в том же Разговоре.
- Вставка картинки из буфера в первое пустое поле.
- Навык читает несколько строк «Файл N» и называет файлы номером
  или именем.

**Non-Goals:**
- Вставка из буфера на странице вычитки, в форме Задачи и в приёме Работ —
  решение владельца в карточке: вернуться по итогам сеанса.
- Больше четырёх файлов, перетаскивание файлов мышью.
- Поднятие предела контейнера (см. Р4).

## Decisions

### Р1. Поля — `file1` … `file4`, номер берётся из имени поля

Четыре `<input type="file" name="fileN" data-paste-file>` с подписями
«Файл 1» … «Файл 4» в одном `<fieldset>` формы; видны все четыре,
у Администратора. Контроллер берёт файлы из `MultipartRequest`
по именам `file1`…`file4` и пропускает пустые, так что номер — имя поля,
а не позиция в списке.

*Отвергнуто:* общее имя `files` и номер по позиции — браузер шлёт части
пустых полей не во всех случаях одинаково, и номер зависел бы от того,
пришла ли пустая часть. Три поля под «Ещё файлы» (`<details>`) —
четыре поля невелики, а спрятанное поле, в которое легла вставка, учитель
не увидит; ADR-0042 прячет вторичные *действия*, а поля одной формы — нет.

### Р2. Всё или ничего — двумя шагами в `AssemblyDraftService`

Новый метод `AssemblyDraftService.upload(List<Source>)`: сначала **каждый**
исходник пишется на диск и проверяется (вид, страницы PDF) — тем же кодом,
что у одиночного `upload`, вынесенным в закрытый шаг; первый отказ
убирает с диска файлы всех уже принятых исходников и бросает
`SourceRefusedException` (наследник `IllegalArgumentException`) с позицией
исходника в списке и словами прежнего отказа. Только когда приняты все,
строки заводятся одной транзакцией. Одиночный `upload` становится
частным случаем — списком из одного, поведение и отказы те же.

Ответчик `AssemblyDraftAttachments` переводит позицию в номер поля
и пишет отказ «Файл 2: Файл «скан.heic» не подходит для сборки: …».

*Отвергнуто:* заводить по одному и при отказе удалять заведённые
(`discard`) — между заведением и удалением черновик виден форме Задачи
во второй вкладке, а сбой посреди удаления оставил бы часть; карточка
требует отказа **до** заведения первого. Номер поля внутри `AssemblyDraftService` —
сервис черновиков не знает страницы Помощника, номер остаётся у ответчика.

### Р3. Вопрос `TurnAttachments` — списком, строки — с номером поля

`TurnAttachment` получает номер поля: `TurnAttachment(int number, String
name, InputStream content)` и `label()` — «Файл N». Вопрос становится
`List<String> attach(List<TurnAttachment> files)`: принимает все или ни
одного, возвращает по строке на файл в порядке списка; отказ —
`IllegalArgumentException`, текст которого начинается с `label()` файла.
Ответчик пишет строку целиком: «Файл 1: загружен черновик сборки 57
«IMG_0412.jpeg», страниц: 1.».

`AssistantService.startTurn(conversation, prompt, List<TurnAttachment>)`
соединяет строки ответчика переводом строки и дописывает их блоком
через пустую строку после текста учителя; пустой список — без файлов.
Проверка идущей Реплики до приёма — как прежде.

*Отвергнуто:* префикс «Файл N:» дописывает сервис Помощника, а ответчик
сообщает позицию отказа своим исключением — ещё один тип в
`ru.locus.assistant` ради двух слов; номер поля и так приходит
в `TurnAttachment`.

### Р4. Предел — прежний, отказ — на странице Помощника

Предел контейнера остаётся: 100 МБ на файл и 110 МБ на запрос. Снимок
листа весит единицы мегабайт, сборник — десятки; четыре сборника в одном
запросе — не сценарий разбора листа (предел страниц за Реплику — четыре).
Поднять предел до 400 МБ значило бы пустить такое же тело на любой
`@LargeUpload` и на любую страницу до проверки перехватчика.

У `AssistantController` — `@ExceptionHandler(MaxUploadSizeExceededException)`
по образцу `StudentWorkController.tooLarge`: шапка и подвал кладутся явно,
страница рисуется тем же `render` с отказом «Файлы слишком велики: до
100 МБ на файл и до 110 МБ за один запрос. Набранный текст не
сохранился — наберите его снова.». Числа берутся из `MultipartProperties`,
а не пишутся строкой — чтобы не разъехаться с `application.yaml`.

Тело при превышении не разобрано, поэтому Разговор берётся не из тела:
форма передаёт его **в адресе действия** — `/assistant/turns?conversation=N`
(скрытое поле убирается), и обработчик отказа читает его из строки
запроса (`request.getQueryString()`, не `getParameter` — тот на
multipart-запросе снова полез бы в тело).

### Р5. Вставка из буфера — раздел `locus.js`

Признак — `data-paste-file` на полях файла и `data-paste-status` на строке
сообщения формы. Скрипт слушает `paste` на документе, если на странице есть
поля с признаком:

- в `clipboardData` есть `text/plain` — ничего не делает: вставляется
  текст (Excel и Word кладут рядом с текстом картинку, и отбирать у учителя
  вставку текста в запрос нельзя);
- иначе берёт первый элемент вида `image/*`; нет — ничего не делает;
- первое пустое поле `data-paste-file` получает файл «Вставка N.<ext>»
  (`N` — номер поля из его имени, `ext` — из вида картинки: `png`, `jpg`
  для `jpeg`, иначе подтип) через `DataTransfer`; строка сообщения
  говорит «Вставка N.png — в поле «Файл N»»;
- пустого поля нет — строка сообщения говорит «Свободного поля нет:
  очистите одно из полей файла», поля не меняются.

Вид картинки не фильтруется: GIF или WebP из буфера ляжет в поле, а отказ
по номеру поля даст сервер — одно место проверки вида.

*Отвергнуто:* номер вставки счётчиком на странице («Вставка 1» в поле 3) —
имя, совпадающее с номером поля, однозначно в разговоре с Помощником.

### Р6. Навык

Раздел 1 «Исходник» `problem-intake/SKILL.md`: строки «Файл N: загружен
черновик сборки M …» — по строке на файл; «первый», «второй», «файл 3» —
строка «Файл N»; имя файла целиком или узнаваемой частью — строка с этим
именем; подходит несколько или ни одной — спросить. Файлы одного запроса —
один лист: задачи в порядке чтения сквозь файлы по номерам (раздел 2).
Предел «не больше четырёх страниц за реплику» — на все файлы вместе.
Описание навыка — «строки «Файл N: загружен черновик сборки …»».

## Граница общего и личного

Черновики сборки — личные у загрузившего, заводит их только Администратор
(`@PreAuthorize` у `AssemblyDraftService.upload` и у нового метода),
репозиторий черновиков не меняется. Реплика и Разговор — личные,
`AssistantRepository` не меняется. Общей библиотеки изменение не касается.

## Risks / Trade-offs

- [Набранный текст пропадает при отказе по пределу] → страница говорит
  об этом прямо; вероятность низка — предел 110 МБ.
- [Вставка картинки в браузере без `DataTransfer` в `input.files`] →
  присваивание обёрнуто в проверку; не вышло — сообщение «вставка
  не поддерживается, выберите файл кнопкой».
- [Старые Разговоры несут строку «Загружен черновик сборки N»] → навык
  называет строку без регистра первого слова; продолжение старого
  Разговора по-прежнему находит номер.
- [Четыре потока открыты одновременно] → контроллер закрывает все в
  `finally`; ответчик читает их по очереди.
