## MODIFIED Requirements

### Requirement: Создание узла

Система SHALL позволять Администратору создать узел, указав имя и, при
наличии, родителя. Узел без указанного родителя становится корневым.

Имя узла обязательно, не пустое после отсечения пробелов по краям
и **уникально среди узлов одного родителя**. Уникальность именно среди
братьев, а не по всему дереву: «признаки подобия» — законное имя и под
треугольниками, и под окружностями, а два одинаковых имени в одном списке
неразличимы для того, кто выбирает Тему для задачи.

Создание потомка у Темы, на которой висят Задачи, MUST требовать указания
**Темы-приёмника** — узла, на который переезжают Задачи углубляемой Темы.
Без приёмника операция отклоняется: Тема с появлением потомка становится
Разделом, а на Разделе Задач не бывает никогда (инвариант 1,
[domain-model.md](../../context/domain-model.md)); её Задачи оказались бы
висящими на узле, который их нести не может, — в дереве они больше
не находятся, в статистике не участвуют, и никакой ошибки при этом
не выдано.

Приёмник выбирает Администратор, а не назначает система
([ADR-0007](../../context/adr/0007-pravka-rubrikatora.md)): им может быть
создаваемый потомок либо любая существующая Тема дерева. Приёмник MUST быть
Темой в состоянии дерева **после** операции — узел, который сам перестаёт
быть листом, приёмником быть не может, включая углубляемую Тему.

Теоретические материалы углублению **не мешают** и приёмника не требуют:
материал живёт на любом узле, и Тема, ставшая Разделом, продолжает его нести
([ADR-0018](../../context/adr/0018-teoriya-v-pervoj-versii.md)). Приёмника
требует только то содержимое, которое обязано остаться на Теме, — Задачи
и, когда появятся, отметки Владения.

#### Scenario: Узел создан

- **WHEN** Администратор создаёт узел с непустым именем под указанным
  родителем
- **THEN** узел появляется среди потомков этого родителя

#### Scenario: Имя повторяется среди братьев

- **WHEN** Администратор создаёт узел с именем, которое уже носит другой
  потомок того же родителя
- **THEN** узел не создаётся
- **AND** сообщается, что имя занято

#### Scenario: То же имя под другим родителем

- **WHEN** Администратор создаёт узел с именем, которое уже встречается
  в дереве, но под другим родителем
- **THEN** узел создаётся

#### Scenario: Пустое имя

- **WHEN** Администратор создаёт узел с пустым именем или именем из одних
  пробелов
- **THEN** узел не создаётся

#### Scenario: Потомок у Темы с Задачами

- **WHEN** Администратор создаёт потомка у Темы, на которой размечена хотя бы
  одна Задача, не указав Тему-приёмник
- **THEN** узел не создаётся
- **AND** сообщается, что нужно указать Тему-приёмник для Задач этой Темы
- **AND** Задачи Темы остаются на месте

#### Scenario: Потомок у Темы без Задач

- **WHEN** Администратор создаёт потомка у Темы, на которой Задач нет
- **THEN** узел создаётся
- **AND** вид прежней Темы — Раздел

#### Scenario: Потомок у Темы с Теоретическими материалами

- **WHEN** Администратор создаёт потомка у Темы, на которой лежат
  Теоретические материалы, но нет Задач
- **THEN** узел создаётся
- **AND** материалы остаются на прежнем узле, ставшем Разделом

### Requirement: Удаляется только пустой узел

Система SHALL позволять Администратору удалить узел обычным удалением
**только если узел пуст**. Пустой — значит не имеющий ни потомков, ни
собственного содержимого. Удаление поддерева одним действием
не предусмотрено: узлы снимаются по одному, снизу вверх, и каждый шаг виден.

Содержимым узла считается всё, что на нём висит: Задачи и отметки Владения —
на Теме, Теоретические материалы — на любом узле.

Тема, несущая только Задачи и отметки, снимается **отдельной** операцией —
удалением с распределением Задач; она описана своим требованием и обычным
удалением не является. Узел, несущий свои Теоретические материалы,
не удаляется **никакой** из двух операций: материал законен на любом узле,
распределять его некуда, и снимается или переносится он Администратором
вручную ([ADR-0033](../../context/adr/0033-teoriya-ne-zamorazhivaetsya.md)).

Узел держат только **свои** материалы. Унаследованные с вышестоящих узлов
удалению не мешают: они лежат не здесь, и с исчезновением узла ничего
не теряют.

#### Scenario: Пустой узел удалён

- **WHEN** Администратор удаляет узел, у которого нет потомков
- **THEN** узел исчезает из дерева
- **AND** его прежний родитель остаётся на месте

#### Scenario: Удаление узла с потомками

- **WHEN** Администратор пытается удалить узел, у которого есть потомки
- **THEN** удаление отклоняется
- **AND** ни сам узел, ни его потомки не исчезают

#### Scenario: Родитель после удаления единственного потомка

- **WHEN** у Раздела с единственным потомком этот потомок удалён
- **THEN** вид прежнего родителя — Тема

#### Scenario: Удаление Темы с Задачами

- **WHEN** Администратор удаляет обычным удалением Тему, на которой размечена
  хотя бы одна Задача
- **THEN** удаление отклоняется
- **AND** сообщается, что на Теме есть Задачи и снять её можно только
  с распределением
- **AND** ни Тема, ни её Задачи не исчезают

#### Scenario: Удаление Темы, освободившейся от Задач

- **WHEN** с Темы снята разметка последней Задачи и Тема удаляется
- **THEN** Тема исчезает из дерева

#### Scenario: Удаление узла с Теоретическими материалами

- **WHEN** Администратор пытается удалить узел, на котором лежит хотя бы один
  Теоретический материал
- **THEN** удаление отклоняется
- **AND** сообщается, что на узле есть материалы
- **AND** ни узел, ни его материалы не исчезают

#### Scenario: Удаление узла, наследующего чужие материалы

- **WHEN** Администратор удаляет узел, своих материалов не имеющий, но
  наследующий материалы вышестоящего узла
- **THEN** узел исчезает из дерева
- **AND** материалы вышестоящего узла остаются на месте

## ADDED Requirements

### Requirement: Задачи углубляемой Темы переезжают на Тему-приёмник

Система SHALL при создании потомка у Темы, несущей Задачи, перевесить **все**
Задачи этой Темы на указанную Тему-приёмник в одной операции с созданием
потомка. Разделение операций не допускается: Тема, оставшаяся Разделом
с Задачами хотя бы на мгновение видимого состояния, нарушает инвариант 1.

Перевешивается **одна метка разметки**: в списке Тем Задачи углубляемая Тема
заменяется приёмником, прочие Темы, Методы, Характеристики и Часть Задачи
не меняются. Задача, размеченная и углубляемой Темой, и приёмником сразу,
после операции остаётся размеченной приёмником один раз.

Отметки Владения углубляемой Темы SHALL переезжать на приёмник вместе
с Задачами: Тема-приёмник — та же самая Тема, уточнённая местом в дереве,
и суждение учителя от переезда не меняется
([ADR-0007](../../context/adr/0007-pravka-rubrikatora.md)). Отметок в системе
ещё нет, поэтому переносить сегодня нечего; **появление отметок обязано
пополнить эту операцию** — иначе они останутся на узле, ставшем Разделом,
и перестанут участвовать в статистике молча.

Перевешивание MUST выполняться и над Задачей, уже вошедшей в Задание или
имеющей Работу: перестройка дерева сильнее заморозки Задачи
([ADR-0034](../../context/adr/0034-perestrojka-silnee-zamorozki.md)).

#### Scenario: Задачи переехали на созданного потомка

- **WHEN** Администратор создаёт у Темы с Задачами потомка, указав приёмником
  этого же создаваемого потомка
- **THEN** потомок появляется в дереве
- **AND** все Задачи прежней Темы размечены потомком
- **AND** прежняя Тема Задач больше не несёт, и вид её — Раздел

#### Scenario: Приёмник — существующая Тема в другом месте дерева

- **WHEN** Администратор создаёт у Темы с Задачами потомка, указав приёмником
  Тему из другой ветки
- **THEN** Задачи прежней Темы размечены этой Темой
- **AND** созданный потомок Задач не несёт

#### Scenario: Прочая разметка Задачи не задета

- **WHEN** Задача, размеченная двумя Темами и двумя Методами, переезжает
  с одной из своих Тем на приёмник
- **THEN** её Темами значатся приёмник и прежняя вторая Тема
- **AND** её Методы, Характеристики и Часть остаются прежними

#### Scenario: Задача уже размечена приёмником

- **WHEN** переезжает Задача, размеченная и углубляемой Темой, и Темой,
  выбранной приёмником
- **THEN** приёмник значится среди её Тем один раз

#### Scenario: Приёмником указан узел, перестающий быть Темой

- **WHEN** Администратор указывает приёмником саму углубляемую Тему либо
  другой узел, который после операции окажется с потомками
- **THEN** операция отклоняется
- **AND** ни потомок не создаётся, ни Задачи не переезжают

#### Scenario: Переезжает выданная Задача

- **WHEN** углубляется Тема, на которой размечена Задача, уже вошедшая
  в Задание
- **THEN** Задача переезжает на приёмник наравне с прочими
- **AND** заморозка правки Задачи операции не мешает

### Requirement: Тема с Задачами удаляется с поштучным распределением

Система SHALL позволять Администратору снять Тему, несущую Задачи, отдельной
операцией: для **каждой** Задачи этой Темы он указывает свою Тему-приёмник.
Общего приёмника на всех у операции нет — распределение поштучное
([ADR-0007](../../context/adr/0007-pravka-rubrikatora.md)).

Каждой Задаче MUST быть назначен приёмник: Задача без Темы существовать
не может (инвариант 1), и незаполненное назначение отклоняет операцию целиком.

Приёмником допустим любой узел, который в состоянии дерева **после** удаления
окажется Темой. В их число входит родитель удаляемой Темы, если та была его
единственным потомком: с её уходом родитель остаётся листом и сам становится
Темой — так задачи поднимаются на родителя, когда соседних Тем нет.

Операция снимает Тему целиком: после неё Темы в дереве нет, а все её Задачи
размечены назначенными приёмниками. Ни одна Задача не исчезает.

#### Scenario: Задачи распределены по разным Темам

- **WHEN** Администратор снимает Тему с тремя Задачами, назначив каждой свой
  приёмник
- **THEN** Тема исчезает из дерева
- **AND** каждая Задача размечена своим назначенным приёмником
- **AND** ни одна Задача не исчезла

#### Scenario: Задачи поднимаются на родителя

- **WHEN** снимается Тема, у которой нет братьев, а приёмником для её Задач
  назначен родитель
- **THEN** Тема исчезает
- **AND** Задачи размечены родителем
- **AND** вид родителя — Тема

#### Scenario: Приёмник назначен не всем Задачам

- **WHEN** Администратор оставляет хотя бы одну Задачу снимаемой Темы без
  назначенного приёмника
- **THEN** операция отклоняется целиком
- **AND** ни Тема, ни разметка Задач не меняются

#### Scenario: Приёмником назначен узел, остающийся Разделом

- **WHEN** приёмником для Задачи назначен узел, у которого после удаления
  всё ещё есть потомки
- **THEN** операция отклоняется
- **AND** сообщается, что Задачи несут только Темы

#### Scenario: Распределение выданной Задачи

- **WHEN** среди Задач снимаемой Темы есть вошедшая в Задание
- **THEN** она распределяется наравне с прочими
- **AND** заморозка правки Задачи операции не мешает

#### Scenario: Снятие Темы, несущей свои материалы

- **WHEN** Администратор пытается снять с распределением Тему, на которой
  лежит свой Теоретический материал
- **THEN** операция отклоняется
- **AND** сообщается, что сначала нужно снять или перенести материалы
- **AND** названо, что перенос материала на другой узел — обычная его правка,
  ничем не обусловленная

### Requirement: Перед снятием Темы показывается число исчезающих отметок

Система SHALL перед снятием Темы с распределением показать Администратору
**количество** отметок Владения, которые исчезнут вместе с Темой, считая
отметки **всех** учеников **всех** учителей.

Отметки удаляемой Темы не сливаются ни с кем и не переезжают ни на один
из приёмников: при поштучном распределении получателей несколько, и слияние
размазало бы одно суждение по трём Темам, испортив достоверные значения
побочным эффектом операции над деревом
([ADR-0007](../../context/adr/0007-pravka-rubrikatora.md)).

Этот показ — **единственное** законное место, где Администратору видны данные
личного контура чужих учителей
([ADR-0005](../../context/adr/0005-roli-administrator-uchitel.md)). Он
не фильтруется по владельцу, и отсутствие фильтра здесь — намеренное
исключение, а не упущение
([ADR-0027](../../context/adr/0027-mehanizm-granicy-obshchego-i-lichnogo.md)).
Показывается только число: чьи это отметки, на каких учениках и с какими
значениями, Администратору не сообщается.

Отметок Владения в системе ещё нет, поэтому число сегодня всегда нулевое,
а предупреждение говорит, что терять нечего. **Появление отметок обязано
пополнить этот счёт**: снятая вместе с Темой отметка невосполнима, а пустое
предупреждение выглядит убедительно и обнаружится только по пропавшим
суждениям.

#### Scenario: Предупреждение перед снятием

- **WHEN** Администратор открывает снятие Темы с распределением
- **THEN** показывается число отметок Владения, исчезающих вместе с Темой
- **AND** показывается, что они не переедут ни на один приёмник

#### Scenario: Отметок нет

- **WHEN** снимается Тема, отметок Владения на которой нет
- **THEN** показывается, что исчезающих отметок нет
- **AND** снятие доступно

### Requirement: Экран дерева ведёт перестройку

Система SHALL предлагать обе операции перестройки в правой части экрана
дерева — там же, где живут прочие действия над выбранным узлом.

Форма углубления SHALL принимать имя создаваемого потомка и Тему-приёмник,
причём приёмником по умолчанию предлагается создаваемый потомок: это самый
частый случай — Тему делят, оставляя её содержимое в первой из новых Тем.

Форма снятия Темы SHALL перечислять **все** Задачи Темы поимённо — номером
и подписью — и против каждой предлагать выбор Темы-приёмника. Число
исчезающих отметок Владения показывается на этой же форме, до подтверждения.

Обе формы SHALL показываться только Администратору и только тогда, когда
операция применима к выбранному узлу: у Темы без Задач углубление идёт
обычным созданием потомка, а снятие — обычным удалением.

#### Scenario: Углубление предлагается на Теме с Задачами

- **WHEN** Администратор выбирает Тему, на которой размечены Задачи
- **THEN** форма создания потомка требует указать Тему-приёмник
- **AND** приёмником предложен создаваемый потомок

#### Scenario: Снятие с распределением предлагается на Теме с Задачами

- **WHEN** Администратор выбирает Тему, на которой размечены Задачи
- **THEN** предлагается снятие с распределением
- **AND** перечислены все Задачи Темы с выбором приёмника у каждой

#### Scenario: На пустой Теме перестройки не предлагают

- **WHEN** Администратор выбирает Тему, на которой Задач нет
- **THEN** предлагаются обычные создание потомка и удаление
- **AND** ни приёмника, ни распределения не запрашивается

#### Scenario: Учителю перестройка не предлагается

- **WHEN** экран дерева открывает Пользователь без роли Администратора
- **THEN** ни углубления с приёмником, ни снятия с распределением ему
  не предлагается

#### Scenario: Возврат после перестройки

- **WHEN** Администратор углубил Тему с Задачами
- **THEN** страница показывает затронутый узел
- **AND** узел остаётся выбранным
