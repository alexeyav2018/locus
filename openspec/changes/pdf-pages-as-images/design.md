# Design

## Context

Страница просмотра (`file/viewer.html`, данные — `FileView`) сегодня
показывает изображение тегом `<img>`, а PDF — `<object type="application/pdf">`
с запасным содержимым. Её открывают четыре обработчика:
`ProblemController.viewCondition`/`viewSolution`, `TheoryController.view`,
`StudentWorkController.viewFile`. Каждый сначала достаёт запись через свой
сервис — для Работы это `StudentWorkService.work` с владельцем из
`CurrentUser`, чужая неотличима от несуществующей, — и лишь потом
подписывает ссылку на файл.

Отрисовка PDF в картинку есть в `PdfAssembly.preview` (PDFBox
`PDFRenderer`, JPEG), но работает по черновику в рабочей папке. Файлы
Задач, теории и Работ лежат в `FileStorage`, у которого чтения нет
(ADR-0021); прочитать умеет только `LocalFileStorage.read` (пакетный метод
для `FileController`). Заголовок рамки — `SecurityConfig`, `sameOrigin()`
ради встроенного PDF (ADR-0042). Решение — [ADR-0052](../../context/adr/0052-pdf-na-stranice-prosmotra-kartinkami-stranic.md).

## Goals / Non-Goals

**Goals:**

- PDF на странице просмотра виден в любом браузере, без просмотрщика PDF
  и без скрипта.
- Картинка страницы под теми же правилами доступа, что страница просмотра.
- Повторное открытие не заставляет сервер рисовать страницу заново, пока
  файл тот же.

**Non-Goals:**

- Масштаб и ручки рамки сборки — это `crop-frame-zoom`; размер отрисовки
  для рамки здесь не меняется (`PdfAssembly.PREVIEW_*` прежние).
- Выделение и поиск текста PDF на странице просмотра.
- Хранение отрисованных страниц; фоновые задачи (ADR-0017).

## Decisions

### Где живут данные

Новых данных нет. Картинка страницы — производное от файла, вычисляемое
по запросу и нигде не хранимое. PDF Задач и теории — **общая библиотека**:
картинки их страниц видны всем вошедшим, фильтра по владельцу нет и быть
не должно. Файлы Работ — **личный контур**: картинка страницы выдаётся
только владельцу Работы, проверка — тем же `StudentWorkService.work`
с `UserId` из `CurrentUser`, что и у страницы просмотра. Менять ничего
нельзя: адреса только читают. Хранилище владельцев не знает, как и прежде
(`OwnerIsUnknownToStorageTest`).

### 1. `FileStorage.read` — четвёртая операция

`Optional<byte[]> read(FileKey key)`: пусто — «файла нет», недоступность —
`FileStorageUnavailableException`, как у остальных операций. `LocalFileStorage`
делает свой пакетный метод публичной реализацией; `ObjectFileStorage` —
`GetObject`, `NoSuchKeyException` → пусто. Контракт проверяется общим
`FileStorageContractTest` для обоих вариантов.

Отвергнуто: сервер читает файл по своей же подписанной ссылке HTTP-запросом —
то же чтение окольным путём, для папки ещё и запрос приложения к самому себе.

### 2. Отрисовщик `PdfPages` и служба `FilePages` в `ru.locus.file`

`PdfPages` — чистые функции над байтами PDF: `outline` (число страниц
и размеры видимой области каждой из первых двадцати — для `width`/`height`
у `<img>`, чтобы столбец не прыгал при ленивой загрузке) и `render(page)`
→ JPEG. Неразбираемый или запароленный PDF — пустой `outline`.

`FilePages` — компонент над `FileStorage` и `PdfPages`: по `FileKey`
отдаёт `outline` и картинку страницы. Контроллеры получают ключ из записи,
которую уже достал сервис с проверкой прав, — так же, как сегодня
`FileView.of` получает ключ. В `FileStorage` контроллеры по-прежнему
не ходят (`ProblemControllerIsThinTest` и соседи).

`PdfAssembly` не трогается: у рамки свои пределы и своя связь с долями
страницы (ADR-0045). Общий отрисовщик для обоих решит `crop-frame-zoom`,
если сочтёт нужным.

### 3. Размер отрисовки: ширина до 1600 px и не больше 200 dpi

Столбец заполняет экран по ширине, поэтому предел — по ширине, а не по
длинной стороне, как у рамки. A4 (595 pt) даёт 1600 px ≈ 194 dpi: на
планшете с плотностью 2 при ширине ~800 CSS-пикселей картинка точна без
увеличения и читаема при увеличении щипком вдвое. Предел 200 dpi не даёт
раздувать мелкие страницы. JPEG качества по умолчанию: страница текста —
сотни килобайт.

### 4. Адреса и ответы

| Страница просмотра | Картинка страницы |
| --- | --- |
| `/problems/{id}/condition` | `/problems/{id}/condition/pages/{n}` |
| `/problems/{id}/solution` | `/problems/{id}/solution/pages/{n}` |
| `/theory/{id}/view` | `/theory/{id}/view/pages/{n}` |
| `/works/{id}/files/{fileId}` | `/works/{id}/files/{fileId}/pages/{n}` |

Номер с единицы. Нет записи, чужая Работа, файла нет в Работе, файл
не PDF, страницы нет, файла нет в хранилище — `404`, один ответ.
Ответ — `image/jpeg`, `Cache-Control: private, no-cache` и `ETag`,
вычисленный из ключа файла (хеш, сам ключ наружу не выходит —
у Работ он не должен попадать в разметку). Совпал `If-None-Match` —
`304` до чтения файла: стоит одного обращения к базе. Ключ меняется при
замене файла Задачи, поэтому заменённое условие не показывается из кэша.

Отвергнуто: `max-age` на час, как у черновика, — черновик неизменен,
а слот Задачи заменяется, и учитель час видел бы старое условие.

### 5. Страница просмотра

`FileView` получает список страниц (адрес, ширина, высота), общее число
страниц и признак «не разобрался». Шаблон для PDF выводит столбец
`<img loading="lazy" width height alt="Страница N">`; если страниц больше
двадцати — строку «Показаны первые 20 из N страниц» перед кнопками; если
PDF не разобрался — «Показать этот PDF на странице не удалось». Кнопка
«Открыть PDF» — всегда. Число страниц считается при показе страницы
просмотра: файл читается один раз на открытие.

Предел 20 — константа `PdfPages`; основание — ADR-0052.

### 6. Рамка снова запрещена

`SecurityConfig`: `frameOptions().deny()` — встроенного PDF больше нет,
встраивать страницы приложения в рамку некому. Тест рамки в
`FileViewerScreenTest` переписывается на `DENY`.

### Проверка антипаттернов

Постоянной ссылки на файл нет: адрес картинки страницы требует сеанса
и права на запись, ключа в нём нет. SDK хранилища из сервисов не
вызывается — только `FileStorage`. Своих `<style>` и скриптов в шаблоне
нет — правила в `locus.css`.

## Risks / Trade-offs

- [Каждая картинка страницы заново разбирает весь PDF] → ленивая загрузка
  и предел 20 страниц; повторы гасит `304`. Файлы Задач малы; длинный
  PDF теории — 20 разборов на первое открытие, это принято.
- [Большой PDF Работы целиком в памяти на каждый запрос] → предел загрузки
  20 МБ на файл (`locus.upload`) ограничивает худший случай.
- [Недоступное хранилище теперь роняет страницу просмотра PDF] → это та же
  явная ошибка, что и сегодня при открытии ссылки, только раньше; данные
  и остальные страницы не затронуты (требование `file-storage`).
- [Текст не выделяется, увеличение мягче] → «Открыть PDF» остаётся.
