## Context

Подпись ввёл [ADR-0029](../../context/adr/0029-nomer-i-podpis-zadachi.md)
изменением `problem-catalog`: поле `caption` в `Problem`, колонка `caption`
таблицы `problem` (`0004-problem-catalog.yaml:39`), поле формы
`problem/form.html:43` и показ в шести шаблонах. Номер — это `id.value()`
(`Problem.number()`), он остаётся как есть.

Учитель 08.10.2026 попросил Подпись убрать; владелец решил развилки
карточки: номер — 1(а), без изменений; Подпись — 2(а), убрать из формы
и показа и удалить колонку с данными. Решение —
[ADR-0050](../../context/adr/0050-zadacha-razlichaetsya-tolko-nomerom.md).

Где Подпись проходит по коду сейчас:

| Слой | Место |
| --- | --- |
| схема | `problem.caption VARCHAR` |
| запись | `Problem.caption`, `hasCaption()`, `normalizedCaption` |
| репозиторий | `ProblemRepository.create(caption, …)`, `changeCaption`, `Row.caption`, четыре `select … p.caption …` |
| сервис | `ProblemService.create(caption, …)`, `edit(id, caption, …)` |
| веб | `ProblemController.create/update` (`@RequestParam caption`), `ProblemForm.caption` |
| шаблоны | `problem/form.html`, `problem/problem.html`, `problem/search.html`, `taxonomy/tree.html` (дважды), `assignment/form.html`, `assignment/assignment.html`, `work/assignment.html` |
| тесты | около двухсот вызовов `create` с подписью первым аргументом; проверки показа; `ProblemFilesTest` |

## Goals / Non-Goals

**Goals:**

- Подписи нет нигде: ни в схеме, ни в записи, ни в формах, ни в показе.
- Номер остаётся тем, чем был: идентификатор, сквозной, неизменный.

**Non-Goals:**

- Номер без дыр, отдельный счётчик — отклонены (ADR-0050).
- Предпросмотр первой страницы условия — отложен ещё ADR-0029.
- Перенос введённых подписей куда-либо (в PDF, в журнал) — владелец
  согласился на стирание.

## Где живут данные

Общая библиотека: Задача, ведёт Администратор, читают все вошедшие.
Фильтр по владельцу не появляется. Личные экраны (Задание, приём Работ)
показывают библиотечную Задачу номером и больше ничего у неё не теряют.

## Decisions

### 1. Колонка удаляется миграцией `dropColumn`, а не обнуляется

Миграция `0014-problem-caption-removal.yaml` — один `changeSet`
с `dropColumn` таблицы `problem`, колонки `caption`. Подключать её в
`db.changelog-master.yaml` не нужно: там `includeAll` по папке.

Альтернатива — обнулить значения и оставить колонку — отклонена тем же
доводом, что вариант 2(в) карточки: колонка без смысла в модели. Откатного
скрипта нет по ADR-0023; необратимость — причина уровня `MAJOR`.

### 2. Параметр `caption` уходит из сигнатур, а не игнорируется

`ProblemService.create/edit` и `ProblemRepository.create` теряют первый
параметр; `ProblemRepository.changeCaption` удаляется; `ProblemController`
перестаёт принимать `caption`. Старый браузер со старой формой пришлёт
`caption` лишним параметром — Spring его просто не свяжет, отказа нет.

Альтернатива — оставить параметр и не писать его — отклонена: сигнатура
обещала бы то, чего нет, а ошибочный вызов со строкой подписи тихо
выдавал бы её за Часть или терял. Удаление параметра ломает компиляцию
во всех вызовах — это и нужно: пропущенный вызов не останется молча.

Вызовов в тестах около двухсот. Правятся скриптом, который убирает первый
аргумент **только** в строках, названных ошибками компиляции, и проверяет,
что убираемый аргумент — строковый литерал или `null`; всё прочее — руками.
Компилятор здесь сторож: несовпавшая правка не даёт зелёной сборки.

### 3. Сбой сохранения в `ProblemFilesTest` вызывается внешним ключом

Тест `failedSavingLeavesNothingInTheStorage` проверяет, что неудавшаяся
запись Задачи не оставляет файлов в хранилище, и вызывал сбой настоящей
базой — подписью длиннее колонки. Подписи нет; другой сбой должен быть
таким же настоящим и падать тоже **после** укладки файлов.

Выбор: собрать проверяемый `ProblemService` с наследником
`CharacteristicService`, который признаёт существующей Характеристику
с несуществующим идентификатором. Проверка сервиса пропускает её, файлы
укладываются, строка `problem` вставляется, а вставку в
`problem_characteristic` отвергает внешний ключ базы — сбой настоящий,
подменена только проверка заранее.

Уточнено при реализации: собранный в тесте руками сервис — не прокси,
`@Transactional` на нём не действует, и строка `problem` зафиксировалась бы
без разметки, сломав соседние тесты на общей базе (запись `Problem` без
Темы не читается). Поэтому вызов идёт внутри `TransactionTemplate` — как
настоящий сервис идёт внутри своей транзакции; сбой откатывает строку,
а уборку файлов делает сам сервис. Если `CharacteristicService` не
наследуется (финальный класс или недоступный конструктор), — то же через
`SolutionMethodService` и `problem_solution_method`.

Отвергнуто: подмена репозитория, бросающая исключение, — тест перестал бы
проверять, что упало именно сохранение в базе, ради которого написана
уборка (так и сказано в его комментарии).

### 4. Страница Задачи: строка «Подписи нет» уходит без замены

`problem/problem.html:20–21` показывал подпись либо «Подписи нет: Задача
различается номером». Обе строки удаляются; заголовок «Задача № N» уже
говорит всё. В строках списков (дерево, поиск, Задание, приём Работ)
удаляется только `span` подписи; номер и метки остаются как были.

## Risks / Trade-offs

- [Потеря введённых подписей на стенде] → необратимо по решению владельца;
  в `CHANGELOG.md` и сообщении коммита — предупреждение: перед выкладкой
  копия базы стенда.
- [Тридцать Задач одного сборника различаются только номером] → принятая
  цена (ADR-0050, «Последствия»).
- [Массовая правка тестов] → только по ошибкам компиляции и с проверкой
  образца; сборка зелёная — правка полная.
