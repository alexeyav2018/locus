# Design

## Context

Мотивация — proposal.md, «Why». Что уже есть и на что опирается дизайн:

- **Черновик сборки** (`AssemblyDraft`, `AssemblyDraftService`) — строка
  `assembly_draft` и файл в рабочей папке; все методы сервиса —
  `@PreAuthorize("hasRole('ADMINISTRATOR')")`, владелец — `CurrentUser`.
  `assemble(PdfAssemblyOrder)` собирает и проверяет строки; `discard(ids)`
  удаляет после сохранения Задачи; `sweep()` — по сроку
  (`locus.problem.draft.ttl: 24h`) при открытии инструмента; `clearAll()` —
  при старте (`AssemblyDraftConfiguration`).
- **Порядок сборки** `PdfAssemblyOrder(List<Line>)`, `Line(draft, from, to,
  frame)` — то, что шлёт форма Задачи и инструмент `create_problem`.
  Разбор полей формы — `ProblemController.order(...)` по повторяющимся
  полям `{slot}Draft/From/To/Crop`; разметка строки — фрагмент
  `problem/assembly :: row`, сцена рамок — `locus.js`.
- **Заведение Задачи** — `ProblemService.create(...)`: без текста (два
  `ProblemPdf`) и с текстом (тексты + два необязательных `ProblemPdf`
  Улик); обе зовут `discardDrafts` после записи.
- **Отрисовка в памяти** — `ProblemService.preview(cond, sol)` →
  `RenderedText` → `TextPreview` (страницы картинками `data:`).
- **Инструменты** — реализации `Tools` рядом с контроллером, `ToolResult`
  (JSON, картинка, отказ), сторожа `ToolsAreThinTest` и реестр.

Ограничение среды — ADR-0059 (Предложено): строки по Черновикам сборки,
держание, срок, перезапуск, пометки `⟦…⟧`.

## Goals / Non-Goals

**Goals:**

- Черновик Задачи с версией, одна правка через один метод сервиса
  для страницы и для Помощника.
- Страница вычитки без своего скрипта: сцена рамок — существующая.
- Держание Черновиков сборки, не ломающее формы Задачи.

**Non-Goals:**

- Навык Помощника (`intake-skill`) и правки `agent/CLAUDE.md` —
  отдельный элемент.
- Дораспознавание существующей Задачи (`backfill-skill`).
- Заведение нового Метода кнопкой со страницы вычитки — новые Методы
  показаны списком со ссылкой на словари; заводит их Администратор там
  или Помощником после «да».
- Улика, переживающая перезапуск (ADR-0059, отвергнутое).

## Decisions

### Р1. Сущность и схема — шесть таблиц, без JSON

`problem_draft`: `id`, `user_id`, `part` (может быть пусто),
`condition_text`, `solution_text` (оба `TEXT`, пусто — `''`), `version`
(`BIGINT`, с нуля), `changed_by` (`ASSISTANT` | `OWNER`), `changed_at`,
`created_at`. Уникальность `(id, user_id)` — под составной ключ строк.

Дочерние, все с `ON DELETE CASCADE` от черновика и `position`:

- `problem_draft_line`: `draft_id`, `user_id`, `slot` (`CONDITION` |
  `SOLUTION`), `position`, `assembly_draft_id`, `page_from`, `page_to`,
  `frame` (строка `CropFrame.formValue()` или пусто). Ключ
  `(assembly_draft_id, user_id)` → `assembly_draft(id, user_id)`
  **без** каскада: Черновик сборки, на который ссылаются, база удалить
  не даст — ошибка держания всплывёт громко, а не дырой в Улике.
  `(draft_id, user_id)` → `problem_draft(id, user_id)` — строка не может
  принадлежать чужому черновику.
- `problem_draft_topic`, `problem_draft_method`,
  `problem_draft_characteristic`: ссылки на узел и словари
  **с каскадом** от библиотеки — разметка черновика лишь предложение,
  удаление Метода или Темы её просто сужает; проверяет разметку
  `ProblemService` при заведении. Ответчиков `DictionaryUsage`
  и `NodeContent` черновик не заводит: удалению из библиотеки
  он не мешает.
- `problem_draft_note`: `kind` (`DOUBT` | `NEW_METHOD`), `position`,
  `text` — два упорядоченных списка строк одной таблицей.

В проекте нет ни `jsonb`, ни массивов; дочерние таблицы — сложившийся
образец (разметка Задачи). Отвергнуто: строки сборки одним `TEXT`
в собственном формате — не держит ссылку на Черновик сборки ключом,
а держание (Р4) должно быть видно базе.

Пакет — `ru.locus.problem`: черновик — часть области Задач, его
репозиторий и `AssemblyDraftRepository` видят таблицы друг друга
одним SQL (Р4).

### Р2. Только Администратор

Все методы `ProblemDraftService` — `hasRole('ADMINISTRATOR')`, как
у `AssemblyDraftService`: строки ссылаются на Черновики сборки, которые
загружает только Администратор (ADR-0044), а утверждение — заведение
Задачи — тоже его. Черновик без строк Учителю был бы бесполезен:
завести из него Задачу он не может. Пользователь с обеими ролями —
тот же владелец (ADR-0005).

### Р3. Одна запись — `ProblemDraftService.write` с частичным изменением

`create(content, editor)` и `write(id, version, change, editor)`,
где `change` — запись с необязательными полями (`null` — не трогать),
`editor` — `OWNER` или `ASSISTANT`. Страница шлёт все поля всегда;
инструмент — только названные. Сравнение версии и запись — одним
`UPDATE … WHERE id = ? AND user_id = ? AND version = ?`; ноль строк →
различить «нет такого/чужой» и «изменён» вторым чтением с владельцем:
нет — `ProblemDraftNotFoundException` (404 / единый отказ инструмента),
есть — `ProblemDraftChangedException` «Черновик Задачи изменён после
того, как вы его прочитали, — перечитайте его».

Кто правил, передаёт **вызывающий** константой: контроллер — `OWNER`,
инструмент — `ASSISTANT`. Отвергнуто: сервис узнаёт это по виду входа
(токен Реплики) — пришлось бы научить `CurrentUser` знать о Помощнике,
а подмена константы ничего не даёт: это одна и та же личность.
Константа — не логика; `ToolsAreThinTest` её не запрещает.

Проверки при записи (спека, первое требование): Темы — листья
(`NotATopicException`), Методы и Характеристики существуют — через
пакетный метод `ProblemService.requireDraftMarkup(...)` поверх уже
имеющегося `requireExistingMarkup`; строки — новым
`AssemblyDraftService.check(order)`: черновики свои и есть, страницы
в пределах, Рамка на одной странице — те же тексты отказов, что
у `assemble`, без сборки. Тексты не отрисовываются при записи:
неразбираемая формула — забота сохранения Задачей (спека).

### Р4. Держание Черновиков сборки — в SQL двух удалений

`AssemblyDraftRepository.deleteByIds(owner, ids)` и
`deleteCreatedBefore(instant)` получают условие
`AND NOT EXISTS (SELECT 1 FROM problem_draft_line l WHERE
l.assembly_draft_id = assembly_draft.id)`. Этого достаточно для всех
путей: форма, `create_problem` и сохранение черновика — все приходят
в `discardDrafts` → `discard` → `deleteByIds`.

Сохранение черновика Задачей — одна транзакция в
`ProblemDraftService`: сначала `write` введённого (версия +1), затем
снимок черновика, затем **удаление строки черновика** (строки уходят
каскадом), затем `ProblemService.create(...)` с порядками из снимка.
Порядок важен: к `discardDrafts` ссылок этого черновика уже нет,
и последний черновик забирает исходник, а ссылки других остаются.
Откат при отказе `create` возвращает и черновик, и Черновики сборки.

Но спека требует: «отказ заведения оставляет введённое сохранённым».
Поэтому страница делает **два вызова**: `write` (своя транзакция),
затем `save(id, version + 1, kind)` (своя). Отказ второго оставляет
записанное первым. Инструмент `save_problem_draft` зовёт только
`save` — правку он делает отдельным `update_problem_draft`.

Уборка: `ProblemDraftService.sweep()` удаляет черновики с `changed_at`
старше `locus.problem.intake.ttl` (по умолчанию `7d`) и затем зовёт
`AssemblyDraftService.sweep()` — освобождённые Черновики сборки уходят
той же уборкой, если их срок прошёл. Зовётся при открытии списка
`/problems/intake`, при `create` и при `list_problem_drafts`.
Старт: раннер `AssemblyDraftConfiguration` зовёт
`ProblemDraftService.clearAll()`, а тот удаляет все черновики Задачи
(`ProblemDraftRepository.deleteAll()`) и лишь затем зовёт
`AssemblyDraftService.clearAll()` — иначе ключ строк не дал бы удалить
Черновики сборки. Зависимость одна: черновик Задачи знает о Черновике
сборки, обратной нет. Методы без владельца —
`deleteChangedBefore` и `deleteAll`, класс уборок ADR-0044,
перечислены в `OwnerIsRequiredByProblemDraftsTest`.

Срок от последней правки, а не от заведения: черновик, к которому
вернулись, жив. Семь дней, а не сутки Черновика сборки: вычитка листа
может растянуться на несколько вечеров, а держит черновик лишь место
на диске.

### Р5. Пометки `⟦…⟧` — функция `DoubtMarks`

Чистая функция в `ru.locus.problem`: `strip(text)` убирает знаки `⟦`
и `⟧`, оставляя фрагмент; `fragments(text)` — помеченные фрагменты
с контекстом (до 40 знаков с каждой стороны) для показа. Непарный знак
показывается и снимается как есть — Локус текст не разбирает
(ADR-0055, п. 4), он лишь снимает два зарезервированных знака.

Где снимается: отрисовка на странице вычитки (`ProblemService.preview`
от снятого текста) и `save` — тексты Задачи без знаков. Внутри формулы
снятие оставляет формулу верной: `$\log_2 ⟦8⟧$` → `$\log_2 8$`.

Подсветка — на странице вычитки, блок «Сомнительные места»: каждый
фрагмент с контекстом, сам фрагмент — `<mark>`; ниже — причины списком.
Отвергнуто: подсветка в самой отрисовке PDF — пришлось бы учить
отрисовщик цвету внутри формул JLaTeXMath, а показ контекста решает
то же: взгляд приведён к месту, рядом — Улика.

### Р6. Страница вычитки и адреса

| Адрес | Что |
| --- | --- |
| `GET /problems/intake` | список своих черновиков, с уборкой |
| `GET /problems/intake/{id}` | страница вычитки |
| `POST /problems/intake/{id}` | «Сохранить черновик» |
| `POST /problems/intake/{id}/problem` | «Сохранить как Задачу» |
| `POST /problems/intake/{id}/snapshot` | «Взять снимок как есть» |
| `POST /problems/intake/{id}/delete` | «Удалить черновик» |

Одна форма, три кнопки `formaction` (как «Предпросмотр» формы Задачи) —
все три шлют всё введённое и скрытую `version`; удаление — отдельная
форма под `<details>` (ADR-0042). После «Сохранить черновик» —
перенаправление на страницу вычитки; после заведения — на Задачу. Отказ
версии — страница вычитки с **хранимым** черновиком и отказом наверху:
введённое учителем при этом не возвращается в поля — оно писано
по устаревшему, и молча смешать его с чужой правкой нельзя; отказ это
называет. Прочие отказы (разметка, формула, слот) — страница
с хранимым черновиком: введённое уже записано первым вызовом (Р4).

Раскладка — `page--wide`: две колонки на широком экране, столбцом
на планшете. Слева «Улика»: условие, решение — картинки страниц PDF,
собранного `AssemblyDraftService.assemble` из строк слота
(`TextPreview`-подобная запись картинками `data:`, не больше
`PdfPages.SHOWN`); слот без строк — «Улики нет». Справа «Отрисовка»:
`TextPreview` от снятых текстов, отказ — на месте. Ниже — «Сомнительные
места» (Р5), поля текстов, сцена рамок (поле файла слота и строки
`problem/assembly :: row` с теми же именами полей, что у формы Задачи —
разбор `order(...)` выносится из `ProblemController` в пакетную
`AssemblyOrderForm`, чтобы не дублировать), разметка теми же
элементами, что форма Задачи, новые Методы списком со ссылкой
на `/dictionaries`, отметка «изменён Помощником / вами, когда».
Скрипт — только существующий в `locus.js`; своих `<style>` нет
(ADR-0041), новые классы — в `locus.css`.

Сборка Улики на каждый показ: строки — куски одного-двух фото,
это доли секунды; сборник целиком (строка «все страницы») собирается
без пересборки (ADR-0049), показываются первые двадцать страниц.

Ссылки: список черновиков — со страницы Помощника для Администратора
(«Черновики Задач: N») и из ответа Помощника — `create_problem_draft`
возвращает адрес `/problems/intake/{id}`, `AnswerMarkdown` делает его
внутренней ссылкой с `from`. Пункта в шапке нет: черновики — короткоживущая
очередь вычитки, а не раздел.

### Р7. Инструменты — `ProblemDraftTools`, плюс `create_method`

Шесть инструментов черновика (спека) рядом с контроллером, тем же
разбором строк, что у `create_problem` (`ProblemTools.line` становится
пакетным). JSON ответа — плоские поля `snake_case` (locus-mcp, Р5):
`id`, `version`, `changed_by` (`assistant` | `teacher`), `changed_at`,
`condition_text`, `solution_text`, `condition`/`solution` — строки
`{draft, from, to, frame}`, `doubts`, `part`, `topics`/`methods`/
`characteristics` — идентификаторы с именами, `new_methods`, `link`.
Отказ версии и «не найден» — `ToolResult.refusal` с текстом сервиса.
`update_problem_draft`: отсутствие аргумента — «не трогать»; пустой
список — «очистить».

`create_method` — в `DictionaryTools`, обёртка
`SolutionMethodService.create(name)`. Нужен навыку `intake-skill`
(«Метод завести только после «да»»), а навык — документ без дельты спек
и инструмента добавить не может. Отвергнуто: оставить `intake-skill`
без него — тогда Помощник предлагает новый Метод, а учитель идёт
заводить его на другую страницу посреди разговора.

### Р8. Изоляция и сторожа

- `OwnerIsRequiredByProblemDraftsTest` — у каждого метода
  `ProblemDraftRepository` параметр `UserId`, кроме `deleteChangedBefore`
  и `deleteAll` (поимённо).
- `ProblemDraftsAreFilteredByOwnerTest` — Б не видит, не пишет,
  не сохраняет и не удаляет черновик А; строка по черновику сборки А
  в черновике Б отклонена и сервисом, и составным ключом базы.
- `ToolsAreThinTest`: `ProblemDraftTools` в `TOOLS`,
  `ProblemDraftRepository` в `FORBIDDEN`; реестр — семнадцать имён.

### Р9. Уровень версии — MINOR

Дельта спек есть, новая область данных — небольшая и личная,
интерфейс прежний. Горизонт редакции 3 учитель получит вместе
с `intake-skill`; там же владелец может поднять уровень.

## Risks / Trade-offs

- [Перезапуск теряет вычитку] → решено ADR-0059: повторить
  распознавание дешевле второго места для файлов; перезапуски делает
  владелец (ADR-0051), он же знает, что черновики уйдут.
- [Черновик держит сборник на 300 страниц неделю] → только место
  на диске; при старте уходит всё.
- [Учитель заполнил поля, а Помощник тем временем записал] → отказ
  версии, введённое не возвращается в поля (Р6) — потеря набранного
  учителем после чужой правки. Окно мало: Помощник пишет только
  во время своей Реплики, а учитель в это время в разговоре. Принято
  как цена отсутствия слияния.
- [Тема черновика перестала быть листом после перестройки дерева] →
  отказ при сохранении Задачей называет это; учитель выбирает Тему.
- [`⟦` в настоящем условии] → в школьной математике не встречается;
  ADR-0059 резервирует знаки.

## Migration Plan

Миграция `0017-problem-intake` — только новые таблицы. Откат —
прежняя версия приложения на той же базе работает: новых таблиц она
не знает, а держать Черновики сборки перестаёт, что безопасно
(ADR-0024). Данные черновиков временные и при старте всё равно уходят.
