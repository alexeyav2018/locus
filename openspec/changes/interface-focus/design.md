## Context

См. proposal.md — зачем. Состояние сейчас (проверено по коду):

- Шаблоны: форм на страницу от одной до шести; `<details>` только в рубрикаторе
  (`taxonomy/tree.html`) и в отборе Заданий (`assignment/list.html`).
- Отказ сервиса: 29 мест в контроллерах возвращают ту же страницу прямо из POST
  (`DictionaryController.refused`, аналоги), успех — redirect (PRG). На такой
  странице адрес — адрес действия.
- «Назад» — фиксированные ссылки внизу или вверху страницы.
- Файлы: `FileController` отдаёт `/file/{key}` по подписи; ссылки строят
  контроллеры Задач, теории и Работ. `SecurityConfig` не настраивает рамки —
  действует умолчание Spring Security `X-Frame-Options: DENY`.
- Ошибки: нет `templates/error.html`, действует белая страница Spring.
- Ограничения: Thymeleaf, без новых зависимостей и без фронтенд-фреймворка
  ([ADR-0020](../../context/adr/0020-stek.md)); скрипты только из
  `/js/locus.js`, встроенных нет ([ADR-0041](../../context/adr/0041-edinaya-sistema-oformleniya.md),
  `TaxonomyScreenTest.noTemplateCarriesAScript`); тесты проверяют текст
  и счёт слов в странице, и свёрнутое содержимое остаётся в разметке.

Где живут данные: новых нет. Просмотр файлов — те же файлы: библиотечные
(Задачи, теория) без фильтра по владельцу, личные (снимки Работ) только
владельцу Работы — решает тот же сервис, что и сегодня; изменение прав не
вводит и не отнимает.

## Goals / Non-Goals

**Goals:**
- Выполнить три правила владельца на всех экранах без нового клиентского кода,
  кроме необязательного закрытия блока кнопкой.
- Контроллеры не знают о блоках: раскрытие определяется адресом действия.
- Любой путь «из экрана» — кнопкой или ссылкой страницы.

**Non-Goals:**
- htmx, подгрузка блоков, модальные окна.
- Возврат по `from` через действие (после сохранения переход — на раздел по
  умолчанию, как сегодня).
- Меню профиля и сложная шапка; мобильное приложение; тёмная тема сверх уже
  сделанной.
- Просмотр внешних ссылок теории внутри системы.

## Decisions

### 1. Блок — `<details class="more">`, группа — общий `name`
Стандартный элемент, работает без скрипта, доступен с клавиатуры. `name`
делает группу исключающей (Chrome 120+, Firefox 130+, Safari 17.6+; в старых
браузерах блоки просто раскрываются независимо — деградация безвредна).
Альтернатива «ссылка на отдельную страницу правки» отвергнута: владелец просил
раскрытие на той же странице.

### 2. Раскрытие при отказе — по адресу действия, без правки контроллеров
`ShellAdvice` кладёт в `Shell` адрес запроса, если он POST (`posted`), и метод
`opened(String... suffixes)` — «адрес оканчивается одним из окончаний».
Шаблон ставит у блока `th:attr="open=${shell.opened('/name')} ? 'open'"`.
Окончания различимы в пределах экрана (`/methods/…/name` против
`/characteristics/…/name` — окончание `/methods`, `/characteristics`
и т. п. подбирается по месту). Альтернатива «контроллер кладёт `open=rename`»
отвергнута: 29 правок в контроллерах ради разметки и риск забыть место —
ошибка тихая. Введённое в поле сохраняется там, где контроллер уже отдаёт его
обратно; где не отдаёт, это отдельная доработка на задачу, а не требование
спеки «имя сохранено» — задачи 3.x проверяют это по экранам и допускают
восстановление значения из параметров запроса в шаблоне.

### 3. `from` — `ReturnTo` и `ShellAdvice`
`ReturnTo.safe(String)` возвращает значение, если оно: не пусто, начинается
ровно с одного `/`, вторым символом не `/` и не `\`, без символов < 0x20,
без `://`, не длиннее 1000 символов; иначе пусто. `ShellAdvice` добавляет в
`Shell`: `back` (проверенный `from` либо `null`), `here` (путь и запрос
текущей страницы, для передачи вглубь) и `backOr(String default)`. В шаблонах:
`th:href="@{${shell.backOr('/students')}}"`; ссылки списка на карточку —
`@{/students/{id}(id=…, from=${shell.here})}` (Thymeleaf кодирует значение).
Альтернатива «последний список в сеансе» отвергнута: ломается с двумя
вкладками и не работает по прямой ссылке. Вложение `from` в `from` ограничено
пределом длины: превышение даёт возврат на раздел по умолчанию.

### 4. Ошибки — `templates/error.html` и `ErrorViewModel`
Boot подбирает шаблон `error` по имени; статус берётся из атрибута запроса.
`ControllerAdvice` применяется и к `BasicErrorController`, поэтому шапка
остаётся; для посетителя без входа `shell` равен `null`, и шапки нет. Тексты —
по статусу (403, 404, прочее); сообщение исключения и трассировка не выводятся
(`server.error.include-*` оставлены по умолчанию — `never`).

### 5. Просмотр файлов — четыре маршрута и один шаблон
`GET /problems/{id}/condition`, `GET /problems/{id}/solution`,
`GET /theory/{id}/view`, `GET /works/{id}/files/{fileId}` собирают модель
`FileView(title, link, image, back)` и отдают `templates/file/viewer.html`.
Ссылку строит тот же сервис, что строит её сегодня, — права не дублируются.
Чужая Работа — тот же ответ, что на несуществующую (404 → страница ошибки).
`image` берётся по `FileType`. PDF — `<object type="application/pdf">` с
запасным содержимым-кнопкой «Открыть PDF» (новая вкладка). Рамка: в
`SecurityConfig` `frameOptions(sameOrigin)` — файловая реализация отдаёт
`/file/{key}` с того же источника; у объектного хранилища источник другой,
и встраивание зависит от его заголовков (проверяется задачей 5.4, при отказе
хранилища остаётся запасная кнопка). Существующие адреса `/theory/{id}/file`
и подписанные ссылки не меняются.
Альтернатива «ссылка в той же вкладке» отвергнута: возврат из просмотрщика
браузера — снова средство браузера.

### 6. «Отмена» блока — необязательный скрипт
Кнопка `<button type="button" data-close>` скрыта, пока `html` не получил
класс `js`; скрипт ставит класс и закрывает `details` по нажатию. Без скрипта
блок закрывает его заголовок. Страницы-формы получают «Отмену» ссылкой на
`backOr(раздел)` — скрипт не нужен.

### 7. «Выйти» в шапке — форма в шапке
Единственный `<form>` каркаса; тест экрана Владения «ни одной формы»
уточняется: форма выхода допускается, любая другая — нет (смысл — «экран только
читает» — сохраняется).

### 8. Порядок на экране
Правило: данные и переходы — на виду; переименование, перенос, замена файлов,
удаление, заведение на списках, необязательные поля — блоки; необратимое —
отдельным блоком «Опасная зона» внизу. Экран приёма Работ: Работа каждой Задачи
показывает на виду статус, вердикт, файлы-ссылки и примечание; «Принять Работу»
(когда Работы нет), «Вердикт», «Владение», «Добавить файлы», «Удалить Работу» —
блоки. Фильтры поиска остаются на виду: это основное действие экрана.

## Risks / Trade-offs

- [Тесты считают слова: «Переименовать», «Удалить», «Добавить потомка» ==1] →
  подписи кнопок и заголовков блоков не повторяют друг друга; проверка —
  полный прогон после каждого экрана.
- [Встроенный PDF не показывается на телефонах и в части браузеров] →
  запасная кнопка «Открыть PDF»; изображения показываются везде.
- [Объектное хранилище может запретить встраивание] → то же запасное
  поведение; проверить на S3-совместимом образе из тестов (`MinioImage`).
- [`from` как вектор переадресации] → только внутренние адреса, проверка
  `ReturnTo` с отдельными тестами; ссылка нигде не используется для HTTP-redirect,
  только как `href`.
- [Скрытое всё равно в разметке] → это не права: роль решается на сервере,
  недоступное действие на странице отсутствует; тест «Недоступное действие».
- [После действия контекст `from` теряется] → зафиксировано в ADR-0042.
- [Доработка «введённое сохраняется» растёт] → ограничена экранами, где
  контроллер уже передаёт значение назад; остальное — в бэклог.

## Migration Plan

Только разметка, стили и два небольших компонента; миграций базы нет. Откат —
возврат коммита. Порядок: инфраструктура (шапка, `ReturnTo`, ошибки) →
экраны по одному → просмотр файлов → документы.
