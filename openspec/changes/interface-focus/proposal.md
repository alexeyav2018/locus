## Why

Первая работа над интерфейсом (`ui-redesign`, [ADR-0041](../../context/adr/0041-edinaya-sistema-oformleniya.md))
дала единый вид, но не порядок на экране: на карточке Ученика, экране приёма
Работ, в рубрикаторе и словарях формы правки, переименования и удаления лежат
рядом с данными и видны всегда. Владелец сформулировал три правила:
пользователь видит на странице только полезное; нужное дополнительное
открывается кнопкой на той же странице; на любом экране хватает кнопок для
навигации, браузер не нужен. Сегодня третье не выполняется: «назад» ведёт на
список без условий (фильтры поиска теряются), у форм нет «Отмены», отказ сервиса
оставляет в адресной строке адрес действия, ошибки 404/500 — белая страница
без шапки, файлы открываются в новой вкладке, из которой выходят кнопкой
браузера.

## What Changes

- Вторичное складывается: переименование, перенос, удаление, замена файлов,
  редкие поля и «Завести …» на списках уходят под раскрывающиеся блоки
  (`<details>`) на той же странице; частое и сами данные остаются на виду.
  При отказе сервиса раскрыт тот блок, чьё действие отклонено.
- Каждая форма имеет выход: на страницах-формах — «Отмена», в раскрытых блоках —
  «Отмена», сворачивающая блок.
- Контекстный возврат: переход из списка к карточке несёт параметр `from`
  (внутренний адрес), ссылка «назад» ведёт туда; чужой или неверный `from`
  игнорируется.
- Собственные страницы ошибок (403/404/500) с шапкой и кнопками «Назад»
  и «На главную».
- Просмотр файлов внутри страницы с кнопкой «Назад»: снимки Работ — картинкой,
  PDF Задач и теории — встроенным просмотром с запасной ссылкой.
- «Выйти» в шапке на каждом экране.
- ADR-0042 (Предложено): решения о блоках, `from` и просмотре файлов.
- **Не меняется:** модель, сервисы, права, границы владельца, адреса действий,
  поля форм; новых зависимостей нет.

## Capabilities

### New Capabilities
- `interface-navigation`: порядок информации на экране (главное на виду,
  вторичное по кнопке), выход из любой формы, контекстный возврат, страницы
  ошибок, просмотр файлов внутри страницы, выход из системы из шапки.

### Modified Capabilities

(Требования существующих спеков не меняются: поведение данных и прав прежнее.)

## Impact

- **Где живут данные:** новых данных нет. Просмотр файлов показывает те же
  файлы, что и ссылки сегодня: библиотечные (PDF Задач, теория) — всем, личные
  (снимки Работ) — только владельцу Работы; фильтр по владельцу применяется
  там же, где сегодня, — в сервисах.
- Код: шаблоны всех экранов, `static/css/locus.css`, `static/js/locus.js`
  (закрытие блока кнопкой «Отмена» — необязательное улучшение), `ShellAdvice`
  (адрес возврата, адрес текущей страницы, отклонённое действие), новый
  `ReturnTo` (проверка адреса), `templates/error.html`, `templates/file/viewer.html`,
  четыре маршрута просмотра в контроллерах Задач, теории и Работ,
  `SecurityConfig` (рамка допускается для своего источника).
- Тесты: новые на проверку `from` и права на просмотр файла; пересмотрен
  `MasteryOverviewScreenTest` (форма выхода в шапке — единственная на экране).
- Документы: `ux-concept.md`, `CLAUDE.md`, ADR-0042.
- Ограничение платформы: встроенный просмотр PDF на телефонах ненадёжен
  (Android Chrome скачивает), поэтому у просмотра PDF есть запасная кнопка
  «Открыть PDF»; изображения Работ показываются везде.
