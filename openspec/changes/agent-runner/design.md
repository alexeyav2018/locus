# Design

## Context

Мотивация — proposal.md, «Why». Что уже есть и что определяет подход:

- **Токен Реплики построен** (`TurnTokens.java`): `issue(UserId, Duration)`,
  `resolve`, `revoke`; живёт в памяти. Цепочка `/mcp` пускает только
  с живым токеном (`TurnTokenFilter`). Реестр (`ToolRegistry.names()`)
  — единственный список инструментов.
- **Образец уборки при старте** — `AssemblyDraftConfiguration.java:20`:
  `ApplicationRunner`, который при подъёме убирает всё брошенное.
  Реплика в «работаю» после перезапуска — ровно такой брошенный остаток.
- **Образец личного репозитория** — `LessonRepository`: `JdbcClient`,
  `UserId` в каждом методе, составной ключ `(id, user_id)` не даёт базе
  сослаться на чужое (`0012-schedule.yaml`).
- **Свойства Claude Code измерены** `agent-spike` (2.1.309, VPS стенда):
  `.mcp.json` рабочего места с `${…}` в заголовке подключается в `-p`
  при `enableAllProjectMcpServers` в `.claude/settings.json` рабочего
  места; `--resume` вместе с `--allowedTools` и MCP работает; SIGTERM
  убивает процесс в срок без сирот, прерванный сеанс возобновляется;
  предел ходов — `subtype: error_max_turns` в итоге. Пределы: ход
  6–8 с, Реплика с картинкой 14–24 с — стартовые 10 ходов и 180 с.
- **Формат `stream-json`** снят живым вызовом Claude Code 2.1.310
  (`-p --output-format stream-json --verbose`): строки JSON по одной;
  первая — `{"type":"system","subtype":"init","session_id",…,
  "claude_code_version",…}`, далее `{"type":"assistant","message":
  {"content":[{"type":"text"|"tool_use",…}]}}` и `{"type":"user",…}`
  с результатами инструментов, служебные (`rate_limit_event`)
  и последняя — `{"type":"result","subtype":"success"|"error_max_turns"|…,
  "is_error","result","total_cost_usd","usage":{"input_tokens",
  "cache_creation_input_tokens","cache_read_input_tokens",
  "output_tokens"},"num_turns","duration_ms"}`. Вложенный запуск
  из сеанса Claude Code отклоняется, пока в окружении есть `CLAUDECODE`.
- **Ключа API у владельца сейчас нет** (записка `agent-spike`): Claude
  Code ходит по подписке. Для процесса с отдельным `CLAUDE_CONFIG_DIR`
  на учителя файл входа подписки из домашнего каталога не виден;
  подписка в неинтерактивном режиме приходит переменной
  `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`).

**Граница общего и личного.** Разговор и Реплика со строками хода —
**личный контур** учителя: правит их только сервис от имени владельца,
каждый запрос репозитория — с `UserId`, кроме одной уборки при старте
(класс исключений [ADR-0036](../../context/adr/0036-voprosy-biblioteki-bez-vladelca.md):
только переводит состояние и ничего наружу не показывает). Составной
ключ `assistant_turn (conversation_id, user_id) → assistant_conversation
(id, user_id)` не даёт базе привязать Реплику к чужому Разговору.
Процесс действует токеном, выпущенным на учителя, — что тот не может
на странице, не может и процесс. Рабочее место и каталог настроек
Claude Code — свои у каждого учителя: чужой сеанс не возобновить ни
идентификатором (его выдаёт только свой Разговор), ни через файлы
(у каждого свой `CLAUDE_CONFIG_DIR`). Библиотеки изменение не трогает.

Проверено по `antipatterns.md`: фоновой работы нет, кроме самой Реплики
— её начинает учитель, она ограничена временем и ходами, одна
на учителя; очереди, тёплого процесса и уборки по расписанию нет;
пометка прерванных — при старте, как у черновиков. Фильтр по владельцу
на личных данных держит репозиторий; к библиотеке не применяется.
Интерпретации содержимого Локусом нет: ответ Помощника хранится строкой.

## Goals / Non-Goals

**Goals:** Реплика учителя исполняется процессом Claude Code в клетке
рабочего места под токеном на Реплику и доходит до конечного состояния
в любом исходе — ответ, падение, зависание, предел ходов, остановка,
перезапуск Локуса; Локус без Claude Code работает и называет причину;
навыки называют только инструменты реестра.

**Non-Goals:** страница разговора, поле ввода, загрузка файла в чат,
отображение ответа Markdown, «Новый разговор» и пункт шапки —
`assistant-chat`; навыки сценариев — `intake-skill`, `backfill-skill`;
тёплый процесс между Репликами (ADR-0054, отвергнуто сейчас);
отдельный пользователь ОС для процесса — эксплуатация (ADR-0057).

## Decisions

### Р1. Таблицы Разговора и Реплики строит это изменение

**Под вопросом:** карточка `assistant-chat` называет таблицы
`assistant_conversation`, `assistant_turn` и тесты изоляции своими;
карточка `agent-runner` требует, чтобы незавершённая Реплика после
перезапуска была помечена прерванной, а сеанс возобновлялся.
**Варианты:** (а) исполнитель держит состояние в памяти, хранение —
в `assistant-chat`; (б) хранение здесь. **Выбрано (б):** пометить после
перезапуска можно только то, что пережило перезапуск, а сеанс
возобновляется по идентификатору, сохранённому с Разговором; признак
готовности этой карточки без таблиц не проверить. `assistant-chat`
получает готовые таблицы и тесты изоляции; карточка в бэклоге
поправляется.

### Р2. Состояния Реплики — семь, «прервано по шагам» отдельно

`TurnState`: `RUNNING` (работаю), `DONE` (готово), `FAILED`
(не удалось), `STOPPED` (остановлено), `TIMED_OUT` (прервано
по времени), `STEP_LIMIT` (прервано по шагам), `INTERRUPTED`
(прервано перезапуском). **Под вопросом:** карточка `assistant-chat`
перечисляет шесть слов, без предела ходов. **Варианты:** считать
`error_max_turns` неудачей с причиной или отдельным состоянием.
**Выбрано отдельное:** это не сбой, а предел, симметричный пределу
времени, и учителю есть что сделать — сказать «продолжай» в том же
Разговоре; «не удалось» звало бы искать поломку. Слово состояния
даёт перечисление (`TurnState.word()`), не шаблон.

### Р3. Одна Реплика на учителя — частичный уникальный индекс

`create unique index … on assistant_turn (user_id) where state =
'RUNNING'`: вторая вставка «работаю» того же учителя отклоняется базой,
сервис переводит нарушение в отказ «Помощник ещё отвечает на прошлую
реплику». Строка заводится **до** запуска процесса — так гонка двух
запросов решается в одном месте. Карта идущих процессов в памяти
(`RunningTurns`) нужна для «Остановить» и для остановки при выключении,
а не для запрета: запрет в памяти не пережил бы двух запросов
в разных потоках без собственной блокировки.

### Р4. Команда процесса и клетка

```
<locus.agent.command> -p --output-format stream-json --verbose
    --max-turns <N> --tools "" --allowedTools "mcp__locus__*"
    [--resume <сеанс>]
```

- запрос учителя — **на стандартный ввод**, а не аргументом: аргумент
  виден в списке процессов любому пользователю стенда и ограничен
  длиной командной строки;
- `--tools ""` отключает встроенные инструменты (файлы, оболочка,
  сеть) — в клетке остаются только инструменты MCP; `--allowedTools`
  и разрешения `.claude/settings.json` рабочего места пропускают
  только `mcp__locus__*` (ADR-0057);
- рабочий каталог процесса — рабочее место учителя; сервер `locus`
  приходит из его `.mcp.json` (свойство, проверенное `agent-spike`).

**Отвергнуто** `--mcp-config … --strict-mcp-config`: подстановку
переменных в этом пути `agent-spike` не проверял, а путь рабочего
места проверен. Что `--tools ""` не прячет инструменты MCP, сверяется
живым запуском на заглушке спайка в задачах (п. 4.6), до закрепления.

**Проверено на версии 2.1.310** (рабочая машина владельца; на стенде
спайком измерена 2.1.309) живым запуском ровно этой команды
из развёрнутого `agent/`, с белым списком окружения, отдельным
`CLAUDE_CONFIG_DIR` и входом по подписке, на заглушке спайка под
именем сервера `locus`:

- `--tools ""` прячет только встроенные: в `tools` строки `init`
  ровно четыре `mcp__locus__*` заглушки, модель вызвала
  `mcp__locus__whoami` и получила ответ, прочитать файл ей нечем;
- `.mcp.json` рабочего места подставил `${LOCUS_MCP_URL}`
  и `${LOCUS_TURN_TOKEN}` — заглушка приняла токен;
- серверы MCP из настроек пользователя не пришли — их отсекает
  отдельный каталог настроек;
- **пришёл коннектор claude.ai** (`"source": "claudeai"`): со входом
  по подписке Claude Code подключает серверы учётной записи claude.ai
  мимо `.mcp.json` и каталога настроек. Клетка их выключает
  переменной `ENABLE_CLAUDEAI_MCP_SERVERS=false` в окружении процесса
  (Р5) — с ней в `mcp_servers` только `locus`;
- `permissions.allow` из `.claude/settings.json` рабочего места
  Claude Code **не применяет**: рабочее место не помечено доверенным
  («this workspace has not been trusted»), о чём он пишет в stderr.
  Разрешение несёт флаг `--allowedTools`; `enableAllProjectMcpServers`
  при этом действует. Отметку доверия в каталог настроек Локус
  не пишет: флаг даёт то же, а разрешения файла остаются вторым,
  проверяемым тестом (`AgentSkillsNameRegisteredToolsTest`) описанием
  клетки, которое заработает, если Claude Code начнёт его применять;
- `--resume <сеанс>` в той же клетке возобновляет сеанс, сеанс
  хранится в `CLAUDE_CONFIG_DIR/projects/<рабочий каталог>`.

### Р5. Окружение процесса — белый список

Процесс получает не окружение Локуса целиком, а: `PATH`, `HOME`,
`LANG`, `LC_ALL`, `TMPDIR` (какие есть), ключ, `CLAUDE_CONFIG_DIR`
учителя, `LOCUS_MCP_URL`, `LOCUS_TURN_TOKEN` и выключатель коннекторов
claude.ai `ENABLE_CLAUDEAI_MCP_SERVERS=false` (добавлен по сверке Р4). **Почему:** в окружении
Локуса лежат секреты объектного хранилища и базы (ADR-0051), процессу
в клетке они не нужны; заодно в окружение не попадает `CLAUDECODE`,
из-за которого вложенный запуск отклоняется.

### Р6. Ключ — ключ API или токен подписки

**Под вопросом:** ADR-0054 говорит «по ключу API владельца», а у владельца
сейчас подписка. **Варианты:** (а) требовать только `ANTHROPIC_API_KEY`;
(б) годится любая из двух переменных — `ANTHROPIC_API_KEY` или
`CLAUDE_CODE_OAUTH_TOKEN`. **Выбрано (б):** суть решения ADR-0054 —
учётные данные владельца в окружении Локуса, не в файлах рабочего
места; какого они вида — эксплуатация ([ADR-0051](../../context/adr/0051-ekspluataciya-stenda-vne-repozitoriya.md)).
Вариант (а) оставил бы Помощника недоступным на стенде владельца.
Нет ни одной — Помощник недоступен с причиной, называющей обе.
Стоимость показывается по `total_cost_usd` в обоих случаях: при
подписке это расчёт по прайс-листу, как в записке спайка.

### Р7. Рабочее место разворачивается на каждую Реплику

`agent/` из корня репозитория входит в сборку ресурсом
`classpath:agent/**` (Maven `<resource>` с `targetPath`). Перед каждой
Репликой Локус очищает `<workspaces>/<id учителя>/work/` и копирует туда
ресурсы; каталог настроек — `<workspaces>/<id учителя>/config/`,
его Локус не трогает (там сеансы Claude Code). **Почему на каждую
Реплику, а не при старте:** учителей заводят без перезапуска, а
копирование десятка мелких файлов ничего не стоит; путь `work/`
не меняется, так что сеанс возобновляется (Claude Code хранит сеансы
по рабочему каталогу). Очистка перед копированием убирает файлы,
удалённые из `agent/` новой версией.

**Тестовые ресурсы — не под `agent/`.** **Под вопросом:** задачи 3.2
и 3.3 клали заготовки `stream-json` и двойник команды в
`src/test/resources/agent/`. **Варианты:** (а) так и оставить и искать
рабочее место по файлу-метке; (б) увести тестовые ресурсы в
`src/test/resources/assistant/`. **Выбрано (б):** в тестах
`target/test-classes` стоит в пути классов раньше `target/classes`,
и `classpath:agent/` указал бы на заготовки, а не на рабочее место —
`AgentWorkspaces` скопировал бы учителю двойник вместо правил. Метка
чинила бы симптом, а пересечение имён осталось бы ловушкой.

### Р8. Разбор `stream-json` — чистая функция строки

`StreamEvent.parse(String)` разбирает одну строку в одно из: `Init`
(сеанс), `ToolCall` (имя, аргументы JSON, обрезанные до 500 знаков),
`Result` (вид, признак ошибки, текст, стоимость, токены входа — сумма
`input_tokens`, `cache_creation_input_tokens` и `cache_read_input_tokens`,
токены выхода, ходы) либо `Other`; неразбираемая строка — `Other`.
Сеанс пишется в Разговор по `Init`, строка хода — в базу сразу по
вызову: `assistant-chat` покажет ход, пока Реплика идёт. Исход:

| что произошло | состояние | причина |
| --- | --- | --- |
| `result`, `success`, не ошибка | готово | — |
| `result`, `error_max_turns` | прервано по шагам | предел ходов N |
| другой `result` с ошибкой | не удалось | текст итога или вид |
| процесс вышел без `result` | не удалось | код выхода и хвост stderr |
| процесс не запустился | не удалось | текст отказа ОС |
| истёк предел времени | прервано по времени | предел T |
| учитель остановил | остановлено | — |

Токены и стоимость записываются при любом пришедшем `result`.
Неразбираемые строки не теряются молча: если итога нет, причина
«не удалось» называет хвост stderr.

**Уточнено при реализации (раздел 3 задач).**

- **Вызовы — списком.** Под вопросом: одна строка `assistant` — один
  вызов или несколько. Варианты: (а) `ToolCall` на строку, лишние
  блоки отбрасывать; (б) `ToolCalls` со списком `ToolCall`. Выбрано (б):
  Claude Code 2.1.310 пишет блоки сообщения по одному в строке (снято
  живьём: `thinking` и `tool_use` одного сообщения — две строки), но
  формат сообщения допускает несколько `tool_use`, и молча потерянная
  строка хода хуже лишнего уровня записи.
- **Текст ошибки итога.** У `error_max_turns` поля `result` нет, текст —
  в списке `errors` (`"Reached maximum number of turns (1)"`); `Result.text`
  берёт `result`, иначе `errors` через «; ».
- **Стоимость — как записал процесс.** `total_cost_usd` приходит
  с двоичным хвостом (`0.0014156400000000001`); разбор отдаёт
  `BigDecimal` этого текста, до шести знаков округляет колонка
  `NUMERIC(12, 6)`.
- **Разбор — `JsonMapper.shared()`**, а не бин приложения: `parse` —
  чистая статическая функция строки, настройки бина (имена полей
  и прочее) ей не нужны; библиотека та же, Jackson 3 приложения.
- **Двойник зовётся из рабочего дерева.** Копия ресурса
  в `target/test-classes` теряет признак исполняемого файла, поэтому
  тестовая команда — `src/test/resources/assistant/claude-double`
  (тесты идут из корня проекта), а заготовки двойник находит рядом
  с собой. Заготовки `stream/` сняты живым вызовом на заглушке спайка
  с `--strict-mcp-config`; у `init` обнулены списки окружения снявшего
  (навыки, плагины, каталоги).
- **Для п. 4.6 замечено:** без `--strict-mcp-config` в `tools` строки
  `init` пришли серверы MCP из настроек пользователя и подключения
  claude.ai — клетку держит отдельный `CLAUDE_CONFIG_DIR` учителя
  (Р7); сверка 4.6 должна это подтвердить, а не предполагать.

### Р9. Потоки: Реплика — виртуальный поток, предел — `waitFor`

`AssistantService.startTurn` проверяет доступность, заводит строку
и отдаёт исполнителю; HTTP-запрос не ждёт. Исполнитель на виртуальном
потоке разворачивает рабочее место, выпускает токен (срок — предел
времени и минута запаса), запускает процесс, пишет запрос в stdin
и закрывает его; stdout читает второй виртуальный поток, stderr —
третий (хвост 2 КБ). Основной ждёт `process.waitFor(предел)`; не
дождался — `destroy()` (SIGTERM, проверен спайком), через 10 с —
`destroyForcibly()`. Конечное состояние пишется одним условным
обновлением `… where state = 'RUNNING'`, токен отзывается в `finally`.
«Остановить» ставит в `RunningTurns` отметку и убивает процесс;
исход определяет тот же основной поток. При выключении Локуса
(`@PreDestroy`) идущие процессы убиваются, строки остаются «работаю»
и при следующем старте помечаются прерванными перезапуском.

### Р10. Доступность — один раз при старте

`ApplicationRunner` сначала помечает прерванные (Р3, уборка), затем
считает `AssistantAvailability`: команда задана и отвечает на `--version`
за 10 с; первое слово ответа равно `locus.agent.version`; ключ есть
в окружении (Р6). Итог — «доступен» или «недоступен: причина»; Локус
при любом итоге поднимается. Повторно не проверяется: версия Claude
Code меняется установкой, а установка — с остановкой стенда (ADR-0024).
Окружение читается через бин `AgentEnvironment` (по умолчанию
`System.getenv()`), чтобы тесты подставляли ключ, не трогая окружение
сборки.

### Р11. Страница `/assistant` — только доступность

Учитель и Администратор видят «Помощник доступен» (закреплённая версия)
либо «Помощник недоступен: причина». Пункта в шапке нет: без разговора
на странице нечего делать, пункт добавит `assistant-chat`. Признак
готовности карточки — «без команды страница называет причину» —
проверяется на ней.

### Р12. Навыки называют инструменты полным именем

В `agent/` инструмент пишется так, как его видит модель:
`mcp__locus__<имя>`. Сторожевой тест читает все файлы `agent/`
из рабочего дерева, находит такие имена и сверяет с `ToolRegistry.names()`;
имя `mcp__locus__*` в разрешениях — шаблон, не инструмент. **Почему
полным именем:** короткое `list_topics` в обратных кавычках неотличимо
от любого другого идентификатора, и тест либо пропускал бы выдумку,
либо падал на постороннем слове.

### Р13. Настройки `locus.agent`

| ключ | умолчание | смысл |
| --- | --- | --- |
| `command` | `claude` | путь к команде |
| `version` | `2.1.309` | закреплённая версия (проверена спайком) |
| `workspaces` | `./.locus-agent` | корень рабочих мест учителей |
| `mcp-url` | пусто — `http://127.0.0.1:<порт Локуса>/mcp` | адрес сервера MCP для процесса (см. «Уточнено при реализации») |
| `time-limit` | `180s` | предел времени Реплики |
| `max-turns` | `10` | предел ходов Реплики |

Запрос учителя — непустой и не длиннее 20 000 знаков.

**Уточнено при реализации (раздел 4 задач).**

- **Адрес сервера MCP по умолчанию пуст.** Под вопросом: умолчание
  `http://127.0.0.1:${server.port:8080}/mcp` связывается при создании
  бина, до подъёма веб-сервера, и в тестах со случайным портом дало бы
  `0`. Варианты: (а) подставлять порт в тестах настройкой; (б) пустое
  значение значит «сервер этого же приложения», порт берётся
  в момент Реплики из `local.server.port`. Выбрано (б): то же поведение
  на стенде и в тестах, а заданный адрес по-прежнему главнее.
- **Путь команды с каталогом — от каталога Локуса.** `ProcessBuilder`
  с рабочим каталогом ищет относительный путь от него, то есть
  от рабочего места учителя. `AgentProperties.executable()` делает
  такой путь абсолютным; имя без каталога ищется по `PATH`.
- **«Команда не найдена» — проверкой файла до запуска**, а не разбором
  текста отказа ОС: текст отказа зависит от языка системы
  («Нет такого файла или каталога») и версии Java.
- **Права — у учителя и у Администратора.** Под вопросом: личный
  контур обычно под `hasRole('TEACHER')`, а Р11 открывает страницу
  обоим, и Задачи через Помощника заводит Администратор. Выбрано
  `hasAnyRole('TEACHER', 'ADMINISTRATOR')` на методах `AssistantService`:
  Разговоры у любого вошедшего свои, а что можно сделать инструментом,
  решают методы сервисов за инструментами (ADR-0056).
- **Заведение Разговора и Реплики — одной транзакцией,** запуск
  процесса — после фиксации (`TransactionTemplate`): отказ «Помощник
  ещё отвечает» не оставляет пустого Разговора, а исполнитель видит
  строку, которую обновляет.
- **Выключение Локуса** ставит в `RunningTurns` отметку, и исполнитель
  исход не пишет: строку пометит уборка при следующем старте (Р9).
- **Запись двойника — разом** (во временный файл и `mv`): тест читает
  её, пока процесс ещё идёт, и мог бы прочитать недописанный токен.
  Папку рабочих мест тестов (`target/test-agent-workspaces`)
  `TurnRunnerTest` очищает перед собой: база у прогона чистая,
  идентификаторы учителей повторяются, и запись прошлого прогона
  выдавала себя за свежую.

## Risks / Trade-offs

- [Формат `stream-json` и флаги чужие и меняются] → версия закреплена
  и сверяется при старте; двойник печатает строки, снятые с настоящего
  вывода; расхождение версии делает Помощника недоступным, а не тихо
  ломает разбор.
- [`--tools ""` в закреплённой версии может прятать и инструменты MCP]
  → живая сверка на заглушке спайка до закрытия задач (п. 4.6);
  не прошла — клетка строится `--disallowedTools` списком встроенных.
- [Процесс Claude Code переживает Локус при аварийном падении JVM] →
  срок токена — предел времени и минута: осиротевший процесс после
  срока ничего в Локусе не сделает; строка помечается при старте.
- [Подписка вместо ключа API — лимиты подписки общие с владельцем] →
  эксплуатация владельца; Локус показывает причину отказа модели
  текстом итога.
- [Хвост stderr может нести служебные подробности] → это личная запись
  учителя о его же Реплике; секретов в stderr Claude Code не печатает,
  токен Реплики передаётся окружением, не аргументом.

## Migration Plan

Новая миграция с тремя таблицами; данных переносить нечего. Оператор
стенда для работы Помощника ставит Claude Code закреплённой версии,
кладёт `ANTHROPIC_API_KEY` или `CLAUDE_CODE_OAUTH_TOKEN` в окружение
Локуса и при желании задаёт `locus.agent.workspaces`. Без этого Локус
работает, Помощник недоступен с причиной. Отката нет (ADR-0023).
