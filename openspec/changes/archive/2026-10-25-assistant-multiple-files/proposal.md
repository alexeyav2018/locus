# Proposal

## Why

Сеанс учителя 25.10.2026: к запросу Помощнику прикладывается только один
файл (`assistant/page.html:99`, `AssistantController.java:84`). Лист часто
снят несколькими кадрами — условия на одном, решения на другом, задача
перешла на вторую страницу, — и сейчас это несколько Реплик подряд,
а Помощник не знает, что файлы — один лист. Снимок экрана нельзя вставить
из буфера обмена — его приходится сначала сохранять файлом.

## What Changes

- На странице Помощника у Администратора — четыре поля «Файл 1» …
  «Файл 4», в каждом один файл. Номер файла — номер поля: пустое поле
  пропускается, номера остальных не сдвигаются.
- Каждый файл становится своим Черновиком сборки, к запросу дописываются
  строки в порядке полей: «Файл 1: загружен черновик сборки 57
  «IMG_0412.jpeg», страниц: 1.». Строка об одном файле тоже несёт номер
  поля — прежней «Загружен черновик сборки N …» больше нет.
- Хоть один файл не подошёл — отклоняется весь запрос, и ни одного
  Черновика сборки не заводится; отказ называет поле: «Файл 2: …».
- Запрос сверх предела контейнера (110 МБ на все файлы, 100 МБ на один)
  отклоняется на той же странице и в том же Разговоре словами о пределе,
  а не безликой страницей ошибки.
- Вставка картинки из буфера обмена (Ctrl+V) на странице Помощника
  кладёт её в первое пустое поле с именем «Вставка N.png», где N — номер
  поля; все поля заняты — вставка не проходит, и страница говорит об этом.
  Точечный скрипт из `locus.js`; без скрипта — выбор файла кнопкой.
- Навык разбора листа (`agent/.claude/skills/problem-intake/SKILL.md`):
  файл называется номером («первый», «файл 3») или именем — целиком или
  узнаваемой частью; имя, подходящее к нескольким файлам или ни к одному, —
  вопрос учителю. Файлы одного запроса — один лист, задачи нумеруются
  сквозь файлы в порядке номеров; предел страниц за Реплику общий.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `assistant-chat`: требование «Файл в реплике становится Черновиком
  сборки» — до четырёх нумерованных файлов, всё или ничего, отказ
  по номеру поля и по пределу размера; новое требование о вставке
  картинки из буфера обмена.

## Версия

`MINOR` — 3.14.1 → 3.15.0: есть дельта спек, изменение не крупное
и не ломающее (standards.md, раздел «Версии»).

## Impact

- **Граница общего и личного.** Файлы ложатся Черновиками сборки — личные
  у загрузившего, принимает их только Администратор, как сейчас
  (`TurnAttachments`, `AssemblyDraftService.upload` под
  `hasRole('ADMINISTRATOR')`). Реплика и Разговор — личные. Фильтры
  по владельцу не меняются, новых методов репозиториев без `UserId` нет.
- Журнал решений: новых записей нет. Порядок полей выбран в карточке
  бэклога решением владельца; вставка — точечный скрипт из одного файла,
  страница работает и без него (ADR-0041); предел загрузки — прежний
  двухуровневый (ADR-0044).
- Код: `AssistantController` (четыре поля, отказ по пределу),
  `AssistantService.startTurn` (список файлов), `TurnAttachment`
  (номер поля), `TurnAttachments` (список, всё или ничего),
  `AssemblyDraftAttachments` и `AssemblyDraftService` (приём нескольких
  исходников разом), шаблон `assistant/page.html`, `static/js/locus.js`,
  `static/css/locus.css`; навык `problem-intake`.
- Зависимостей и схемы БД не трогает.
- Признак готовности, кроме тестов, — сеанс учителя (как у `intake-skill`):
  строка бэклога после архивации ждёт условия.
