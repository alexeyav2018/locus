# Proposal

## Why

Отзыв учителя 06.11.2026: запрос к Помощнику отклоняется «Помощник
недоступен», хотя команда Claude Code на стенде исправна. Доступность
проверяется один раз при старте (`AgentStartup.java:47-49`), итог лежит
в поле `AssistantService` (`AssistantService.java:44`) и больше не меняется.
Одна неудачная проверка — на стенде 05.11.2026 команда не ответила
на `--version` за 10 с, пока сервер был занят перезапуском после
автообновления — выключила Помощника больше чем на сутки, и восстановить
его мог только перезапуск службы.

Элемент бэклога `assistant-availability-recheck`, верхний доступный.

## What Changes

- **Недоступный Помощник перепроверяется при обращении.** Пока Помощник
  недоступен, команду проверяют заново при открытии страницы `/assistant`
  и при запросе Реплики; первое же обращение после сбоя возвращает
  Помощника без перезапуска Локуса.
- **Доступный не перепроверяется.** Исправный Помощник при обращениях
  команду не запускает.
- **Проверка одна на всех.** Пока одна идёт, другое обращение её не ждёт
  и получает прежний итог.
- Фоновой проверки нет: проверяет только обращение учителя (ADR-0014,
  ADR-0054). Предел ответа на `--version` остаётся 10 с.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `assistant-turns`: доступность проверяется не только при старте — пока
  Помощник недоступен, проверка повторяется при обращении к нему.

## Версия

MINOR — 3.19.0: есть дельта спек, изменение не крупное и не ломает.

Строка журнала: `assistant-availability-recheck` — недоступный Помощник
проверяется заново при открытии страницы и при запросе и возвращается
сам, без перезапуска Локуса.

## Impact

- Код: новый `AvailabilityCheck` в `ru.locus.assistant`; `AgentStartup`,
  `AssistantService`, `AssistantController`, комментарий
  `AssistantAvailability`.
- Документы: `openspec/context/architecture.md`, раздел об исполнителе
  Реплики («считается один раз при старте»). `CLAUDE.md` пересказа этой
  проверки как «один раз» не содержит — только сводку изменения.
- Журнал решений: новых записей нет. ADR-0054 требует недоступности
  с названной причиной и запрещает фоновое; однократность проверки
  решена не там, а в `design.md` изменения `agent-runner`, Р10.
- Схема базы, данные, настройки не меняются.
