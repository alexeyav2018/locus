## 3. Углубление Темы с Темой-приёмником

- [x] 3.1 Заменить в `TaxonomyService.create` безусловный
      `refuseIfDeepeningLosesContent` на условный: перегрузка
      `create(String name, TaxonomyNodeId parent, TaxonomyNodeId receiver)`,
      где `receiver` — Тема-приёмник. Если у родителя есть содержимое,
      требующее Темы, а `receiver` не указан — прежний отказ
      `TopicCarriesContentException` с новым текстом «нужно указать
      Тему-приёмник». Прежняя двухаргументная `create` остаётся и зовёт
      новую с `null`. Проверка: `TaxonomyServiceTest` — потомок у Темы
      с Задачами без приёмника отклоняется, у Темы без Задач создаётся
      по-прежнему.
- [x] 3.2 Ввести проверку приёмника по состоянию дерева **после** операции
      (design.md, «Проверка „приёмник — Тема“»): законен создаваемый потомок
      (обозначается отдельным значением, а не идентификатором — его ещё нет)
      и любой существующий узел без потомков, кроме углубляемой Темы.
      Отказ — своим исключением с внятным текстом. Проверка:
      `TaxonomyServiceTest` — приёмником указана сама углубляемая Тема:
      отказ, потомок не создан; приёмником указан Раздел: отказ.
- [x] 3.3 Выполнить переезд в одной транзакции с созданием потомка: создать
      узел, затем позвать `moveTopicContent(углубляемая, приёмник)` у каждой
      реализации `NodeContent`. Порядок именно такой — приёмником может быть
      только что созданный узел. Проверка: `TaxonomyServiceTest` — после
      углубления все Задачи прежней Темы размечены приёмником, прежняя Тема
      Задач не несёт и её вид — Раздел; при отказе на любом шаге узел
      не создан и разметка не тронута.

      Сделано: приёмник — тип `TopicReceiver` (`CREATED_CHILD` либо
      `existing(id)`), отказ по приёмнику — `ReceiverIsNotATopicException`.
      Проверки с Задачами живут не в `TaxonomyServiceTest`, а в
      `ProblemsGuardTheTreeTest`: тесты пакета `taxonomy` о Задачах не знают
      по тому же правилу, что и сам сервис. В `TaxonomyServiceTest` — только
      чистые проверки приёмника на пустой Теме: приёмник проверяется всегда,
      когда указан, а не только при наличии содержимого.
- [x] 3.4 Тест `TaxonomyKnowsNothingOfProblemsTest` дополнить: в исходниках
      `TaxonomyService` не встречается ни `ProblemService`, ни `problem_topic`
      — переезд идёт только через `NodeContent`. Проверка: тест зелёный.

- [x] 4.4 Тест целостности: при отказе внутри `deleteWithDistribution` —
      узел на месте и разметка Задач прежняя (транзакция откатилась целиком).
      Проверка: новый случай в `TaxonomyServiceTest` на Testcontainers.

      Сделано иначе, чем записано в 4.2, и вот почему. Сигнатура
      `deleteWithDistribution(…, Map<ProblemId, TaxonomyNodeId>)` невозможна:
      `ProblemId` живёт в `ru.locus.problem`, а сторожевой тест этого же
      изменения (`TaxonomyKnowsNothingOfProblemsTest`) запрещает
      `TaxonomyService` упоминать этот пакет хоть строкой. Распределение идёт
      тем же путём, что и переезд, — через `NodeContent`, новым действием

      в типе `TopicDistribution` пакета дерева, у которого дерево читает
      только `receivers()`, а область Задач узнаёт в нём свою запись
      `ProblemDistribution` (design.md, «Распределение пересекает границу,
      не называя Задачу»). Приёмники проверяются буквально по состоянию

      на откате транзакции — и потому тест целостности 4.4 проверяет
      настоящий откат, а не отказ до первой правки. Проверки с Задачами
      и с материалами живут в `ProblemsGuardTheTreeTest`
      и `TheoryGuardsTheTreeTest` по правилу раздела 3; в
      `TaxonomyServiceTest` — только чистые проверки приёмника
      (родитель как единственный оставшийся лист; родитель, у которого
      останется брат; сама снимаемая Тема) и нулевой счёт отметок.
