# Proposal

## Why

Элемент бэклога `method-edit-impact` и ADR-0011, раздел «Последствия», фиксируют
риск: правка разметки Задачи задним числом может снять с неё Метод и оставить
ячейку Владения «Тема × Метод» без единой Задачи, при том что на ней уже стоят
отметки. На момент постановки этой карточки (сентябрь 2026, до `assignments`,
`submission-review` и `mastery-marks`) решения для этого случая не было.

Сегодня, когда все три возможности построены, риск оказался закрыт побочным
эффектом двух принятых решений, не рассчитанных специально на этот случай:

- [ADR-0030](../../context/adr/0030-zadacha-zamorazhivaetsya-posle-vydachi.md) —
  Задача, вошедшая хотя бы в одно Задание, не правится рукой вовсе, пока такие
  Задания существуют (`ProblemService.refuseUnlessUnused`,
  `problem-catalog` требование 8);
- [ADR-0037](../../context/adr/0037-zadanie-neizmenno-posle-vydachi.md) —
  Задание с Работой не удаляется.

Отметка Владения ставится только с экрана приёма Работы
(`MasteryController.mark`), а Работа существует только по паре «Задание ×
Задача». Значит, если на паре «Тема × Метод» уже стоит хоть одна отметка, её
Задача обязательно входит в неудаляемое Задание — и поэтому заморожена
навсегда. Снять с неё Метод, оставив ячейку без Задач, невозможно: правка
такой Задачи отклоняется целиком, ещё до разбора состава разметки.

Половина карточки про словарь уже закрыта раньше: `mastery-marks` не даёт
удалить Метод из словаря, пока на нём есть отметки (`MasteryOfMethod`,
`MasteryGuardsTheMethodTest`).

Открытый вопрос ADR-0011 отвечен без нового решения. Изменение фиксирует это
регрессионным тестом на стыке `problem-catalog` и `mastery-marks` — том месте,
где сходятся заморозка и отметка, — и закрывает карточку бэклога.

## What Changes

- Интеграционный тест, показывающий сквозной сценарий: Задача выдана Ученику,
  Работа принята, отметка Владения поставлена на паре «Тема × Метод» этой
  Задачи — попытка снять с Задачи этот Метод (`ProblemService.edit`)
  отклоняется `ProblemInUseException`, отметка и ячейка остаются на месте.
- Карточка `method-edit-impact` в `openspec/backlog.md` помечается ✅ со
  ссылкой на этот change и кратким объяснением, чем закрыта.
- Код не меняется: поведение уже реализовано `problem-catalog`
  (заморозка, ADR-0030) и `assignments` (неудаляемость Задания с Работой,
  ADR-0037). Требование специфицировано ранее в `problem-catalog`, требование 8.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет: поведение системы не меняется, только фиксируется регрессионным тестом.
Требование «Задача не правится, пока использована» уже описано в
`problem-catalog`, требование 8. `skip_specs: true`.

## Impact

- Новый тестовый класс на стыке `ru.locus.problem` и `ru.locus.mastery`
  (модуль `submission-review`/`assignments`/`mastery-marks` для фикстур).
- `openspec/backlog.md` — статус строки 18.
- Продуктового кода изменение не затрагивает.
