# Spec Delta

## ADDED Requirements

### Requirement: Главное на виду, вторичное — по кнопке на той же странице

Система SHALL показывать на экране данные и частые действия, а вторичное —
переименование, перенос, удаление, замену файлов, заведение записей на
экранах-списках и необязательные поля — скрывать под блоками, раскрываемыми
кнопкой на той же странице, без перехода и без перезагрузки. Раскрытие блока
MUST NOT давать или отнимать права: блок с действием, недоступным роли, на
странице отсутствует вовсе, как и до этого требования. Соседние блоки
действий одного экрана SHOULD раскрываться по одному.

Когда сервис отклоняет действие, страница MUST показываться с раскрытым блоком
именно этого действия и с сообщением об отказе: введённое не теряется,
искать форму не нужно.

#### Scenario: Правка не мешает чтению

- **WHEN** Учитель открывает карточку своего Ученика
- **THEN** на виду имя, состояние, Группы и переходы к Заданиям, Работам
  и Владению
- **AND** переименование, выбытие и удаление свёрнуты и раскрываются кнопкой

#### Scenario: Блок раскрывается на месте

- **WHEN** пользователь нажимает кнопку блока «Переименовать»
- **THEN** на той же странице открывается форма переименования
- **AND** открытие другого блока действий закрывает этот

#### Scenario: Отказ раскрывает нужный блок

- **WHEN** Администратор переименовывает узел рубрикатора в занятое имя
- **THEN** страница показывает сообщение об отказе
- **AND** блок переименования раскрыт, введённое имя в нём сохранено, а остальные
  блоки свёрнуты

#### Scenario: Недоступное действие не появляется

- **WHEN** Учитель открывает экран, на котором Администратору доступно удаление
- **THEN** кнопки удаления на странице нет — ни раскрытой, ни свёрнутой

### Requirement: У каждой формы есть выход без браузера

Система SHALL предоставлять на каждой странице-форме кнопку «Отмена», ведущую
туда, откуда пришли (по правилу контекстного возврата), а в каждом раскрытом
блоке с формой — кнопку «Отмена», сворачивающую блок. Любой экран MUST
оставлять пользователю путь дальше кнопками и ссылками страницы (шапка,
возврат, переходы); возвращаться кнопкой браузера не должно быть нужно.

#### Scenario: Отмена создания Задачи

- **WHEN** Администратор открыл форму новой Задачи из рубрикатора и нажал «Отмена»
- **THEN** он оказывается на том узле рубрикатора, откуда пришёл

#### Scenario: Отмена в раскрытом блоке

- **WHEN** пользователь раскрыл блок с формой и нажал «Отмена»
- **THEN** блок сворачивается, ничего не сохраняется

### Requirement: Контекстный возврат

Переход из списка или поиска к карточке SHALL нести адрес исходной страницы
в параметре `from`, а ссылка «назад» карточки SHALL вести на него, а без него —
на раздел по умолчанию. Параметр `from` SHALL приниматься только как адрес
внутри системы: начинающийся с одного `/`, без схемы и без второго `/` или `\`
в начале, без управляющих символов и не длиннее установленного предела.
Любое другое значение MUST игнорироваться без ошибки, а ссылка вести на раздел
по умолчанию.

#### Scenario: Условия поиска не теряются

- **WHEN** Учитель находит Задачи по Методу и Части, открывает одну и нажимает
  «назад»
- **THEN** он снова на результатах поиска с теми же условиями

#### Scenario: Возврат без контекста

- **WHEN** Задача открыта по прямому адресу
- **THEN** «назад» ведёт на поиск Задач без условий

#### Scenario: Чужой адрес не принимается

- **WHEN** адрес карточки открыт с параметром `from`, указывающим на другой
  сайт, на `//другой-сайт`, на `javascript:` или содержащим перевод строки
- **THEN** страница открывается как обычно
- **AND** «назад» ведёт на раздел по умолчанию, а не на указанный адрес

### Requirement: Страницы ошибок ведут дальше

Система SHALL показывать при отсутствии страницы (404), отказе в доступе (403)
и внутренней ошибке (500) собственную страницу на русском языке с общей шапкой
вошедшего и кнопками «Назад» (по правилу возврата) и «На главную». Страница
MUST NOT раскрывать трассировку, имена классов и внутренние сообщения.

#### Scenario: Несуществующий адрес

- **WHEN** вошедший открывает адрес, которого нет
- **THEN** он видит страницу «Страница не найдена» с шапкой и кнопкой «На главную»

#### Scenario: Нет доступа

- **WHEN** Учитель открывает по прямому адресу экран Администратора
- **THEN** он видит страницу «Нет доступа» с кнопкой «На главную»
- **AND** содержимого экрана Администратора на ней нет

#### Scenario: Посетитель без входа

- **WHEN** посетитель без входа получает ошибку
- **THEN** страница ошибки показывается без шапки разделов

### Requirement: Файлы просматриваются внутри системы

Система SHALL открывать PDF условия и решения Задачи, файл теоретического
материала и файлы Работ на странице просмотра с общей шапкой и кнопкой «Назад»
(по правилу возврата). Изображения SHALL показываться на странице картинкой;
PDF — встроенным просмотром с запасной кнопкой «Открыть PDF» для браузеров,
которые встроенный просмотр не показывают. Страница просмотра MUST выдавать
файл по тем же правилам доступа, что и сегодня: файлы Работ — только владельцу
Работы, остальные — вошедшим, и ссылка на файл остаётся временной подписанной
([ADR-0021](../../../../context/adr/0021-hranilishche-fajlov.md)). Внешняя
ссылка теоретического материала не просматривается внутри системы.

#### Scenario: Снимок решения

- **WHEN** Учитель на экране приёма нажимает на файл Работы
- **THEN** открывается страница просмотра со снимком и кнопкой «Назад»
- **AND** «Назад» возвращает на экран приёма

#### Scenario: PDF решения Задачи

- **WHEN** пользователь открывает PDF решения Задачи
- **THEN** он видит страницу просмотра с PDF, кнопкой «Назад» и кнопкой «Открыть PDF»

#### Scenario: Чужой файл Работы

- **WHEN** Учитель открывает адрес просмотра файла Работы, принадлежащей другому Учителю
- **THEN** ему отвечают так же, как на несуществующий файл: просмотра нет

### Requirement: Выход из системы доступен из шапки

Система SHALL предоставлять кнопку «Выйти» в общей шапке каждого экрана
вошедшего.

#### Scenario: Выход с любого экрана

- **WHEN** вошедший нажимает «Выйти» на любом экране
- **THEN** сеанс завершается и показывается форма входа
