## Why

Отметки Владения ставятся (`mastery-marks`), но увидеть их можно только
по одной Задаче на экране приёма: никакого вида «что этот Ученик знает
и чего не знает» в системе нет, и разметка библиотеки Темами и Методами
по-прежнему не замыкает круг «выдал → принял → отметил → увидел пробелы →
выдал по ним» — а ради этого круга система и затевалась
(С4 «Подбор по пробелам», С6 [scenarios.md](../../context/scenarios.md);
веха 4 [strategy.md](../../context/strategy.md) — цель первой версии).
Все входы для этого уже есть: суждения читаются одной картой,
ячейки порождены разметкой, поиск по паре «Тема × Метод» принимает
её адресом и с самого начала строился под «второй вход — подбор по пробелам»
(`ProblemFilter`).

## What Changes

- Появляется **экран Владения Ученика** — `GET /mastery?student=`,
  только чтение: ни одной формы, ни одной ячейки для правки. Отметки
  по-прежнему ставятся только на экране приёма, точечно, в момент
  проверки ([ADR-0011](../../context/adr/0011-otmetka-na-pare.md),
  «Последствия»: таблица владения как форма — не нужна и вредна;
  как вид — это С6). Карточка Ученика ведёт на экран ссылкой, как ведёт
  на его Задания и Работы.
- На экране — три среза, и каждый — **распределение по четырём статусам**,
  а не одно значение ([ADR-0013](../../context/adr/0013-agregaciya-raspredelenie.md),
  инвариант 5):
  - **по Теме** — распределение её ячеек «Тема × Метод»;
  - **по Разделу** — распределение всех ячеек поддерева; показывается
    всё дерево целиком, у каждого узла — своё распределение;
  - **по Методу** — распределение по всем Темам, где Метод встречается.
- **Ячейки Темы** — пары «Тема × Метод», порождённые разметкой Задач
  (инвариант 4: не декартово произведение словарей), плюс пары
  с суждением этого Ученика, если такие вдруг остались без Задачи.
  Ячейка без суждения считается как `неизвестно` — это нормальное
  состояние, а не сигнал тревоги. `Неизвестно` и `не владеет` различаются
  везде ([ADR-0012](../../context/adr/0012-shkala-vladeniya.md)).
- **Перечень пробелов** — ячейки со статусом `не владеет`, напрямую,
  без агрегатов ([ADR-0013](../../context/adr/0013-agregaciya-raspredelenie.md),
  «Последствия»). Из каждого пробела открывается **поиск Задач по этой
  паре** — существующий `/problems` с узлом и Методом в адресе: это второй
  вход в тот же поиск, а не свой поиск. Дальше учитель отмечает найденное
  и выдаёт, как в С4.
- Никакого «единого значения владения» для Темы, Раздела или Метода
  не появляется ни в интерфейсе, ни в коде — только четыре числа; это
  сторожит тест.
- Экран личный: показывает только своего Ученика; чужой — неотличим
  от несуществующего, как всюду в личном контуре
  ([ADR-0027](../../context/adr/0027-mehanizm-granicy-obshchego-i-lichnogo.md)).
  Администратору экран недоступен — личного контура у него нет
  ([ADR-0005](../../context/adr/0005-roli-administrator-uchitel.md)).
- Новых решений изменение не принимает: всё уже решено ADR-0011,
  ADR-0012, ADR-0013 и ADR-0039; записей журнала не заводится.
- Не входит: протаскивание Ученика сквозь поиск в форму выдачи
  (карточка требует только «открывается поиск по паре»; Ученик
  выбирается на форме выдачи, как сейчас); подбор теории по пробелам
  (отложено, [strategy.md](../../context/strategy.md)); какие-либо
  сводки по нескольким Ученикам или по Группе.

**Достижение горизонта.** Закрытие этого элемента замыкает сквозной
проход и достигает горизонта редакции 1 стратегии
([strategy.md](../../context/strategy.md), «Горизонт», веха 4). Пересмотр
редакции — отдельное решение владельца через цикл изменений; здесь
только фиксируется, что условие сработало.

## Capabilities

### New Capabilities

- `mastery-views`: экран Владения Ученика — распределения по Теме,
  Разделу и Методу; перечень пробелов; переход из пробела в поиск Задач
  по паре; изоляция по владельцу; отсутствие единого значения владения.

### Modified Capabilities

Нет: поиск по библиотеке (`library-search`) уже принимает узел и Метод
адресом — новых требований к нему не появляется; карточка Ученика
(`students-groups`) получает ссылку, как получила её от `submission-review`,
и требование о ссылке живёт в новой спеке, а не в спеке Учеников.

## Impact

- Пакет `ru.locus.mastery`: `Distribution` (четыре числа),
  `MasteryOverview` и её части — вид Ученика; `MasteryService` получает
  операцию чтения по Ученику; `MasteryController` — `GET /mastery?student=`;
  новый шаблон `templates/mastery/student.html`.
- `ProblemRepository` получает вопрос библиотеки «какие пары
  «Тема × Метод» порождены разметкой» — без владельца, как всё
  в библиотеке.
- `templates/student/student.html`: ссылка «Владение Ученика».
- Схема базы не меняется: всё вычисляется в запросе.
- Тесты: распределения по Теме, Разделу, Методу; перечень пробелов
  и адрес перехода в поиск; изоляция по владельцу; отсутствие единого
  значения; доступ только Учителю; тонкий контроллер.
- Документы: `domain-model.md` (вычисляемое — построено), `glossary.md`
  (`Distribution` — построено), `CLAUDE.md` (статус, список
  возможностей), `openspec/backlog.md` (строка 17, карточка),
  `strategy.md` — не правится, но при архивации фиксируется достижение
  горизонта.
