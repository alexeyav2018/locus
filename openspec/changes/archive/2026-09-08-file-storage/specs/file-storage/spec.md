## Purpose

Хранение файлов системы: PDF задач и теории, сканы работ учеников. Описывает,
как файл попадает в хранилище, как он оттуда отдаётся наружу, как удаляется
и что происходит с изображениями при загрузке. Прикладного смысла для учителя
здесь нет — это условие, при котором Задаче есть где держать своё условие,
а Работе — свой скан.

## ADDED Requirements

### Requirement: Файл кладётся в хранилище и адресуется ключом

Система SHALL принимать файл на хранение и возвращать ключ, по которому этот
файл потом находится. Ключ выдаёт хранилище, а не тот, кто кладёт: так два
файла с одинаковым исходным именем не затирают друг друга, и никакое сочетание
имени и даты не позволяет угадать чужой ключ.

Содержимое возвращается тем же, каким было положено, — байт в байт, кроме
случая пережатия изображения, описанного отдельным требованием.

#### Scenario: Файл положен и прочитан

- **WHEN** файл кладётся в хранилище
- **THEN** возвращается ключ
- **AND** по этому ключу читается содержимое, совпадающее с положенным

#### Scenario: Два файла с одинаковым именем

- **WHEN** в хранилище кладутся два разных файла с одинаковым исходным именем
- **THEN** ключи различны
- **AND** по каждому ключу читается своё содержимое

#### Scenario: Обращение по несуществующему ключу

- **WHEN** запрашивается файл по ключу, которого в хранилище нет
- **THEN** файл не возвращается
- **AND** ответ не позволяет отличить «никогда не существовал» от «удалён»

### Requirement: Наружу файл отдаётся только по временной подписанной ссылке

Система SHALL отдавать файл исключительно по ссылке, которая подписана
и ограничена сроком. Постоянного адреса у файла нет ни в одном варианте
хранилища: ни зная ключ, ни перебирая ключи, получить содержимое без
действующей подписи невозможно.

Требование обязательно, а не желательно: PDF с решениями не должны попадать
к ученикам, а сканы работ — персональные данные детей
([ADR-0021](../../../context/adr/0021-hranilishche-fajlov.md)).

#### Scenario: Действующая ссылка

- **WHEN** запрашивается ссылка на существующий файл и по ней сразу же
  происходит обращение
- **THEN** возвращается содержимое файла

#### Scenario: Истёкшая ссылка

- **WHEN** обращение по ссылке происходит после того, как срок её действия
  вышел
- **THEN** содержимое не возвращается

#### Scenario: Обращение без подписи

- **WHEN** обращение идёт по адресу файла, из которого убрана подпись
- **THEN** содержимое не возвращается

#### Scenario: Подделанная подпись

- **WHEN** обращение идёт по адресу, в котором подпись или срок изменены
- **THEN** содержимое не возвращается

### Requirement: Файл удаляется из хранилища

Система SHALL удалять файл по ключу. После удаления содержимое недоступно
по любой ранее выданной ссылке, даже если срок её действия ещё не вышел.

Удаление уже отсутствующего файла MUST считаться выполненным, а не ошибкой:
повторный вызов после сбоя не должен требовать разбирательства, был ли файл
удалён в прошлый раз.

#### Scenario: Удаление существующего файла

- **WHEN** файл удаляется по своему ключу
- **THEN** по этому ключу он больше не читается

#### Scenario: Ранее выданная ссылка на удалённый файл

- **WHEN** файл удаляется, а затем происходит обращение по ссылке, выданной
  до удаления и ещё не истёкшей
- **THEN** содержимое не возвращается

#### Scenario: Повторное удаление

- **WHEN** удаление вызывается для ключа, которого в хранилище нет
- **THEN** операция считается выполненной
- **AND** ошибка не возникает

### Requirement: Изображение пережимается при загрузке

Система SHALL уменьшать изображение, попадающее в хранилище, до предела,
заданного настройкой, — снимки приходят с телефона многомегабайтными, а поток
измеряется сотнями в неделю. Изображение, уже укладывающееся в предел,
пережиматься не обязано.

Ориентация MUST сохраняться такой, какой её видел снимавший: снимок,
повёрнутый камерой, после пережатия не лежит на боку.

Пережатие применяется к изображениям и MUST NOT применяться к PDF: условие
и решение задачи хранятся ровно такими, какими их дал Администратор.

#### Scenario: Крупный снимок

- **WHEN** в хранилище кладётся изображение, превышающее заданный предел
- **THEN** сохранённое изображение меньше исходного по объёму
- **AND** его большая сторона не превышает предела

#### Scenario: Снимок, сделанный повёрнутой камерой

- **WHEN** в хранилище кладётся снимок, у которого ориентация задана
  не порядком пикселей, а сведениями о съёмке
- **THEN** сохранённое изображение показывается в той же ориентации, в какой
  его видел снимавший

#### Scenario: PDF

- **WHEN** в хранилище кладётся PDF
- **THEN** содержимое сохраняется байт в байт

### Requirement: Поведение не зависит от варианта хранилища

Система SHALL вести себя одинаково при любом варианте хранилища — объектном
для рабочей системы и файловом для разработки. Все требования выше выполняются
обоими: варианты различаются местом хранения и способом подписи, но не тем,
что видит вызывающая сторона.

Требование существует ради обратимости выбора поставщика
([ADR-0021](../../../context/adr/0021-hranilishche-fajlov.md)) и ради того,
чтобы проверка на одном варианте что-то говорила о другом.

#### Scenario: Один и тот же набор проверок

- **WHEN** проверки укладки, отдачи по ссылке, удаления и пережатия
  выполняются против объектного варианта хранилища, а затем против файлового
- **THEN** результат совпадает

### Requirement: Недоступность хранилища не останавливает систему

Система SHALL продолжать обслуживать всё, что не касается файлов, когда
хранилище не отвечает. Операция с файлом в этом случае MUST завершаться
явной ошибкой, а не пустым результатом: «файла нет» и «хранилище недоступно» —
разные события, и второе не должно выглядеть как первое.

Хранилище — единственная внешняя зависимость системы
([architecture.md](../../../context/architecture.md), «Внешние зависимости»),
и её отказ не обязан выглядеть как отказ системы.

#### Scenario: Хранилище не отвечает при укладке

- **WHEN** файл кладётся в хранилище, которое недоступно
- **THEN** операция завершается ошибкой
- **AND** причина отказа выведена в журнал приложения

#### Scenario: Хранилище не отвечает при чтении

- **WHEN** происходит обращение к файлу, а хранилище недоступно
- **THEN** отказ отличается от ответа «файла нет»

#### Scenario: Страницы, не касающиеся файлов

- **WHEN** хранилище недоступно
- **THEN** страницы, не обращающиеся к файлам, продолжают открываться
