## 1. Схема

- [x] 1.1 Завести миграцию `0002-taxonomy.yaml`: таблица `taxonomy_node`
  (`id` BIGINT autoincrement, `name` VARCHAR(200) NOT NULL, `parent_id` BIGINT
  nullable), внешний ключ `fk_taxonomy_node_parent` на себя **без**
  `ON DELETE CASCADE` — каскад удалял бы поддерево одним запросом, а это
  запрещено спекой. Проверка: `mvn test -Dtest=MigrationsOnStartupTest`
  проходит, таблица есть в чистой базе
- [x] 1.2 Добавить туда же уникальный индекс по `(parent_id, name)` —
  имя не повторяется среди братьев. Проверка: тест репозитория на отказ
  при повторе имени у одного родителя
- [x] 1.3 Добавить частичный индекс по `name` при `parent_id IS NULL` —
  уникальность имён среди корней. Обычный индекс их не покрывает: `NULL`
  не равен `NULL` (`design.md`, «Проверки целостности»). Changeset сырым SQL,
  отката у него нет — это ожидаемо (`standards.md`, «Данные»). Проверка: тест
  на отказ при создании второго корня с тем же именем

## 2. Узел, идентификатор, репозиторий

- [x] 2.1 Завести пакет `ru.locus.taxonomy` и в нём `TaxonomyNodeId` — record

  по образцу `ru.locus.user.UserId`. Проверка: модульный тест на отказ

- [x] 2.2 Завести `TaxonomyNode` — узел с идентификатором, именем,

- [x] 2.3 Реализовать `TaxonomyRepository` на `JdbcClient` по образцу

  на каждый метод
- [x] 2.4 Реализовать обход поддерева рекурсивным запросом (`WITH RECURSIVE`

  ошибку, а не висящий запрос. Проверка: сценарии «Поддерево на четырёх

- [x] 2.5 **Тест изоляции:** ни один метод `TaxonomyRepository` не принимает

  владельца туда некуда (ADR-0027, `antipatterns.md`, первый пункт). Проверка:
  тест отражением по сигнатурам методов репозитория, по образцу
  `OwnerIsUnknownToStorageTest`

## 3. Сервис и правила дерева

- [x] 3.1 Реализовать `TaxonomyService`: чтение дерева и поддерева — без
  аннотаций прав (вход уже потребован рубежом в `SecurityConfig`); создание,
  переименование, перемещение и удаление — под `@PreAuthorize("hasRole('ADMINISTRATOR')")`,
  как в `UserService`. Проверка: сценарии «Учитель читает дерево», «Учитель
  пытается изменить дерево», «Два учителя видят одно дерево»
- [x] 3.2 Реализовать создание узла: имя обязательно и не пустое после
  отсечения пробелов, родитель — существующий узел или отсутствует.
  Проверка: сценарии «Узел создан», «Пустое имя», «Имя повторяется среди
  братьев», «То же имя под другим родителем»
- [x] 3.3 Реализовать переименование. Проверка: сценарии «Узел переименован»,
  «Новое имя занято братом»
- [x] 3.4 Реализовать перемещение с запретом переезда узла в собственное
  поддерево и под самого себя — проверка тем же рекурсивным обходом
  (`design.md`). Проверка: сценарии «Узел перенесён с поддеревом», «Узел поднят
  в корень», «Перенос внутрь своего поддерева», «Перенос узла под самого себя»,
  «Имя занято у нового родителя»
- [x] 3.5 Реализовать удаление **одним** методом проверки пустоты узла —
  отдельным и названным так, чтобы будущие условия дописывались в одно место,
  а не по всем вызовам удаления (`design.md`, «Риски»). Сегодня единственное
  условие — отсутствие потомков. Проверка: сценарии «Пустой узел удалён»,
  «Удаление узла с потомками», «Родитель после удаления единственного потомка»
- [x] 3.6 Написать в javadoc этого метода перечисление трёх сущностей, при
  появлении которых условие обязано пополниться: Задачи и отметки Владения
  (на Теме), Теоретические материалы (на любом узле). Проверка: комментарий
  на месте и называет `problem-catalog`, `theory-materials`, `mastery-marks`
- [x] 3.7 Проверить, что вид узла нигде не хранится: в схеме нет колонки вида,
  в коде нет поля, которое пришлось бы обновлять при появлении потомка.
  Проверка: сценарии «Новый узел — Тема», «Тема становится Разделом при
  появлении потомка», «Раздел становится Темой, когда последний потомок ушёл»

## 4. Экран

- [x] 4.1 Добавить адрес рубрикатора в `ru.locus.Addresses` и реализовать
  `TaxonomyController` — тонкий: разбор запроса и выбор шаблона, ни предметной
  логики, ни проверок прав (`standards.md`, «Слои и границы»). Проверка: тест
  на то, что контроллер не обращается к репозиторию
- [x] 4.2 **Левая панель — только структура.** Шаблон дерева: имена узлов
  ссылками выбора (`?node=<id>`), вложенные `<ul>`, свёртка ветвей штатным
  `<details>`, потомки одного родителя по алфавиту. Никаких форм в дереве.
  Ни одной внешней библиотеки, ни строки JavaScript; две колонки — минимальным
  `<style>` в шаблоне (CSS не скрипт, ADR-0020 его не запрещает). Проверка:
  сценарии «Дерево видно целиком», «Братья по алфавиту»;
  `grep -rn "script" src/main/resources/templates` ничего не находит
- [x] 4.3 **Правая панель — действия над выбранным узлом.** Карточка узла
  (путь от корня, вид) и формы создания, переименования, перемещения (выбор
  нового родителя из списка, не перетаскивание) и удаления. Список выбора
  родителя — **один на страницу**. Каждая операция возвращает на
  `?node=<затронутый>#node-<id>`, удаление — на прежнего родителя. Проверка:
  сценарии «Действия относятся к выбранному узлу», «Возврат к выбранному узлу
  после операции»
- [x] 4.4 Скрыть формы правой панели от Пользователя без роли Администратора —
  условием «показать или нет», а не вычислением в шаблоне (`antipatterns.md`,
  «Логика в шаблонах Thymeleaf»). Карточка узла остаётся видна всем: путь
  от корня — то, чего в дереве не видно. Проверка: сценарий «Учителю операций
  не предлагают»
- [x] 4.5 Добавить пункт рубрикатора в навигацию. Проверка: со страницы после
  входа на дерево можно перейти ссылкой, тест переходит по ней `Browser`
- [x] 4.6 Выбор узла: параметр `node` в адресе экрана, подсветка выбранного
  в дереве, поведение при неуказанном узле и при узле, которого больше нет —
  дерево показывается, действий не предлагается, об исчезнувшем сообщается.
  Проверка: сценарии «Пока узел не выбран», «Выбран узел, которого больше нет»
- [x] 4.7 Тест: на странице ровно один список выбора родителя. До разделения
  панелей их было столько же, сколько узлов, — квадратичный рост разметки,
  и это вторая причина разделения (`design.md`). Проверка: тест считает
  `<select name="parentId">` и находит ровно один

Записи в журнале решений изменение **не заводит**: новых решений оно
не принимает, обоснование — в `proposal.md`. `glossary.md`, `domain-model.md`,

инварианты и сценарии рубрикатора там уже записаны, и изменение им следует,
а не меняет их.
