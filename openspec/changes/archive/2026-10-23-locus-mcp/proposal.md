# Proposal

## Why

Помощник редакции 3 ([ADR-0053](../../context/adr/0053-redakciya-3-strategii-pomoshchnik.md))
должен действовать в Локусе теми же глаголами, что и страницы, и под
личностью учителя — иначе он либо видит базу, либо повторяет проверки прав
своей копией ([ADR-0056](../../context/adr/0056-pomoshchnik-vtoroj-klient-servisnogo-sloya.md)).
Инструменты MCP — единственный вход агента и общий фундамент любого
будущего навыка; без них `agent-runner` некуда подключать процесс
Claude Code, а `problem-intake` некуда дописывать инструменты Черновика
Задачи. Элемент бэклога `locus-mcp`, первый доступный после
`strategy-edition-3`.

## What Changes

- Сервер MCP **внутри приложения** (Java SDK MCP, транспорт Streamable
  HTTP без сессий) по адресу `/mcp` на том же порту, что и страницы
  ([ADR-0054](../../context/adr/0054-pomoshchnik-claude-code-na-stende-process-na-repliku.md)).
- **Токен на Реплику** ([ADR-0057](../../context/adr/0057-lichnost-i-kletka-pomoshchnika-navyki-dokumenty.md)):
  Локус выпускает его на Пользователя со сроком, инструмент узнаёт по нему
  учителя из заголовка `Authorization: Bearer`, по завершении Реплики токен
  отзывается, перезапуск убивает все. Вызов без токена, с мёртвым или
  истёкшим — отказ `401`, ни один инструмент не зовётся. Выпускать токен
  будет `agent-runner`; здесь — выпуск, проверка и отзыв как сервис
  и тест-двойник, который ими пользуется.
- **Личность** — та же, что у страницы: инструмент входит в сервисный слой
  с тем же вошедшим, что получил бы контроллер; собственной проверки прав
  и фильтра по владельцу у инструмента нет, `@PreAuthorize` и `UserId`
  сервисов работают как есть.
- **Реестр инструментов** — единственный список того, что умеет
  Помощник: по нему строится сервер и по нему сторожевой тест
  `agent-runner` сверит навыки.
- **Инструменты первой очереди** (библиотека и Черновики сборки):
  `list_topics`, `list_methods`, `list_characteristics`, `find_problems`,
  `get_problem`, `get_problem_page`, `create_problem`,
  `list_assembly_drafts`, `get_assembly_draft_page`,
  `crop_assembly_draft_page`. Каждый — тонкая обёртка метода сервиса;
  страница и кусок страницы отдаются **картинкой**, прочее — JSON; отказ
  сервиса возвращается Помощнику текстом того же отказа, что увидел бы
  учитель на странице.
- Чего **нет** в этой очереди и почему — в design.md: загрузки черновика
  инструментом (у процесса в клетке нет файлов), инструментов Черновика
  Задачи (сущность строит `problem-intake`), текста Задачи у `create_problem`
  (`problem-text`), инструментов личного контура (ADR-0054, ADR-0056 —
  по одному элементу на область с решением, что уходит наружу).
- Новая внешняя библиотека: `io.modelcontextprotocol.sdk:mcp` 2.1.0.
  Видна только пакету `ru.locus.assistant` — как SDK хранилища виден
  только `ru.locus.file`.

## Capabilities

### New Capabilities

- `assistant-tools`: инструменты Помощника — сервер MCP внутри
  приложения, личность по токену на Реплику, реестр и первая очередь
  инструментов библиотеки и Черновиков сборки; изоляция чужих черновиков
  и отказ без токена.

### Modified Capabilities

Нет. Сервисы библиотеки и черновиков не меняют поведения: инструмент
зовёт существующие методы, а новые (список своих черновиков, кусок
страницы черновика картинкой) — чтение, описанное требованиями новой
возможности.

## Версия

`MINOR` — есть дельта спек, учитель на страницах изменения не замечает
(standards.md, «Версии»): 3.2.0 → 3.3.0. Строка журнала: «`locus-mcp` —
сервер MCP внутри приложения: Помощник действует в библиотеке
и в черновиках сборки инструментами под личностью учителя по токену
на реплику; первая очередь инструментов — дерево, словари, Задачи
и страницы черновиков картинками».

## Impact

- Решения: новых записей журнала нет. Изменение исполняет ADR-0054
  (сервер внутри приложения), ADR-0056 (второй клиент сервисного слоя,
  реестр) и ADR-0057 (токен на Реплику); выбор транспорта без сессий,
  состав первой очереди и форма ответов — решения в design.md,
  в рамках принятых записей.
- Код: новый пакет `ru.locus.assistant` (сервер, токены, реестр,
  абстракция инструмента); классы инструментов в областях —
  `TaxonomyTools`, `DictionaryTools`, `ProblemTools`,
  `AssemblyDraftTools` — рядом с контроллерами, слоем «Инструменты MCP»
  из architecture.md; `AssemblyDraftRepository.findByOwner(UserId)`,
  `AssemblyDraftService.own()` и `previewPiece(...)`,
  `PdfAssembly.previewPiece(...)`; `Addresses.MCP`; вторая цепочка
  безопасности для `/mcp`.
- Тесты: отказ без токена, с мёртвым и истёкшим; чужой черновик
  неотличим от несуществующего; `create_problem` Учителем без роли
  Администратора — отказ; инструменты тонкие (без репозиториев
  и хранилища — по образцу `ProblemControllerIsThinTest`); реестр
  совпадает со списком сервера; тест-двойник клиента MCP из того же SDK
  проходит все инструменты по HTTP.
- Документы: `architecture.md` (сервер MCP построен: адрес, транспорт,
  токен), `glossary.md` (токен Реплики `TurnToken`, реестр `ToolRegistry`),
  `standards.md` (SDK MCP только в `ru.locus.assistant`; инструменты
  тонкие, реестр сторожится тестом), `antipatterns.md` (инструмент
  со своей проверкой прав или репозиторием), `CLAUDE.md`.
- **Граница общего и личного** — изменение её **задаёт для второго
  клиента**: инструменты библиотеки отдают общее всем вошедшим без фильтра
  по владельцу; инструменты черновиков отдают только черновики владельца
  токена — тем же `AssemblyDraftService`, что и страницы, с `UserId`
  из `CurrentUser`; данных личного контура у инструментов нет. Свои
  проверки прав инструменты не держат.
- Не ломает: схема базы не меняется, страницы не меняются; новая
  зависимость не требует действий оператора.
