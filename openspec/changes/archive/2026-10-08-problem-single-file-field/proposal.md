## Why

У каждого слота Задачи — условия и решения — по два поля выбора файла:
«PDF условия» и «или собрать из картинок и страниц PDF»; то же в блоках
замены файла. Учитель (замечание 08.10.2026, Locus 1.2.0) не понимает,
зачем два, и просит оставить одно — сборки: не тронул файл — он ложится
целиком, задал диапазоны и рамки — собирается.

## What Changes

- На форме заведения Задачи и в блоках «Замена файлов» — одно поле файла
  на слот: нынешнее поле сборки. Отдельное поле готового PDF убирается.
- Порядок сборки, который берёт ровно один PDF-черновик целиком (все
  страницы, без рамки), кладёт в слот **сам исходный файл байт в байт**,
  без пересборки: ссылки, закладки и комментарии сохраняются. Любой другой
  порядок собирается, как прежде; одна картинка — страница своего размера.
- Такой нетронутый PDF держит предел инструмента, а не общий предел
  загрузки ([ADR-0049](../../context/adr/0049-odno-pole-fajla-na-slot-zadachi.md)).
- Без скрипта то же поле уходит с формой готовым файлом (у поля есть имя,
  скрипт его снимает, перехватывая файл в черновик). Готовый файл теперь
  проверяется по содержимому: не PDF — отказ с объяснением, а не картинка
  в слоте PDF.
- Правило «на слоте либо готовый файл, либо порядок сборки, не оба»
  остаётся на уровне запроса.

Решение — новая запись журнала
[ADR-0049](../../context/adr/0049-odno-pole-fajla-na-slot-zadachi.md)
(«Предложено»); она уточняет, а не заменяет
[ADR-0044](../../context/adr/0044-sborka-pdf-zadachi.md).

**Граница общего и личного.** Общее: PDF Задачи библиотеки, ведёт
Администратор. Черновик сборки по-прежнему принадлежит загрузившему
(репозиторий с `UserId`). Права и фильтры не меняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `problem-pdf-assembly`: одно поле на слот; нетронутый единственный PDF
  ложится байт в байт под пределом инструмента; путь без скрипта —
  тем же полем и только PDF.
- `problem-catalog`: способ приложить файл описывается одним полем
  вместо «готовым либо собранным».

## Версия

`MINOR` — есть дельта спек (`problem-pdf-assembly`, `problem-catalog`),
изменение не крупное и не ломающее: 2.1.3 → **2.2.0**.

## Impact

- `src/main/resources/templates/problem/form.html` — одно поле на слот
  при заведении и при замене.
- `src/main/resources/static/js/locus.js` — поле сборки снимает своё имя
  при запуске скрипта.
- `AssemblyDraftService.assemble` — «целиком» отдаёт исходный файл.
- `ProblemService` — проверка, что готовый файл — PDF; `PdfAssembly` —
  признак PDF рядом с признаками JPEG и PNG.
- Тесты сборки, формы и отказа без скрипта.
- Схема БД, хранилище, права — без изменений.
