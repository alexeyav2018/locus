## Context

Слот Задачи сегодня принимает два вида присланного (`ProblemPdf`,
`src/main/java/ru/locus/problem/ProblemPdf.java`): готовый файл
`UploadedFile` из поля `condition`/`solution` и порядок сборки
`PdfAssemblyOrder` из скрытых полей строк `…Draft/From/To/Crop`. Что
прислан ровно один вид, решает `ProblemController.slot`. Форма
`problem/form.html` рисует под оба вида по полю — при заведении
и в двух блоках замены.

Поле сборки (`data-assembly-source`) не имеет `name` и работает только
скриптом: `locus.js` загружает каждый выбранный файл в черновик
(`POST /problems/drafts`, обработчик с `@LargeUpload`) и вставляет строку
сборки; новая строка берёт исходник целиком (`AssemblyRow.whole`,
страницы 1…N, рамки нет). Собирает `AssemblyDraftService.assemble`,
вызываемый из `ProblemService.resolved`.

Предел: обработчики формы Задачи держат общий предел 20 МБ
(`UploadLimitInterceptor`), загрузка черновика — предел инструмента.

## Goals / Non-Goals

**Goals:**

- одно поле файла на слот — при заведении и при замене;
- нетронутый единственный PDF — в слот байт в байт;
- путь без скрипта — тем же полем, только PDF.

**Non-Goals:**

- менять сборку, обрезку, черновики, уборку и их пределы;
- сущность «Источник» и повторное использование сборника (ADR-0044
  оставил её отвергнутой);
- менять правку разметки Задачи — файлы там не участвуют.

## Где живут данные

Общая библиотека: PDF Задачи; менять — только Администратор, проверка
в `ProblemService` (`@PreAuthorize`); по владельцу не фильтруются.
Черновик сборки — по-прежнему личный у загрузившего: `assemble` читает
только черновики вошедшего (`findByIds(currentUser.id(), …)`), новых
методов репозитория не появляется, классы исключений ADR-0036/ADR-0044
не расширяются.

## Decisions

### 1. Поле сборки получает `name` слота; скрипт имя снимает

У одного поля на слот — `name="condition"` (`solution`) и
`data-assembly-source`. Скрипт при запуске снимает `name`, и файл
уходит только в черновик; без скрипта поле отправляется с формой как
готовый файл, и `ProblemController` разбирает его прежним путём
`UploadedFile`. `multiple` по-прежнему ставит скрипт: без скрипта файл
один — готовый PDF слота.

*Альтернатива:* оставить поле без имени и на сервере принимать «без
скрипта» отдельным полем в `<noscript>`. Отвергнуто — второе поле
возвращается, только спрятанным.

### 2. «Целиком» решает `AssemblyDraftService.assemble`, а не контроллер

Признак вычисляется по порядку и по черновику: одна строка, вид `PDF`,
`from == 1`, `to == pageCount`, рамки нет. Тогда `assemble` отдаёт
содержимое файла черновика как есть (`Files.readAllBytes`), не открывая
PDFBox. Число страниц знает только черновик, а владельца проверяет
только сервис — поэтому решение там же, где сборка; для вызывающего
это по-прежнему «собрать PDF по порядку», и `ProblemService.resolved`
не меняется.

*Альтернатива:* новый вариант `ProblemPdf` «черновик целиком».
Отвергнуто: форма не знает, тронут ли файл (диапазон правится в
полях строки), и различать пришлось бы снова по строкам — тот же
признак в двух местах.

*Альтернатива:* в `PdfAssembly` — если единственный кусок `Pages` покрывает
файл, копировать. Отвергнуто: чистой функции пришлось бы открывать
документ ради подсчёта страниц, а черновик это число уже знает.

### 3. Готовый файл проверяется по первым байтам

`ProblemService.resolved` для `UploadedFile` проверяет сигнатуру
`%PDF-`; иначе — `IllegalArgumentException` «PDF условия: без скрипта
принимается только PDF; картинку соберите при включённом скрипте».
Проверка признака переезжает из `AssemblyDraftService.isPdf` в
`PdfAssembly.isPdf` — рядом с `isJpeg` и `isPng`, одна на оба пути.
Отказ идёт до укладки в хранилище, как остальные проверки `create`.

### 4. Предел нетронутого PDF — предел инструмента

Отдельного кода не требует: файл принят загрузкой черновика под
пределом инструмента, а форма Задачи присылает только номер черновика.
Записано в спеке и ADR-0049, проверяется тестом с файлом крупнее
общего предела.

### 5. Подписи формы

Поле слота подписано «PDF условия» / «PDF решения» (при замене —
«Новый PDF …») с подсказкой: «PDF, картинки JPEG и PNG; выбранный PDF
без изменений ляжет как есть, можно взять страницы, обвести кусок или
добавить ещё файлы». Подсказка — один `p.hint` на блок файлов, а не
на каждое поле.

## Risks / Trade-offs

- [Скрипт загрузил файл, а пользователь успел отправить форму до вставки
  строки] → имя снято при запуске скрипта, файл в форму не уходит;
  отказ «Не приложен PDF …» — как при пустом слоте сегодня.
- [Нетронутый PDF крупнее 20 МБ ложится в хранилище] → принято ADR-0049;
  собранные из крупных сборников результаты уже не ограничены общим
  пределом.
- [Нетронутый PDF несёт в себе всё, что было в файле, включая вложения
  и скрытое] → так же, как готовый PDF сегодня: Администратор дал файл —
  файл и хранится.
