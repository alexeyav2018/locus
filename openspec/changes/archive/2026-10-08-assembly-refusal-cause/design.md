## Context

`PdfAssembly` отклоняет неразбираемый исходник отказом
`IllegalArgumentException` с текстом для Администратора и именем файла,
но без исходного исключения: `imagePreview` («Картинка … не разбирается»),
`open` («закрыт паролем», «не разбирается как PDF»), `imagePiece`
и `imagePage` (JPEG через `JPEGFactory`). Отказ ловят и показывают
`AssemblyDraftController.upload` (ответ 422 с фрагментом `refusal`)
и `ProblemController` — заведение Задачи (`create`) и формы замены файла
(через `refusedEdit`). Ни один из них не пишет в журнал; в пакете
`ru.locus.problem` журнала нет вовсе.

Единственный прецедент журнала в коде —
`FileStorageUnavailableException.reported`: `ERROR` в месте отказа внешней
зависимости.

Данные — общая библиотека (сборка PDF Задачи, ведёт Администратор). Модель
данных, права и фильтр по владельцу не меняются.

## Goals / Non-Goals

**Goals:**
- Отказ на неразбираемом файле оставляет в журнале `WARN` с именем файла
  и исходным исключением.
- Текст отказа на экране прежний.

**Non-Goals:**
- Показ причины Администратору (вариант (б) карточки отклонён).
- Журнал отказов вне сборки PDF и журнал ошибок заполнения форм.
- Показ страницы черновика (`GET …/pages/{page}`): там отказ не ловится
  и уходит общим путём ошибок; `cause` у него теперь есть, отдельной
  записи не добавляется.

## Decisions

**Причина — `cause`, журнал — в месте показа (вариант (а) карточки).**
Варианты из карточки: (а) `cause` и `WARN` в месте показа с именем файла;
(б) показывать текст исключения на экране; (в) только `cause`. Выбран (а),
предпочтительный: (б) показывает учителю английскую техническую строку,
(в) кладёт причину в объект, который никуда не попадает. Пишет тот, кто
обрабатывает отказ, а не тот, кто его бросает: `PdfAssembly` — чистая
функция, и отказ ещё может быть перехвачен выше.

**В журнал — только отказ с исходным исключением.** Под вопросом было,
какие отказы писать: места показа ловят `IllegalArgumentException` общим
обработчиком, и туда же попадают ошибки заполнения формы («хотя бы один
Метод», «страницы 4–7 в нём нет»). Варианты: писать все отказы; писать
только отказы с `cause`; завести отдельный тип исключения для отказа
разбора. Выбран второй: признак «у отказа есть исходное исключение»
ровно отделяет сбой разборщика от ответа на ввод, не требует нового типа
и правки обработчиков; писать все — засорять `WARN` штатными ошибками
заполнения, по которым разбирать нечего. Новый тип отвергнут как лишний:
формы ловят отказ общим `IllegalArgumentException`, и подтип ничего
не добавил бы, кроме ещё одной ветки в `catch`.

**Одна запись — один класс `AssemblyRefusals`.** Запись в журнал вынесена
в пакетный класс с одним статическим методом, а не повторена в двух
контроллерах: строка журнала одинакова в обоих местах, и тест слушает
один журнал. Имя файла в строку отдельно не передаётся — оно уже в тексте
отказа, как его видит Администратор.

## Risks / Trade-offs

- [Отказ с `cause`, не связанный с файлом, попадёт в `WARN`] → таких
  в пакете нет; появится — строка журнала всё равно полезна.
- [Испорченный PNG при сборке по-прежнему не отказ, а страница ошибки:
  `ImageIO.read` в `imagePage` бросает `IOException`, которую `assemble`
  оборачивает в «Не удалось собрать PDF»] → причина при этом попадает
  в журнал общим путём ошибок; приведение к отказу с именем файла —
  вне карточки, оставлено долгом.
- [Стек исключения в журнале длинный] → `WARN` на неразбираемом файле
  редок; разбор по одной строке ценнее краткости.
