## MODIFIED Requirements

### Requirement: Работа — решение одной Задачи одного Задания, с файлами и датой получения

Система SHALL хранить Работу как запись из владельца-Учителя, Задания
этого Учителя, Задачи из состава этого Задания, даты получения, вердикта
(может отсутствовать), примечания (может быть пустым) и упорядоченного
набора файлов, который MAY быть пустым: решение, увиденное вживую или
не перенесённое со снимка, принимается без файла
([ADR-0063](../../context/adr/0063-fajl-raboty-neobyazatelen.md)).
Работа без файла SHALL быть полноценной Работой — она снимает «не сдано»,
держит Задание и Ученика и служит основанием отметки Владения наравне
с Работой с файлами.
На паре «Задание × Задача» Работа MUST быть одна: повторная присылка
по той же Задаче — добавление файлов к существующей Работе, а не вторая
Работа ([ADR-0038](../../context/adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)).
Работа по Задаче, не входящей в состав Задания, MUST отклоняться.
Дата получения обязательна; по умолчанию — сегодня, Учитель может указать
другую: решение пришло раньше, чем его перенесли в систему. Срок Задания
на приём не влияет: Работа с опозданием принимается
([ADR-0016](../../context/adr/0016-zadaniya-bez-shablonov.md)).

#### Scenario: Приём Работы с двумя снимками

- **WHEN** Учитель принимает по Задаче своего Задания два снимка,
  не указывая ни вердикта, ни примечания
- **THEN** у этой Задачи Задания появляется Работа с двумя файлами в порядке
  загрузки и сегодняшней датой получения
- **AND** Работа показывается как не проверенная

#### Scenario: Приём с датой получения в прошлом

- **WHEN** Учитель принимает Работу, указав дату получения позавчера
- **THEN** Работа показывает дату получения позавчера

#### Scenario: Работа без файла

- **WHEN** Учитель отправляет приём, не выбрав ни одного файла,
  с вердиктом «верно»
- **THEN** у этой Задачи Задания появляется Работа без файлов
  с вердиктом «верно» и сегодняшней датой получения

#### Scenario: Работа без файла снимает «не сдано»

- **WHEN** срок Задания прошёл, и Учитель принимает по одной из его Задач
  Работу без файла
- **THEN** Задание не показывается как несданное

#### Scenario: Вторая Работа на той же Задаче Задания

- **WHEN** по Задаче Задания уже есть Работа, и Учитель отправляет приём
  по той же Задаче того же Задания снова
- **THEN** вторая Работа не создаётся
- **AND** Учителю сообщается, что Работа по этой Задаче уже принята
  и файлы добавляются к ней

#### Scenario: Задача не из состава Задания

- **WHEN** в приёме указана Задача, которой в составе Задания нет
- **THEN** Работа не создаётся
- **AND** Учителю сообщается, что такой Задачи в Задании нет

#### Scenario: Приём после срока

- **WHEN** срок Задания прошёл вчера, и Учитель принимает Работу сегодня
- **THEN** Работа принята
- **AND** Задание больше не показывается как несданное

### Requirement: Файлы Работы — изображение или PDF, наружу только по временной ссылке

Система SHALL принимать в Работу изображения и PDF: изображение
пережимается при загрузке, PDF хранится как есть
([ADR-0021](../../context/adr/0021-hranilishche-fajlov.md)); файл
иного типа MUST отклоняться с объяснением, и приём с таким файлом
не проходит целиком. Файл Работы SHALL отдаваться только по временной
подписанной ссылке; постоянного адреса у файла MUST NOT быть — сканы
работ суть персональные данные детей. Система SHALL принимать несколько
файлов одним действием — и при приёме, и при добавлении к существующей
Работе, в том числе к Работе без файла; добавленные файлы становятся
в конец. Учитель SHALL удалять отдельный файл Работы, но MUST NOT удалять
последний: у Работы, у которой файлы есть, хотя бы один остаётся,
ошибочная загрузка исправляется удалением Работы целиком
([ADR-0063](../../context/adr/0063-fajl-raboty-neobyazatelen.md)).
Пределы объёма загрузки MUST вмещать несколько снимков с телефона
за один приём.

#### Scenario: Снимок пережат

- **WHEN** Учитель принимает Работу со снимком, большая сторона которого
  превышает заданный предел
- **THEN** сохранённый файл по объёму меньше исходного
- **AND** открывается как изображение в той же ориентации

#### Scenario: PDF как есть

- **WHEN** Учитель принимает Работу с PDF
- **THEN** по ссылке на файл читается ровно то содержимое, что было
  загружено

#### Scenario: Файл неподдерживаемого типа

- **WHEN** Учитель принимает Работу со снимком и текстовым документом
- **THEN** Работа не создаётся
- **AND** Учителю сообщается, что принимаются изображения и PDF

#### Scenario: Файл только по временной ссылке

- **WHEN** Учитель открывает Работу и переходит по ссылке на её файл
- **THEN** содержимое отдаётся
- **AND** по тому же адресу без подписи или после истечения срока
  содержимое не отдаётся

#### Scenario: Добавление файлов к принятой Работе

- **WHEN** к Работе с одним файлом Учитель добавляет ещё два
- **THEN** Работа показывает три файла, добавленные — после прежнего

#### Scenario: Файлы к Работе без файла

- **WHEN** к Работе, принятой без файла, Учитель прикладывает один снимок
- **THEN** Работа показывает этот файл
- **AND** вердикт, примечание и дата получения Работы прежние

#### Scenario: Удаление файла

- **WHEN** Учитель удаляет один из двух файлов Работы
- **THEN** Работа показывает оставшийся файл
- **AND** удалённый файл не отдаётся по ранее выданной ссылке

#### Scenario: Последний файл не удаляется

- **WHEN** Учитель удаляет единственный файл Работы
- **THEN** файл остаётся
- **AND** Учителю сообщается, что последний файл не удаляется
  и удалить можно Работу целиком

### Requirement: Приём идёт с экрана Задания и рассчитан на телефон

Система SHALL показывать Учителю экран приёма по Заданию: все Задачи
его состава, у каждой — принятая Работа с файлами, датой получения,
вердиктом и примечанием и действиями над ней либо форма приёма
(С5 [scenarios.md](../../context/scenarios.md)). Форма приёма
и добавления файлов SHALL принимать несколько файлов одним выбором;
поле файлов в форме приёма MAY оставаться пустым. Экран MUST быть
пригоден для узкого экрана телефона: разметка масштабируется под ширину
устройства, ни один элемент не задаёт ширины больше экрана. Страница
Задания SHALL вести на экран приёма. Система SHALL показывать Работы
одного Ученика списком — по Заданиям, новые первыми, с датой получения
и вердиктом — чтобы вернуться к прошлым работам; карточка Ученика SHALL
вести на этот список.

У Работы без файла система SHALL показывать пометку «без файла» и действие
«Приложить файлы» — и на экране приёма, и в списке Работ Ученика
([ADR-0063](../../context/adr/0063-fajl-raboty-neobyazatelen.md)).
Пометка MUST вычисляться из отсутствия файлов, а не храниться: как только
у Работы появился файл, пометки и действия «Приложить файлы» у неё нет.
«Приложить файлы» в списке Работ Ученика SHALL вести на экран приёма
Задания этой Работы с раскрытой формой дополнения файлов.

#### Scenario: Экран приёма по Заданию

- **WHEN** Учитель открывает экран приёма Задания из двух Задач, по первой
  из которых Работа принята
- **THEN** у первой Задачи показаны файлы, дата получения и вердикт
  или «не проверена»
- **AND** у второй — форма приёма с выбором нескольких файлов

#### Scenario: Узкий экран

- **WHEN** экран приёма открыт на телефоне
- **THEN** страница масштабируется под ширину устройства
- **AND** форма приёма доступна без горизонтальной прокрутки

#### Scenario: Работы Ученика

- **WHEN** Учитель открывает Работы своего Ученика, от которого приняты
  Работы по двум Заданиям
- **THEN** показаны обе Работы с датами получения и вердиктами,
  новые первыми, каждая со ссылкой на экран приёма своего Задания

#### Scenario: Работа без файла на экране приёма

- **WHEN** Учитель открывает экран приёма Задания, по Задаче которого
  принята Работа без файла
- **THEN** у этой Работы показана пометка «без файла»
- **AND** есть действие «Приложить файлы» с выбором нескольких файлов

#### Scenario: Работа без файла в списке Работ Ученика

- **WHEN** Учитель открывает Работы своего Ученика, среди которых есть
  Работа без файла
- **THEN** у неё показаны пометка «без файла» и ссылка «Приложить файлы»
- **AND** ссылка ведёт на экран приёма её Задания с раскрытой формой
  дополнения файлов этой Работы

#### Scenario: Приложенный файл снимает пометку

- **WHEN** к Работе без файла Учитель приложил снимок и открывает экран
  приёма и список Работ Ученика
- **THEN** ни на одном из них у этой Работы нет пометки «без файла»
  и действия «Приложить файлы»

## REMOVED Requirements

### Requirement: Приём и вердикт сохраняются вместе с отметками Владения, целиком

**Reason**: требование держало пример «приём без файла отклонён, отметок
нет», а приём без файла теперь законен (ADR-0063).

**Migration**: заменено требованием «Приём с файлами или без и вердикт
сохраняются вместе с отметками Владения, целиком»: правило отката то же,
пример отказа — на файле неподдерживаемого типа, добавлен приём без файла
с вердиктом и отметкой.

## ADDED Requirements

### Requirement: Приём с файлами или без и вердикт сохраняются вместе с отметками Владения, целиком

Система SHALL принимать Работу вместе с отметками Владения по её Задаче
одним действием — с файлами или без них — и SHALL так же одним действием
сохранять вердикт и примечание принятой Работы вместе с отметками.
Действие MUST выполняться целиком или не выполняться вовсе. После отказа
форма SHALL показываться снова с выбранным, кроме превышения предела
загрузки: тогда запрос не разобран. Вердикт MUST NOT менять ячеек.
Работа без файла SHALL считаться в справке у ячейки Владения наравне
с Работой с файлами.

#### Scenario: Приём с отметкой

- **WHEN** Учитель принимает Работу с одним снимком, выбрав в ячейке
  «А × X» «владеет», а в остальных оставив «без изменения»
- **THEN** Работа принята
- **AND** ячейка «А × X» показывает «владеет», остальные — прежние значения

#### Scenario: Приём без файла с вердиктом и отметкой

- **WHEN** Учитель отправляет форму приёма без файла, выбрав вердикт
  «верно» и в ячейке «А × X» «владеет»
- **THEN** Работа принята без файла с вердиктом «верно»
- **AND** ячейка «А × X» показывает «владеет»
- **AND** справка у ячейки «А × X» считает эту Работу решённой

#### Scenario: Отказ приёма не пишет отметок

- **WHEN** Учитель отправляет форму приёма с текстовым документом вместо
  снимка, выбрав в ячейке «А × X» «владеет» и вердикт «верно»
- **THEN** приём отклонён, Работы нет и отметки нет
- **AND** форма приёма показана снова с выбранными «верно» и «владеет»

#### Scenario: Отказ в отметке отменяет приём

- **WHEN** форма приёма с двумя снимками приходит с ячейкой не из разметки
  Задачи
- **THEN** приём отклонён, Работы нет
- **AND** ни один из снимков не остался в хранилище

#### Scenario: Вердикт и отметки одним сохранением

- **WHEN** у принятой без вердикта Работы Учитель ставит «неверно»
  и в ячейке «А × X» «не владеет» и сохраняет
- **THEN** Работа показывает «неверно»
- **AND** ячейка «А × X» показывает «не владеет»

#### Scenario: Отказ в отметке не меняет вердикта

- **WHEN** форма вердикта приходит с ячейкой не из разметки Задачи
  и с вердиктом «верно»
- **THEN** сохранение отклонено
- **AND** вердикт Работы прежний, и ни одна ячейка не изменилась
