# Design

## Context

Мотив — proposal.md, «Why». Нынешнее устройство:

- `StudentWork` (`src/main/java/ru/locus/work/StudentWork.java:62-64`)
  отказывает в записи с пустым списком файлов; это единственная проверка
  «хотя бы один» в модели.
- `StudentWorkService.accepted` (`StudentWorkService.java:285-298`) после
  отбрасывания пустых полей формы требует непустой остаток; им же
  пользуются `receive` и `addFiles`.
- `StudentWorkService.deleteFile` (`:214-229`) отказывает, если файл один.
- `StudentWorkRepository.create` (`:83-100`) вставляет строку Работы
  и затем файлы через `insertFiles`, который на пустом списке ничего
  не делает (`:272-275`); чтение собирает Работу и дочитывает файлы
  отдельно, `getOrDefault(..., List.of())` (`:310`). Схема
  (`migrations/0008-submission-review.yaml`) держит файлы отдельной
  таблицей `student_work_file`; ограничения «хотя бы одна строка» в базе
  нет.
- Справка «Работы: N из M» — `StudentWorkRepository.countCheckedByPairs`
  (`:242-268`) — считает строки `student_work` с вердиктом и с файлами
  не соединяется.
- Экран приёма `templates/work/assignment.html` показывает у принятой
  Работы ссылки «файл N» и блоки «Вердикт и владение», «Файлы», «Удаление»;
  список `templates/work/list.html` — дату, Задачу, вердикт и «к Заданию».

## Goals / Non-Goals

**Goals:**

- Приём без файла проходит тем же действием и той же транзакцией,
  что приём с файлами, вместе с вердиктом и отметками.
- Работа без файла видна как таковая на обоих экранах и ведёт
  к дополнению файлов.

**Non-Goals:**

- Нового действия «принять без файла» или отдельной формы нет — то же
  поле, оставленное пустым.
- Схема базы не меняется; признак «без файла» не хранится.
- Работа без файла в Разминку не превращается и наоборот: это разные
  записи (ADR-0061).

## Decisions

### Данные: личный контур, фильтр по владельцу всегда

Работа и её файлы — личный контур вошедшего Учителя; правит только
владелец, владелец берётся у `CurrentUser`. Изменение не добавляет методов
репозитория и не трогает фильтрацию: `StudentWorkRepository` остаётся
с `UserId` всюду без исключений. Задачи на экране приёма — общая
библиотека, по-прежнему без фильтра.

### Ноль файлов — допустимое значение, а не особый вид Работы

`StudentWork` принимает пустой список; появляется `hasFiles()`
(`!files.isEmpty()`), которым шаблоны решают о плашке и о действии.
Альтернатива — хранимый признак «принята без файла» (чтобы различать
«принята без файла» и «файлы появились позже»). Отвергнута: различие
никому не нужно — последний файл не удаляется ни у какой Работы
с файлами (ADR-0063), — а хранимый признак разошёлся бы с таблицей файлов
так же тихо, как флаг «не проверена» с вердиктом (ADR-0038).

### Проверка «хотя бы один» уходит из приёма, остаётся в дополнении

`accepted` делится: общая часть (отбросить пустые поля, проверить тип)
служит обоим, а требование непустого остатка остаётся только у `addFiles`
— дополнение пустым набором бессмысленно, и отказ «Нужен хотя бы один
файл» там уместен. `receive` при пустом остатке не обращается
к хранилищу вовсе (пустой список ключей, `discard` пустого — ничего).

### Удаление последнего файла: правило прежнее, текст отказа — новый

`deleteFile` по-прежнему отказывает при одном файле. Текст «Работа без
файла не существует» стал бы неправдой — Работа без файла теперь есть;
новый: «Последний файл не удаляется: удалите Работу целиком». Спека
говорит то же.

### Показ «без файла» и «Приложить файлы»

- **Экран приёма.** У Работы без файла вместо списка ссылок «файл N» —
  плашка `badge badge--warn` «без файла» рядом с вердиктом (тот же класс,
  что «без текста» у Задачи, `problem/problem.html:23`). Блок «Файлы»
  у такой Работы называется «Приложить файлы» и несёт только форму
  дополнения (списка с «Удалить файл» нет — удалять нечего). Это тот же
  адрес `POST /works/{id}/files`, а значит, отказ раскрывает тот же блок
  (`shell.openedUnder`), и контроллер не меняется.
- **Список Работ Ученика.** Плашка «без файла» и ссылка-кнопка
  «Приложить файлы» на экран приёма с параметром `attach=<id Работы>`
  и якорем `#work-<id>`; блок «Приложить файлы» на экране приёма
  раскрыт, когда `param.attach` равен его Работе. Читает параметр шаблон
  (`${param.attach}`), контроллер о блоках не знает (ADR-0042) —
  так же, как `shell.opened`. Альтернатива — форма дополнения прямо
  в списке: отвергнута, после дополнения контроллер ведёт на экран
  приёма, и человек оказался бы не там, откуда начал; кроме того, это
  второе место одной формы.

### Тексты отказа приёма в спеке

Сценарий «Приём без файла не пишет отметок» был примером «отказ приёма —
ни Работы, ни отметок, форма с выбранным». Он заменяется тем же примером
на файле неподдерживаемого типа: правило отката не меняется, меняется
только повод.

## Risks / Trade-offs

- [Учитель по ошибке принимает без файла, хотя снимок был] → снимок
  прикладывается позже тем же дополнением; пометка «без файла» в списке
  Работ Ученика напоминает об этом.
- [Справка «Работы: N из M» больше не равна числу снимков] → принятый
  риск ADR-0063; пометка «без файла» показывает, у каких Работ снимка нет.
- [Тесты, проверявшие отказ без файла, начнут падать] → они переписываются
  на новое поведение в том же разделе задач, что и код; старый сценарий
  отказа — на тип файла.

## Migration Plan

Миграций нет: существующие Работы все с файлами, новое значение (ноль
файлов) появляется только у новых. Откат кода к прежней версии при уже
принятых Работах без файла сломает их чтение (конструктор `StudentWork`
откажет) — обновление идёт вперёд (ADR-0024), откатных сценариев нет.
