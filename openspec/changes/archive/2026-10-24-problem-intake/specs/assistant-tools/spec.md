## MODIFIED Requirements

### Requirement: Реестр инструментов — единственный список умений Помощника

Приложение SHALL вести реестр инструментов: имя латиницей в `snake_case`,
описание и схему аргументов каждого. Сервер MCP MUST предлагать клиенту
ровно инструменты реестра; имя в реестре неповторимо. Реестр — то, с чем
сверяются навыки Помощника
([ADR-0056](../../context/adr/0056-pomoshchnik-vtoroj-klient-servisnogo-sloya.md),
[ADR-0057](../../context/adr/0057-lichnost-i-kletka-pomoshchnika-navyki-dokumenty.md)).

#### Scenario: Список сервера равен реестру

- **WHEN** клиент MCP запрашивает список инструментов
- **THEN** имена в ответе совпадают с именами реестра, без лишних
  и без пропущенных

#### Scenario: Инструментов личного контура и глаголов человека нет

- **WHEN** читается реестр
- **THEN** в нём ровно семнадцать инструментов: `list_topics`,
  `list_methods`, `create_method`, `list_characteristics`,
  `find_problems`, `get_problem`, `get_problem_page`, `create_problem`,
  `list_assembly_drafts`, `get_assembly_draft_page`,
  `crop_assembly_draft_page`, `list_problem_drafts`,
  `create_problem_draft`, `get_problem_draft`, `update_problem_draft`,
  `save_problem_draft`, `delete_problem_draft`
- **AND** ни один не читает Учеников, Группы, Задания, Работы, отметки
  Владения или Занятия и не ставит вердикта или отметки

## ADDED Requirements

### Requirement: Администратор заводит Метод инструментом

`create_method` SHALL заводить Метод в словарь по имени тем же сервисом
и с теми же проверками, что экран словарей: только Администратор,
имя неповторимо без учёта регистра. В ответе — идентификатор нового
Метода.

#### Scenario: Новый Метод

- **WHEN** Помощник Администратора зовёт `create_method` с именем,
  которого в словаре нет
- **THEN** Метод заведён, в ответе его идентификатор
- **AND** `list_methods` называет его

#### Scenario: Повтор имени

- **WHEN** Помощник зовёт `create_method` с именем существующего Метода
  в другом регистре
- **THEN** ответ — результат с признаком ошибки с текстом отказа сервиса

### Requirement: Помощник ведёт Черновики Задачи своего учителя

Инструменты Черновика Задачи SHALL действовать тем же сервисом, что
страница вычитки, и под личностью учителя:

- `create_problem_draft` — завести черновик (тексты, строки сборки
  условия и решения, сомнительные места, Часть, Темы, Методы,
  Характеристики, новые Методы); в ответе — идентификатор, версия
  и адрес страницы вычитки;
- `list_problem_drafts` — свои черновики: идентификатор, версия, кем
  и когда изменён;
- `get_problem_draft` — черновик целиком с версией;
- `update_problem_draft` — записать с версией прочитанного; часть,
  не названная в вызове, не меняется; в ответе — новая версия;
- `save_problem_draft` — сохранить как Задачу с текстом с версией
  прочитанного; в ответе — номер Задачи;
- `delete_problem_draft` — удалить с версией прочитанного.

Чужой и несуществующий Черновик Задачи MUST давать один и тот же отказ.
Вызов с версией, отличной от хранимой, MUST отклоняться результатом
с признаком ошибки, просящим перечитать черновик
([ADR-0056](../../context/adr/0056-pomoshchnik-vtoroj-klient-servisnogo-sloya.md)).
Правку, сделанную инструментом, страница вычитки отмечает «изменён
Помощником».

#### Scenario: Заведение и чтение

- **WHEN** Помощник Администратора зовёт `create_problem_draft` с текстом
  условия, решения и строками по своему черновику сборки, затем
  `get_problem_draft`
- **THEN** ответ чтения содержит те же тексты и строки и версию
- **AND** ответ заведения называет адрес страницы вычитки

#### Scenario: Учитель поправил, Помощник пишет по старому

- **WHEN** Помощник прочитал черновик, учитель затем сохранил его
  на странице вычитки, и Помощник зовёт `update_problem_draft`
  с прочитанной версией
- **THEN** ответ — результат с признаком ошибки, просящий перечитать
- **AND** черновик остаётся тем, что сохранил учитель

#### Scenario: Правка одной части

- **WHEN** Помощник зовёт `update_problem_draft` с текущей версией
  и только текстом решения
- **THEN** текст решения новый, текст условия, строки и разметка прежние

#### Scenario: Чужой Черновик Задачи

- **WHEN** Помощник Б зовёт `get_problem_draft` с идентификатором
  черновика А, а затем — с идентификатором, которого нет
- **THEN** оба ответа — одинаковый результат с признаком ошибки

#### Scenario: Сохранение инструментом

- **WHEN** Помощник зовёт `save_problem_draft` с текущей версией
  у черновика с текстами, Темой-листом, Методом и Частью
- **THEN** в ответе номер заведённой Задачи с текстом
- **AND** Черновика Задачи больше нет

#### Scenario: Строка по чужому черновику сборки

- **WHEN** Помощник Б зовёт `create_problem_draft` со строкой по черновику
  сборки А
- **THEN** ответ — результат с признаком ошибки того же отказа, что
  на несуществующий черновик сборки
- **AND** Черновик Задачи не заведён
