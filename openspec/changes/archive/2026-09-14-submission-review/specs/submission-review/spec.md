## Purpose

Работа — то, чем Учитель фиксирует присланное Учеником решение конкретной
Задачи Задания: скан или фотография, дата получения, бинарный вердикт
и примечание. Описывает состав Работы, приём файлов с телефона, вердикт
отдельно от приёма, добавление и удаление файлов, удаление Работы, экран
приёма по Заданию и список Работ Ученика, изоляцию по владельцу и ответы
области на вопросы Заданий и Учеников.

## ADDED Requirements

### Requirement: Работа — решение одной Задачи одного Задания, с файлами и датой получения

Система SHALL хранить Работу как запись из владельца-Учителя, Задания
этого Учителя, Задачи из состава этого Задания, даты получения, вердикта
(может отсутствовать), примечания (может быть пустым) и упорядоченного
набора файлов, MUST содержащего хотя бы один файл
([ADR-0015](../../../context/adr/0015-skany-rabot-hranyatsya.md)).
На паре «Задание × Задача» Работа MUST быть одна: повторная присылка
по той же Задаче — добавление файлов к существующей Работе, а не вторая
Работа ([ADR-0038](../../../context/adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)).
Работа по Задаче, не входящей в состав Задания, MUST отклоняться.
Дата получения обязательна; по умолчанию — сегодня, Учитель может указать
другую: решение пришло раньше, чем его перенесли в систему. Срок Задания
на приём не влияет: Работа с опозданием принимается
([ADR-0016](../../../context/adr/0016-zadaniya-bez-shablonov.md)).

#### Scenario: Приём Работы с двумя снимками

- **WHEN** Учитель принимает по Задаче своего Задания два снимка,
  не указывая ни вердикта, ни примечания
- **THEN** у этой Задачи Задания появляется Работа с двумя файлами в порядке
  загрузки и сегодняшней датой получения
- **AND** Работа показывается как не проверенная

#### Scenario: Приём с датой получения в прошлом

- **WHEN** Учитель принимает Работу, указав дату получения позавчера
- **THEN** Работа показывает дату получения позавчера

#### Scenario: Работа без файла

- **WHEN** Учитель отправляет приём, не выбрав ни одного файла
- **THEN** Работа не создаётся
- **AND** Учителю сообщается, что нужен хотя бы один файл

#### Scenario: Вторая Работа на той же Задаче Задания

- **WHEN** по Задаче Задания уже есть Работа, и Учитель отправляет приём
  по той же Задаче того же Задания снова
- **THEN** вторая Работа не создаётся
- **AND** Учителю сообщается, что Работа по этой Задаче уже принята
  и файлы добавляются к ней

#### Scenario: Задача не из состава Задания

- **WHEN** в приёме указана Задача, которой в составе Задания нет
- **THEN** Работа не создаётся
- **AND** Учителю сообщается, что такой Задачи в Задании нет

#### Scenario: Приём после срока

- **WHEN** срок Задания прошёл вчера, и Учитель принимает Работу сегодня
- **THEN** Работа принята
- **AND** Задание больше не показывается как несданное

### Requirement: Файлы Работы — изображение или PDF, наружу только по временной ссылке

Система SHALL принимать в Работу изображения и PDF: изображение
пережимается при загрузке, PDF хранится как есть
([ADR-0021](../../../context/adr/0021-hranilishche-fajlov.md)); файл
иного типа MUST отклоняться с объяснением, и приём с таким файлом
не проходит целиком. Файл Работы SHALL отдаваться только по временной
подписанной ссылке; постоянного адреса у файла MUST NOT быть — сканы
работ суть персональные данные детей. Система SHALL принимать несколько
файлов одним действием — и при приёме, и при добавлении к существующей
Работе; добавленные файлы становятся в конец. Учитель SHALL удалять
отдельный файл Работы, но MUST NOT удалять последний: Работа без файла
не существует, удаляется Работа целиком
([ADR-0038](../../../context/adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)).
Пределы объёма загрузки MUST вмещать несколько снимков с телефона
за один приём.

#### Scenario: Снимок пережат

- **WHEN** Учитель принимает Работу со снимком, большая сторона которого
  превышает заданный предел
- **THEN** сохранённый файл по объёму меньше исходного
- **AND** открывается как изображение в той же ориентации

#### Scenario: PDF как есть

- **WHEN** Учитель принимает Работу с PDF
- **THEN** по ссылке на файл читается ровно то содержимое, что было
  загружено

#### Scenario: Файл неподдерживаемого типа

- **WHEN** Учитель принимает Работу со снимком и текстовым документом
- **THEN** Работа не создаётся
- **AND** Учителю сообщается, что принимаются изображения и PDF

#### Scenario: Файл только по временной ссылке

- **WHEN** Учитель открывает Работу и переходит по ссылке на её файл
- **THEN** содержимое отдаётся
- **AND** по тому же адресу без подписи или после истечения срока
  содержимое не отдаётся

#### Scenario: Добавление файлов к принятой Работе

- **WHEN** к Работе с одним файлом Учитель добавляет ещё два
- **THEN** Работа показывает три файла, добавленные — после прежнего

#### Scenario: Удаление файла

- **WHEN** Учитель удаляет один из двух файлов Работы
- **THEN** Работа показывает оставшийся файл
- **AND** удалённый файл не отдаётся по ранее выданной ссылке

#### Scenario: Последний файл не удаляется

- **WHEN** Учитель удаляет единственный файл Работы
- **THEN** файл остаётся
- **AND** Учителю сообщается, что Работа без файла не существует
  и удалить можно Работу целиком

### Requirement: Вердикт и примечание ставятся отдельно от приёма и меняются свободно

Система SHALL хранить у Работы вердикт — одно из двух значений, «верно»
либо «неверно», — и свободное текстовое примечание
([ADR-0014](../../../context/adr/0014-proverka-bez-avtomatiki.md)).
Вердикт MUST быть необязателен при приёме и SHALL ставиться и меняться
в любой момент после; Работа без вердикта показывается как «не проверена»
([ADR-0038](../../../context/adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)).
Примечание меняется вместе с вердиктом. Третьего значения вердикта нет:
частичность описывается примечанием. Вердикт MUST NOT влиять на отметки
Владения и MUST NOT выводиться из чего-либо
([ADR-0011](../../../context/adr/0011-otmetka-na-pare.md)).

#### Scenario: Вердикт при приёме

- **WHEN** Учитель принимает Работу, сразу отметив «верно» и написав
  примечание
- **THEN** Работа показывает «верно» и примечание

#### Scenario: Вердикт позже приёма

- **WHEN** Работа принята без вердикта, и позже Учитель ставит «неверно»
  с примечанием «потерян корень»
- **THEN** Работа показывает «неверно» и примечание
- **AND** больше не показывается как не проверенная

#### Scenario: Смена вердикта

- **WHEN** у Работы стоит «неверно», и Учитель меняет его на «верно»
- **THEN** Работа показывает «верно»

### Requirement: Работа удаляется владельцем в любой момент вместе с файлами

Система SHALL удалять Работу по действию её владельца в любой момент —
условия «пока на неё ничего не ссылается» у Работы нет: по ключу на Работу
не ссылается ни одна запись
([ADR-0038](../../../context/adr/0038-rabota-odna-na-paru-i-udalyaetsya-svobodno.md)).
Удаление MUST уносить все файлы Работы из хранилища и MUST NOT трогать
Задание и Ученика. После удаления по паре «Задание × Задача» снова можно
принять Работу.

#### Scenario: Удаление Работы

- **WHEN** Учитель удаляет Работу с двумя файлами
- **THEN** Работы по этой Задаче Задания больше нет
- **AND** ни один из её файлов не отдаётся по ранее выданной ссылке
- **AND** Задание и Ученик остаются на месте

#### Scenario: Повторный приём после удаления

- **WHEN** Учитель удалил Работу по Задаче Задания и принимает по ней новую
- **THEN** новая Работа принята

### Requirement: Приём идёт с экрана Задания и рассчитан на телефон

Система SHALL показывать Учителю экран приёма по Заданию: все Задачи
его состава, у каждой — принятая Работа с файлами, датой получения,
вердиктом и примечанием и действиями над ней либо форма приёма
(С5 [scenarios.md](../../../context/scenarios.md)). Форма приёма
и добавления файлов SHALL принимать несколько файлов одним выбором.
Экран MUST быть пригоден для узкого экрана телефона: разметка
масштабируется под ширину устройства, ни один элемент не задаёт ширины
больше экрана ([ADR-0015](../../../context/adr/0015-skany-rabot-hranyatsya.md)).
Страница Задания SHALL вести на экран приёма. Система SHALL показывать
Работы одного Ученика списком — по Заданиям, новые первыми, с датой
получения и вердиктом — чтобы вернуться к прошлым работам; карточка
Ученика SHALL вести на этот список.

#### Scenario: Экран приёма по Заданию

- **WHEN** Учитель открывает экран приёма Задания из двух Задач, по первой
  из которых Работа принята
- **THEN** у первой Задачи показаны файлы, дата получения и вердикт
  или «не проверена»
- **AND** у второй — форма приёма с выбором нескольких файлов

#### Scenario: Узкий экран

- **WHEN** экран приёма открыт на телефоне
- **THEN** страница масштабируется под ширину устройства
- **AND** форма приёма доступна без горизонтальной прокрутки

#### Scenario: Работы Ученика

- **WHEN** Учитель открывает Работы своего Ученика, от которого приняты
  Работы по двум Заданиям
- **THEN** показаны обе Работы с датами получения и вердиктами,
  новые первыми, каждая со ссылкой на экран приёма своего Задания

### Requirement: Учитель видит и ведёт только свои Работы

Система SHALL показывать Учителю только его Работы и SHALL принимать
приём, добавление и удаление файлов, вердикт и удаление Работы только
от владельца. Чужая Работа MUST быть неотличима от несуществующей:
ни экраном приёма, ни списком, ни прямым адресом, ни правкой; принять
Работу по чужому Заданию MUST быть невозможно — ответ такой же, как для
несуществующего Задания. Владелец назначается по вошедшему и MUST NOT
приниматься из запроса. Фильтр по владельцу применяется к Работам
всегда; к Задачам, которые экран приёма показывает, — никогда
([ADR-0027](../../../context/adr/0027-mehanizm-granicy-obshchego-i-lichnogo.md)).
Операции над Работами доступны только роли Учителя.

#### Scenario: Экран приёма чужого Задания

- **WHEN** Учитель Б открывает экран приёма Задания Учителя А или Работы
  его Ученика
- **THEN** страница не показывается
- **AND** ответ такой же, как для несуществующего

#### Scenario: Приём по чужому Заданию

- **WHEN** Учитель Б отправляет приём по Задаче Задания Учителя А
- **THEN** Работа не создаётся
- **AND** ответ такой же, как для несуществующего Задания

#### Scenario: Правка чужой Работы

- **WHEN** Учитель Б отправляет вердикт, файлы или удаление Работы Учителя А
- **THEN** операция не выполняется
- **AND** Работа Учителя А остаётся прежней

#### Scenario: Администратор без роли Учителя

- **WHEN** Пользователь с ролью Администратора, но без роли Учителя,
  обращается к экрану приёма или к приёму
- **THEN** доступ не предоставляется

### Requirement: Работы отвечают на вопросы Заданий и Учеников

Работа SHALL считаться с момента приёма, не с момента вердикта: вопрос
Заданий «есть ли по Заданию Работа» получает ответ «есть», как только
принята Работа хотя бы по одной его Задаче, и ответ снимается с удалением
последней Работы Задания ([ADR-0037](../../../context/adr/0037-zadanie-neizmenno-posle-vydachi.md)).
Работа SHALL считать Ученика используемым: вопрос «ссылается ли
что-нибудь на Ученика» получает ответ «принято Работ» с их числом
у вошедшего Учителя ([ADR-0035](../../../context/adr/0035-udalenie-uchenika-i-gruppy.md));
удаление Работ снимает ответ.

#### Scenario: Задание с непроверенной Работой сдано

- **WHEN** срок Задания прошёл, а по одной из его Задач принята Работа
  без вердикта
- **THEN** Задание не показывается как несданное

#### Scenario: Задание с Работой не удаляется

- **WHEN** по Задаче Задания принята Работа, и Учитель удаляет Задание
  или его Раздачу
- **THEN** удаление отклоняется
- **AND** в отказе названо, что по Заданию уже есть Работа

#### Scenario: Ученик с Работой не удаляется

- **WHEN** от Ученика принята Работа, и Учитель удаляет Ученика
- **THEN** удаление отклоняется
- **AND** в отказе названо, что от Ученика приняты Работы, и их число

#### Scenario: Последняя Работа удалена

- **WHEN** Учитель удалил единственную Работу по Заданию
- **THEN** просроченное Задание снова показывается как несданное
- **AND** Задание снова удаляется
