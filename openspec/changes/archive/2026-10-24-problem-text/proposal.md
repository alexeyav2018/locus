# Proposal

## Why

Задача, которую заведёт помощник, — текст с формулами, а не картинка:
его можно вычитать, поправить без пересъёмки, отрисовать чисто и в будущем
искать по словам ([ADR-0055](../../context/adr/0055-tekst-zadachi-pervichen-pdf-otrisovka.md)).
Сегодня Задача — только два PDF, и помощнику нечего ей записать; без
текста `problem-intake` умеет лишь резать картинку, что учитель делает
и сам. Элемент бэклога `problem-text`, доступный после `strategy-edition-3`
и `agent-spike` (П7 измерена: 0 ошибок в формулах из ~166).

## What Changes

- У Задачи появляется **необязательный Текст** — текст условия и текст
  решения, Markdown с формулами LaTeX (`$…$` в строке, `$$…$$`
  выключные). Задача бывает двух видов: **с текстом** (оба текста есть)
  и **без текста** (как сегодня); половинчатой нет.
- **Отрисовка на сервере при сохранении** в тот же слот `FileStorage`,
  что и приложенный PDF: Задания, страница просмотра и страницы картинками
  отрисованный PDF от приложенного не отличают. Отрисовщик — внутри
  приложения: вёрстка openhtmltopdf, формулы JLaTeXMath, шрифт в ресурсах
  ([ADR-0058](../../context/adr/0058-otrisovshchik-teksta-zadachi-v-steke.md),
  предложено). Неразбираемая формула — отказ сохранения с её названием.
- **Улика у каждого слота**: при Задаче с текстом PDF, собранный или
  приложенный полем слота, хранится не в слоте, а уликой этого слота;
  показывается на странице правки, в Задание не уходит. Улика
  необязательна.
- **Форма Задачи** получает выбор вида: «с текстом» — два поля текста
  и поле слота как улика, «без текста» — как сегодня. **Предпросмотр**
  отрисовки — кнопкой, на сервере, картинками страниц, без обязательного
  скрипта; введённое не теряется.
- **Правка текста**: на странице правки — поля текста, **скачать текст
  файлом `.md`** и **загрузить `.md` обратно** по слоту; правка с текстом,
  изменившимся после открытия страницы, отклоняется с просьбой перечитать
  (версия текста). Задаче без текста можно **записать текст** — прежние
  PDF становятся уликами своих слотов.
- **Заморозка** ([ADR-0030](../../context/adr/0030-zadacha-zamorazhivaetsya-posle-vydachi.md))
  распространяется на текст целиком: выданная Задача не правится и в
  тексте; опечатка в выданной — новая Задача (скачать `.md`, завести).
- **«Без текста» видно честно**: пометка на странице Задачи, в списке Темы
  и в строке поиска; поиск называет, у скольких из найденных текста нет.
  Признак не хранится — вычисляется из отсутствия текста.
- Попутно: ссылка спеки `theory-materials` на заменённую ADR-0008
  переводится на ADR-0055.

## Capabilities

### New Capabilities

- `problem-text`: Текст Задачи — два вида Задач, отрисовка текста в PDF
  слота, Улики слотов, предпросмотр, правка текста и обмен файлом `.md`
  с проверкой версии, заморозка текста, честное «без текста».

### Modified Capabilities

- `problem-catalog`: состав Задачи — два PDF, которые у Задачи с текстом
  есть отрисовка (ссылка на ADR-0055 вместо ADR-0008); файлы, не остающиеся
  без Задачи, включают Улики.
- `library-search`: строка результата помечает Задачу без текста, результат
  называет число найденных без текста.
- `theory-materials`: формулировка про текст материала ссылается на ADR-0055
  вместо заменённой ADR-0008; поведение не меняется.

## Версия

`MINOR` — есть дельта спек (standards.md, «Версии»): 3.3.0 → 3.4.0.
Вид Задачи «с текстом» — новая возможность библиотеки, но не новый
интерфейс и не целая область: форма та же, Задания и просмотр те же.
Строка журнала: «`problem-text` — Текст Задачи: условие и решение
Markdown с формулами LaTeX, PDF отрисовывается Локусом при сохранении,
снимок хранится уликой; предпросмотр, обмен файлом `.md`, честное
„без текста“ в списках и поиске».

## Impact

- Решения: новая запись журнала
  [ADR-0058](../../context/adr/0058-otrisovshchik-teksta-zadachi-v-steke.md)
  (Предложено) — отрисовщик внутри приложения. Исполняется ADR-0055;
  ADR-0030 не меняется — его действие на текст решено по умолчанию карточки
  (design.md, решение 6).
- Данные: общее. Текст и Улики — часть Задачи общей библиотеки; ведёт
  Администратор, читают все вошедшие, фильтра по владельцу нет и быть
  не должно ([ADR-0027](../../context/adr/0027-mehanizm-granicy-obshchego-i-lichnogo.md)).
- Схема: миграция `0015-problem-text` — четыре колонки таблицы Задач
  (два текста, две Улики), версия текста, ограничения «оба текста или
  ни одного» и «Улика только при тексте». Существующие Задачи остаются
  без текста, данных миграция не трогает.
- Код: пакет `ru.locus.problem` — запись `Problem`, `ProblemService`,
  `ProblemRepository`, `ProblemController`, `ProblemForm`, новая чистая
  функция отрисовки; шаблоны `problem/form.html`, `problem/problem.html`,
  `problem/search.html`, список Задач Темы.
- Зависимости: `io.github.openhtmltopdf:openhtmltopdf-pdfbox` (на том же
  PDFBox 3.0.8), `org.commonmark:commonmark`,
  `org.scilab.forge:jlatexmath` и `jlatexmath-font-cyrillic`; шрифт с
  кириллицей (OFL) в `src/main/resources`.
- Стенд: ничего не ставится, миграция обычная, «Ломает: нет».
- Инструменты помощника (`assistant-tools`) не меняются: запись текста
  инструментом и инструменты Черновика Задачи — у `problem-intake`
  и `backfill-skill`; отрисованный PDF отдаётся `get_problem_page` как
  любой другой.
