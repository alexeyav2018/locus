# Design

## Context

Мотивация — proposal.md, «Why». Что уже есть и что определяет подход:

- **Сервис Реплик построен** (`AssistantService.java`): `startTurn`
  (заводит Разговор и Реплику одной транзакцией и отдаёт исполнителю,
  отказы — `IllegalArgumentException`, `AssistantBusyException`,
  `AssistantUnavailableException`, чужой Разговор —
  `AssistantConversationNotFoundException` с `404`), `stop`, `turn`,
  `steps`, `availability`. Права — `hasAnyRole('TEACHER',
  'ADMINISTRATOR')`, владелец — из `CurrentUser`.
- **Репозиторий** (`AssistantRepository.java`) умеет Разговор
  по идентификатору и Реплики Разговора (`turnsOf`), но не умеет
  ни списка своих Разговоров, ни «идущей Реплики учителя», ни
  «последнего Разговора». Все методы — с `UserId`, кроме уборки
  `interruptRunning`; список поимённо в `OwnerIsRequiredByAssistantTest`.
- **Страница `/assistant`** (`AssistantController.java`,
  `templates/assistant/page.html`) показывает только доступность;
  `AssistantPageTest.headerHasNoAssistantItem` сторожит отсутствие
  пункта шапки.
- **Черновики сборки** — личное загрузившего, сервис
  `AssemblyDraftService.upload(имя, поток)` под
  `hasRole('ADMINISTRATOR')`, неподходящий файл —
  `IllegalArgumentException`. Обработчик загрузки у формы Задачи —
  `@LargeUpload` (`AssemblyDraftController.java:56`).
- **Направление зависимостей:** области знают `ru.locus.assistant`
  (объявляют `Tools`), а `ru.locus.assistant` областей не знает
  ни одной. Вопросы между областями — интерфейс у спрашивающего
  и ответчик у знающего (`NodeContent`, `StudentUsage`).
- **CommonMark** уже в сборке (`problem-text`, `ProblemTextRendering`:
  `escapeHtml(true)`, `sanitizeUrls(true)`, свой отрисовщик картинки).
- **Шапка** (`fragments/shell.html`): группы «Библиотека», «Кабинет»
  (только Учителю), «Админ»; раздел определяет `ShellAdvice.sectionOf`.
- **Двойник команды** (`src/test/resources/assistant/claude-double`)
  выбирает заготовку по первому слову запроса: ответ, вызовы,
  зависание, падение, шаги.

**Граница общего и личного.** Разговоры, Реплики и строки хода —
личные: каждый новый метод репозитория принимает `UserId`, и сервис
подставляет его из `CurrentUser`; чужой Разговор неотличим
от несуществующего. Черновик сборки из реплики — личный загрузившего,
его заводит сервис черновиков со своими правами (Администратор).
Библиотеку страница не трогает: Задачи заводят инструменты Помощника
по правам учителя (ADR-0056). Новых запросов без владельца нет.

Проверено по `antipatterns.md`: фильтр на личном не забыт (новые
методы — с `UserId`, изоляцию сторожит тест), к библиотеке
не применяется; фонового процесса нет — страница перечитывается
браузером по `meta refresh`, а не сервером; логики в шаблоне нет —
тон состояния, адрес возврата и HTML ответа готовит Java; Локус
не интерпретирует содержимое — ответ показывается как Markdown,
снимок кладётся черновиком как есть.

## Goals / Non-Goals

**Goals:** учитель разговаривает с Помощником со страницы Локуса
с планшета: пишет, прикладывает снимок, видит ход и ответ, может
остановить; прежние Разговоры перечитываются; ответ Помощника
не приносит на страницу ни чужой разметки, ни внешних ссылок.

**Non-Goals:** навык заведения Задач с листа (`intake-skill`)
и Черновик Задачи (`problem-intake`); подтягивание хода фрагментом
скриптом (карточка: потом, если мигание мешает); удаление
и переименование Разговоров; формулы LaTeX в ответе — показываются
как набраны.

## Decisions

### Р1. Адреса и порядок «отправил — показал»

| Метод | Адрес | Что делает |
| --- | --- | --- |
| GET | `/assistant` | Разговор по умолчанию (Р3) |
| GET | `/assistant?conversation=N` | Разговор `N`; чужой — 404 |
| GET | `/assistant?new=true` | пустая страница нового Разговора |
| POST | `/assistant/turns` | начать Реплику: `conversation` (необязательно), `prompt`, `file` (необязательно) |
| POST | `/assistant/turns/{id}/stop` | остановить свою Реплику |

После POST — переадресация на `/assistant?conversation=N` (образец
«отправил — перечитал»): обновление `meta refresh` перечитывает GET,
а не повторяет отправку. Отказ сервиса — та же страница в ответ
на POST с текстом отказа и набранным запросом (`shell.echo`), как
у прочих форм. Обработчик отправки — `@LargeUpload`: PDF сборника
весит десятки мегабайт, его предел держит сервис черновиков.

### Р2. Самообновление — параметр `refresh` у `shell :: head`

Карточка выбрала `meta refresh` без скрипта (ADR-0041). Общий
фрагмент получает необязательный параметр: страница зовёт
`~{fragments/shell :: head(refresh=${…})}`, фрагмент рисует
`<meta http-equiv="refresh" content="3">`, когда значение задано;
остальные страницы зовут `head` по-прежнему и параметра не видят.
Интервал — 3 с: ход Помощника длится 6–8 с (`agent-spike`), чаще —
лишняя нагрузка, реже — заметная задержка. Значение кладёт
контроллер — `true`, только если идущая Реплика стоит в показанном
Разговоре; шаблон только показывает.

### Р3. Какой Разговор показан по умолчанию

**Под вопросом:** карточка — «"Новый разговор" — кнопкой и по
умолчанию первым сообщением нового дня». Варианты: (а) последний
Разговор всегда, новый — только кнопкой; (б) последний, если его
последняя Реплика начата сегодня, иначе пусто; (в) по дате заведения
Разговора. **Выбрано (б)** и с поправкой на идущую Реплику: сначала
Разговор с идущей Репликой (учитель вернулся на страницу — ответ ещё
идёт), иначе последний по последней Реплике, если она начата сегодня
по `Clock` в зоне системы (`TimeConfiguration`), иначе пусто.
Почему не (в): Разговор, начатый вчера в 23:50 и продолженный
в 00:05, по дате заведения вчерашний, а по делу — сегодняшний, и (б)
это видит. Почему не (а): вчерашний Разговор тянул бы в сеанс модели
вчерашнюю историю, а каждая Реплика отправляет модели всю историю
сеанса — лишние деньги (ADR-0054). Разговор без Реплик (заведён,
но первая Реплика отклонена) не показывается: его нет в списке
прежних и нет в «последнем».

### Р4. Форма прячется, пока Реплика идёт где угодно

Реплика одна на учителя. Если она идёт в показанном Разговоре —
формы нет, есть «Остановить» и обновление. Если в другом — формы нет
и обновления нет, вместо формы — «Помощник отвечает в другом
разговоре» со ссылкой туда. Иначе вторая отправка была бы заведомо
отклонена базой. Сервис получает метод «идущая Реплика вошедшего»
(`runningTurn()`), репозиторий — `findRunningTurn(owner)`.

### Р5. Файл реплики — вопрос `TurnAttachments`, ответчик в области Задач

**Под вопросом:** как файл из формы становится Черновиком сборки,
если `ru.locus.assistant` не знает области Задач. Варианты:
(а) `AssistantController` зовёт `AssemblyDraftService` прямо —
обратная зависимость, пакеты зацикливаются (`problem` уже знает
`assistant` через `Tools`); (б) отдельный обработчик в области Задач
принимает файл и сам начинает Реплику — у Реплики два входа с разной
логикой отказов; (в) интерфейс-вопрос `TurnAttachments` в
`ru.locus.assistant` («прими файл к Реплике — скажи, что передать
Помощнику»), ответчик `AssemblyDraftAttachments` в `ru.locus.problem`
зовёт `AssemblyDraftService.upload` и возвращает строку
«Загружен черновик сборки N «имя», страниц: K.». **Выбрано (в)** —
образец `NodeContent` и `StudentUsage`: направление зависимостей
прежнее, права и отказы черновика — его сервиса.

`AssistantService.startTurn` получает необязательное вложение
(`TurnAttachment`: имя и поток). Порядок: доступность и пустота
(текст пуст и файла нет — отказ до загрузки), идущая Реплика
(отказ до загрузки — чтобы не плодить черновики), загрузка через
`TurnAttachments`, затем запрос = текст и строка о черновике через
пустую строку, затем прежняя проверка длины и транзакция. Если гонка
всё же отклонит Реплику после загрузки, черновик останется и уйдёт
попутной уборкой по сроку — как брошенный с формы Задачи.

Ответчик один; если ответчиков нет (такого в сборке не бывает, но
тест-срез может), вложение отклоняется словами «Файлы Помощнику
не принимаются».

### Р6. Поле файла — только у Администратора

Черновики сборки и заведение Задач — Администратора
(`AssemblyDraftService` и `create_problem` под `hasRole
('ADMINISTRATOR')`). Учителю без этой роли поле не показывается:
файл, отклонённый правами, был бы обещанием, которое страница
не держит. Признак берётся из `shell.administrator` — тем же, что
показывает «Админ» в шапке; сервер всё равно отклонит чужую попытку
правами сервиса черновиков (403). `accept="image/jpeg,image/png,
application/pdf"`: планшет предлагает камеру, iPad отдаёт снимок
JPEG; HEIC не принимается (`heic-images` ждёт условия).

### Р7. Ответ — `AnswerMarkdown`: белый список CommonMark и только внутренние ссылки

Чистая функция `AnswerMarkdown.html(ответ, адрес возврата)`
в `ru.locus.assistant`:

- `escapeHtml(true)` — сырой HTML блоком и в строке выводится текстом;
  набор тегов на выходе — только теги самого CommonMark (абзацы,
  заголовки, списки, выделение, код, цитата, черта, перевод строки);
  это и есть белый список;
- свой отрисовщик ссылки: адрес, прошедший `ReturnTo.safe`, становится
  `<a href>` с `from` = адрес показанного Разговора (параметр
  заменяется, если был; якорь сохраняется); иначе — содержимое
  ссылки текстом, а если текст не совпадает с адресом — ещё и адрес
  в скобках текстом, чтобы учитель видел, куда звали;
- свой отрисовщик картинки — подписью (`alt`), как в
  `ProblemTextRendering`: внешнюю картинку браузер загрузил бы сам;
- одиночный перевод строки — `<br>`: Помощник пишет списки шагов
  строками.

Возврат — адрес Разговора (`/assistant?conversation=N`), а не просто
`/assistant`: по умолчанию после полуночи показался бы пустой новый.
HTML готовит контроллер (это показ, не предметная логика) и кладёт
рядом с Репликой; шаблон выводит его `th:utext` — единственное место
`utext` на странице.

### Р8. Показ Реплики

Запрос — текстом с переводами строк; состояние — `badge` со словом
`TurnState.word()` и тоном `TurnState.tone()` (`info` — работаю,
`ok` — готово, `warn` — остановлено и прервано по шагам, `bad` —
остальные): тон даёт перечисление, шаблон только показывает. Причина —
у всех конечных, кроме «готово». Подсказка у «прервано по шагам»:
«Помощник исчерпал предел шагов. Напишите «продолжай», и он продолжит
в этом разговоре». Ход — `<details class="more">` «Ход: N вызовов»
со списком имён инструментов без префикса `mcp__locus__`
(`TurnStep.tool()`), аргументы — под именем мелким кодом. Итог —
«N токенов входа, M выхода · $0.0123», если итог был. Время начала —
`ЧЧ:ММ`.

### Р9. Пункт «Помощник» — в группе «Кабинет»

Разговоры — личные, значит пункт — в группе личного. Но страница
открыта и Администратору (`agent-runner`, «Уточнено при реализации»),
а «Кабинет» сейчас рисуется только Учителю. **Выбрано:** группа
«Кабинет» рисуется вошедшему с любой из двух ролей; пункты Учеников,
Групп, Заданий и Расписания внутри — только Учителю, «Помощник» —
обоим. Отвергнуто: отдельная группа «Помощник» — лишняя подпись
в тесной шапке телефона; пункт в «Админ» — путает общее и личное
цветом. `ShellAdvice.sectionOf` получает раздел `assistant`.

### Р10. Прежние Разговоры

`<details class="more">` «Прежние разговоры»: до 30 последних
Разговоров с Репликами, новые сверху, у каждого — дата и время
последней Реплики и начало первого запроса (до 80 знаков),
ссылка `?conversation=N`. Репозиторий — `conversationsOf(owner,
limit)` с `UserId`, запись `ConversationSummary`. Обрезка запроса —
в Java, не в шаблоне.

### Р11. Недоступный Помощник и пустое состояние

Недоступный: «Помощник недоступен: причина», без формы и без
«Новый разговор»; показанный Разговор и прежние читаются — данные
учителя не исчезают от того, что на стенде нет команды. Доступный —
строка «Claude Code X» мелко под заголовком остаётся (спека
`assistant-turns` требует «Помощник доступен»). Пустое состояние:
«Напишите, что сделать, — например, «найди задачи на теорему Виета»;
снимок листа можно приложить файлом» (вторая часть — только
у Администратора).

### Р12. Уровень версии — MINOR

**Под вопросом:** `MAJOR` по прецеденту `schedule` (новый раздел
шапки) или `MINOR`. **Выбрано `MINOR`:** у `schedule` `MAJOR` дала
новая область данных и новый заявленный сценарий целиком; здесь
данные построил `agent-runner` (MINOR), интерфейс прежний, а сценарий
«заводить задачи с листа» складывается целиком только с
`problem-intake` и `intake-skill`. Владелец может поднять уровень
при приёмке редакции.

## Risks / Trade-offs

- **Мигание раз в 3 с** на планшете, пока Помощник думает — принято
  карточкой; скрипт, подтягивающий ход фрагментом, — потом.
- **Обновление сбрасывает прокрутку** длинного Разговора. Смягчение:
  у идущей Реплики якорь `#turn-N`, переадресация после отправки
  ведёт на него, и `meta refresh` перечитывает тот же адрес с якорем.
- **Черновик при гонке** может остаться без Реплики (Р5) — уходит
  попутной уборкой; данных не портит.
- **Формат ответа Помощника** — чужой: Markdown без формул. Формулы
  `$…$` показываются как набраны; отрисовывать их на странице — новое
  решение, не сейчас.
