# Design

## Context

Сегодня Задача — запись `Problem` (`src/main/java/ru/locus/problem/Problem.java`):
номер, Часть, разметка и два ключа `FileKey` — PDF условия и PDF решения,
оба обязательны. Каждый PDF приходит в `ProblemService.create` /
`replaceCondition` / `replaceSolution` как `ProblemPdf` — готовый файл
(`UploadedFile`) или порядок сборки из Черновиков сборки
(`PdfAssemblyOrder`), который `ProblemService.resolved` превращает в байты.
Файлы кладутся в `FileStorage` до записи строки и убираются, если запись
не удалась. Страница просмотра показывает PDF картинками страниц
(`ru.locus.file.PdfPages.render`, ADR-0052). Заморозка — 
`ProblemService.refuseUnlessUnused`: Задача, вошедшая в Задание или
имеющая Работу, рукой не правится.

Текста Задача не знает — это и меняет изменение. Глоссарий уже описывает
результат: **Задача с текстом** (Текст Задачи `conditionText`,
`solutionText`; оба PDF — отрисовка) и **без текста**; **Улика**
(`evidence`) — снимок, с которого текст распознан. Инвариант 13
`domain-model.md`: у Задачи с текстом PDF всегда равен отрисовке текста.

**Где живут данные.** В **общей библиотеке**: текст и Улики — часть
Задачи. Меняет только Администратор (`@PreAuthorize` сервиса, как у всей
правки Задачи), читают все вошедшие, фильтра по владельцу нет
и `ProblemRepository` параметра `UserId` не получает (ADR-0027).

## Goals / Non-Goals

**Goals:**

- Задача с текстом заводится, правится и отрисовывается в те же слоты PDF;
  всё, что читает PDF Задачи (Задания, просмотр, `get_problem_page`),
  не меняется.
- Улика хранится и показывается на странице правки.
- Предпросмотр без обязательного скрипта; правка во внешнем редакторе
  файлом `.md` с проверкой версии.
- «Без текста» видно на странице Задачи, в списке Темы, в поиске числом.

**Non-Goals:**

- Инструменты помощника для текста — `problem-intake` (Черновик Задачи)
  и `backfill-skill` (запись текста существующей Задаче инструментом).
- Полнотекстовый поиск — отложен редакцией 3 с условием возврата.
- Перерисовка уже сохранённых PDF при смене отрисовщика.
- «Убрать текст» у Задачи с текстом: потребности не названо; Задачу без
  использования можно удалить и завести заново.
- Картинки внутри текста (`![…](…)`): внешних ресурсов отрисовщик
  не загружает (решение 1).

## Decisions

### Р1. Отрисовщик — внутри приложения: openhtmltopdf + CommonMark + JLaTeXMath

Выбор — [ADR-0058](../../context/adr/0058-otrisovshchik-teksta-zadachi-v-steke.md)
(Предложено; Typst, своя вёрстка на PDFBox, TeX Live и SnuggleTeX
отвергнуты там). Здесь — механика.

Чистая функция `ProblemTextRendering.render(String markdown) → byte[] PDF`
в пакете `ru.locus.problem`, без Spring и без состояния, как `PdfAssembly`:

1. **Формулы вынимаются до Markdown.** Обратная косая в Markdown —
   экранирование (`\{` становится `{`, `\\` — `\`), и формула, прошедшая
   через CommonMark, ломалась бы молча. Поэтому сначала текст проходится
   одним сканером: `$$…$$` — выключная формула, `$…$` — строчная, `\$` —
   знак доллара; каждая формула заменяется меткой-заполнителем,
   незакрытый `$` — отказ с номером строки.
2. **Markdown → XHTML** библиотекой CommonMark с `escapeHtml(true)`
   (сырой HTML выводится текстом), картинки выводятся своей подписью.
   Метки заменяются элементами формул (п. 4).
3. **Формула → `TeXIcon`** JLaTeXMath (`TeXFormula`, стиль
   `STYLE_TEXT` для строчной, `STYLE_DISPLAY` для выключной, размер
   по кеглю текста). `ParseException` — отказ
   `IllegalArgumentException` с самой формулой и причиной. Размеры иконки
   становятся шириной и высотой элемента, глубина — `vertical-align`,
   чтобы строчная формула стояла на базовой линии.
4. **Формула → маленький PDF → встроенный документ.** Иконка рисуется
   через Graphics2D поверх PDFBox (`PdfBoxGraphics2D`, приходит с
   openhtmltopdf) на одностраничный PDF своего размера — вектор, глифы
   контурами — и вставляется в строку элементом
   `<img src="data:application/pdf;base64,…">`: openhtmltopdf встраивает
   такой PDF формой, без загрузки ресурсов, по границам блока элемента.
   *Решено при реализации (пункт 1.3):* задуманный путь — `<object>`
   с собственным `FSObjectDrawer` и `drawWithGraphics` — проверку
   не прошёл: `PdfBoxObjectDrawerReplacedElement` openhtmltopdf 1.1.97
   рисует строчный объект по своей точке `point`, а не по границам блока,
   и формула оказывалась в начале абзаца под строкой (сдвиг на 11 пт
   по вертикали). Запасной путь через SVG отвергнут: он рисуется тем же
   способом (`PdfBoxSVGReplacedElement` тоже берёт `point`) и тянет Batik.
   Встроенный PDF рисуется `drawPdfAsImage` по `getContentAreaEdge`,
   как картинка; тест базовой линии сходится до сотых долей пункта.
5. **XHTML → PDF** openhtmltopdf: страница A4, поля, кегль и шрифт —
   в одной таблице стилей ресурсом рядом с классом.
6. **Ничего наружу.** `useUriResolver`/фабрика потоков отказывают любому
   адресу: текст пришёл от человека или модели, и `<img src>`
   или `@import` по чужому адресу превращали бы сохранение в запрос
   с сервера куда угодно.

Шрифт текста — **PT Serif** (ParaType, Open Font License, сделан для
кириллицы), четыре начертания в `src/main/resources/fonts/` вместе
с текстом лицензии; вшивается в каждый PDF. Кириллица в `\text{…}` —
`jlatexmath-font-cyrillic`. Предел текста — 20 000 знаков на слот
(константа записи `ProblemText`): решение на страницу — около 3 000,
предел ограничивает время отрисовки, а не учителя.

Версии зависимостей — не моложе двух недель. *Решено при реализации
(пункт 1.1):* версии openhtmltopdf на PDFBox 3.0.8 нет старше двух дней,
поэтому взята 1.1.97 на PDFBox 3.0.7; прямая зависимость проекта
`pdfbox` 3.0.8 по правилу Maven «ближайший выигрывает» главнее, копия
PDFBox одна, а `xmpbox` выровнен на 3.0.8 в `dependencyManagement`.
CommonMark — 0.30.0, JLaTeXMath — 1.0.7.

### Р2. Вид Задачи — оба текста или ни одного

Задача с текстом имеет **оба** текста, без текста — ни одного; половинчатой
(текст условия при приложенном PDF решения) нет. Так написано в глоссарии
(«оба PDF Локус отрисовывает из него сам») и так проще всем потребителям:
«с текстом» — одно булево свойство Задачи, а не пара. Решение, которое
учитель не хочет набирать, можно оставить снимком в Улике и написать
текстом коротко — вычитывать всё равно текст.

Отвергнуто — вид на каждый слот: две оси вместо одной в списках, поиске
и в будущем полнотекстовом поиске, без названной потребности.

### Р3. Хранение — колонки Задачи и вложенная запись `ProblemText`

Миграция `0015-problem-text`: в таблице Задач `condition_text`,
`solution_text` (`text`, пустые — `NULL`), `condition_evidence_key`,
`solution_evidence_key` и `text_version` (`integer not null default 0`).
Ограничения в базе: оба текста `NULL` либо оба нет; Улика не `NULL`
только при тексте. Отдельной таблицы нет: текст — часть Задачи один
к одному.

В коде `Problem` получает поле `ProblemText text` (`null` — без текста)
и метод `hasText()`; `ProblemText(String condition, String solution,
FileKey conditionEvidence, FileKey solutionEvidence, int version)` —
правила состава в компактном конструкторе (оба текста не пусты после
отсечения пробелов, не длиннее предела), как у `Problem`.

**«Без текста» не хранится** — нет ни флага, ни колонки вида; состояние —
отсутствие текста. Сторожит `TextlessIsNotStoredTest` (того же рода, что
`NotSubmittedIsNotStoredTest` и `NoSingleMasteryValueTest`): в схеме нет
колонки вида, а `Problem` не принимает признака в обход текста.

### Р4. Улика — у каждого слота, из того же поля слота

У слота Задачи с текстом поле файла (ADR-0049: нетронутый PDF — как есть,
рамки и картинки — сборка) даёт **Улику этого слота**, а не PDF слота:
PDF слота — всегда отрисовка. Улика необязательна (текст, набранный
рукой, снимка не имеет). Улика на слот, а не одна на Задачу, — потому что
у `backfill-skill` прежних PDF два и оба становятся уликами своих слотов,
а у помощника рамки условия и решения различны.

Показывается на странице правки ссылкой на страницу просмотра файла
картинками (ADR-0052), с теми же правилами доступа, что у PDF Задачи
(читают все вошедшие). В Задание не уходит: Задание ссылается на Задачу,
а файлы Задачи для Задания — по-прежнему условие и решение.

На странице правки Улику слота можно **заменить** (тот же блок замены
файла, что у Задачи без текста); снять — нельзя (Non-Goals).

### Р5. Записать текст Задаче без текста — прежние PDF становятся Уликами

На странице правки Задачи без текста — блок «Записать текст» с двумя
полями. Сохранение отрисовывает оба PDF в слоты, а прежние приложенные
PDF переходят в Улики своих слотов без копирования (ключ `FileKey`
переезжает в колонку Улики). Так требует карточка `backfill-skill`
(«прежний PDF становится уликой»), и тот же сервисный метод она обернёт
инструментом.

### Р6. Заморозка держится и для текста; опечатка в выданной — новая Задача

Под вопросом было (ADR-0055, п. 6): правка опечатки в тексте Задачи,
уже выданной ученику. Варианты: (а) заморозка как есть — текст выданной
не правится, исправленная Задача заводится новой; (б) правка текста
выданной разрешена; (в) разрешена правка «без изменения смысла».
Выбрано (а) — по умолчанию карточки и ADR-0030: ученик держит прежний
PDF, а Работа проверяется по Задаче — изменённый текст разошёлся бы
с тем, что ученик решал, и тихо. (в) системе невычислимо: она не понимает
текста (ADR-0055, п. 4). Путь для опечатки — скачать `.md` выданной
и завести новую Задачу; отказ правки называет этот путь.

Заморозка закрывает правку текста формой, загрузку `.md`, «Записать
текст» и замену Улики — всё, что меняет Задачу рукой. Скачивание `.md`
и предпросмотр — чтение, им заморозка не мешает.

### Р7. Версия текста — счётчик, проверяемый при каждой правке текста

`text_version` растёт на каждой записи текста. Страница правки несёт
прочитанную версию скрытым полем; правка формой и загрузка `.md`
с версией, отличной от хранимой, отклоняются: «Текст Задачи изменился
после того, как открыта страница, — перечитайте её». Это ловит то, о чём
владелец сказал при решении 24.10.2026: `.md` скачан, правится в Obsidian,
а тем временем текст поменял другой Администратор (а позже — помощник).

Отвергнут отпечаток содержимого (хеш прочитанного текста): равносилен,
но счётчик — тот же механизм, что ляжет на Черновик Задачи
в `problem-intake`, и одно правило проще двух.

### Р8. Обмен файлом `.md` — по слоту

`GET /problems/{id}/condition.md` и `…/solution.md` отдают текст слота
как `text/markdown; charset=UTF-8` с `Content-Disposition: attachment`
и именем вида «Задача 417 — условие.md» (имя называет обработчик сам —
антипаттерн «отдача файла без своего `Content-Disposition`»). Загрузка —
`POST` на тот же адрес, файл и версия: UTF-8 (метка порядка байтов
снимается), не длиннее предела; заменяет текст **своего** слота
и перерисовывает только его. Один файл на два текста отвергнут: деление
файла на условие и решение было бы разбором записи по заголовкам,
который учителю пришлось бы соблюдать руками.

### Р9. Предпросмотр — кнопка формы на сервер, картинки в той же странице

Кнопка «Предпросмотр» — `formaction` той же формы на
`POST /problems/preview` (заведение) и `POST /problems/{id}/text/preview`
(правка): скрипт не нужен. Обработчик отрисовывает оба текста в памяти,
ничего не сохраняя, и возвращает ту же форму с введённым (как при отказе,
`problem-form-keeps-input`) и страницами отрисовки картинками
`PdfPages.render`, вставленными адресами `data:` — превью не хранится
и ссылок на себя не имеет. Отказ отрисовки (неразбираемая формула)
показывается на месте предпросмотра. Черновики сборки в полях слотов
живут сами и переживают предпросмотр; готовый файл, выбранный в поле
без скрипта, браузер при повторном показе формы не сохраняет — это
сказано подсказкой у кнопки.

### Р10. Порядок отрисовки и укладки

Отрисовка — **до** обращения к хранилищу, после проверки разметки:
неразбираемая формула отказывает, ничего не положив. Затем, как у
`create`: положить файлы (отрисовки и Улики), записать строку, при сбое
записи убрать положенное. При правке текста прежний отрисованный PDF
слота удаляется после записи — как заменённый файл сегодня.

### Р11. «Без текста» в списках и поиске

`FoundProblem` и строка списка Темы получают `hasText`; шаблоны
показывают пометку «без текста» по готовому свойству (логики в шаблоне
нет). Результат поиска называет «из них без текста — N»; число считает
контроллер по найденному, а не отдельный запрос. Страница Задачи — та же
пометка, у Задачи с текстом — ссылки на `.md`.

## Risks / Trade-offs

- [JLaTeXMath поддерживает не всё LaTeX] → неподдержанное отказывает
  при предпросмотре и сохранении с названием формулы; набор окружений
  ЕГЭ (`\frac`, `\sqrt`, `\log`, `cases`, `array`) проверяется тестом
  отрисовки. Если реальные решения упрутся — ADR-0058 заменяется
  Typst, тексты остаются.
- [Строчная формула не на базовой линии] → проверочный тест первым пунктом
  и запасной путь через SVG (Р1).
- [Первая отрисовка медленная — загрузка шрифтов JLaTeXMath] → однократно
  на процесс; отрисовка идёт только при сохранении и предпросмотре.
- [Размер страницы предпросмотра с двадцатью картинками `data:`] →
  тот же предел `PdfPages.SHOWN`, решение на страницу — одна-две
  страницы.
- [Лицензии] → openhtmltopdf — LGPL, JLaTeXMath — GPL с исключением
  для связывания, PT Serif — OFL; приложение не распространяется,
  работает на стенде владельца.
- [Отрисованный PDF устаревает при смене библиотек] → принято (ADR-0058,
  «Последствия»): хранится файлом, перерисовывается при правке текста.

## Migration Plan

Миграция `0015-problem-text` добавляет колонки и ограничения; существующие
Задачи получают `NULL` — без текста, — `text_version` = 0. Данных миграция
не меняет, откатного скрипта нет (ADR-0023). Стенду ничего не ставится.
