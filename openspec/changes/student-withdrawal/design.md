# Design

## Context

Ученик (`ru.locus.student.Student`, `Student.java:23`) сегодня — запись
из идентификатора, владельца и имени, без какого-либо состояния. Ведение
идёт через `StudentService` → `StudentRepository` (чистый JDBC, без ORM,
как весь проект). Список для выбора адресата используется в двух местах:
`StudentController.renderList` (`/students`) и
`AssignmentController.renderForm` (`/assignments/new`), оба зовут
`StudentService.all()`.

Выдача Группе устроена как один сервисный метод
`AssignmentService.issueToGroup`, который берёт состав Группы через
`GroupService.members` и создаёт по одному Заданию на каждого — код
не читал (это `apply`), но по спецификации `assignments` («Раздача
выдаётся Группе одним действием») понятно, что фильтрация состава должна
произойти до создания Заданий, а не после.

Данные — личный контур Учителя (Ученики), фильтруются по владельцу как
сейчас; это предложение не трогает границу общего и личного, а добавляет
состояние внутри уже личной записи.

## Goals / Non-Goals

**Goals:**
- Флаг «выбыл» у Ученика с переключением в обе стороны.
- Список Учеников и выбор адресата при прямой выдаче скрывают выбывших
  по умолчанию.
- Выдача Группе пропускает выбывших членов, не трогая состав Группы.

**Non-Goals:**
- Каскад выбытия на членство в Группах — состав не меняется.
- История выбытий (когда и сколько раз) — хранится только текущее
  состояние, по аналогии с отметками Владения (ADR-0039).
- Изменение `/works` и `/mastery`: их фильтр по Ученику — обращение
  к уже существующей истории, а не выбор адресата, и выбывшего должен
  находить как прежде.

## Decisions

### Состояние — булево поле на Ученике, а не отдельная сущность

Флаг `withdrawn boolean not null default false` в таблице `student`.
Альтернатива — отдельная таблица «выбывшие» — отвергнута: состояние
принадлежит ровно одной записи и не имеет собственных атрибутов
(в отличие, например, от отметки Владения, у которой есть значение
и пара «Тема × Метод»); отдельная таблица добавила бы join без пользы.
Предпочтение владельца ADR-0035 «заводить флаг «выбыл»» уже называет
именно эту форму.

### Список — один экран с переключателем, а не отдельный адрес

`/students` без параметра показывает действующих; `/students?withdrawn`
— выбывших. Тот же паттерн уже используется в `/assignments` (параметры
отбора в адресе). Альтернатива «отдельный список выбывших» (развилка «б»
из карточки бэклога) отклонена: два независимых экрана держали бы два
шаблона почти без различий и два маршрута, тогда как разница — только
в условии `WHERE` и подписи страницы.

### Фильтрация — на уровне репозитория, а не сервиса

`StudentRepository.findAll(UserId owner, boolean withdrawn)`: один метод
с явным параметром, а не два метода `active`/`withdrawn` — фильтр всего
один бит, и разветвление в SQL проще держать в одном месте. Метод без
владельца по-прежнему не существует (ADR-0027).

### Выдача одному Ученику — отказ на уровне сервиса, не только сокрытие в форме

Форма прячет выбывших из списка, но `AssignmentService.issueToStudent`
дополнительно проверяет состояние и отклоняет прямую выдачу
(по аналогии с тем, как чужой Ученик отклоняется независимо от того,
показан ли он в форме — тот же принцип, что уже применён во всех местах
границы личного контура). Без этой проверки прямой POST-запрос
с идентификатором выбывшего обошёл бы правило.

### Выдача Группе — фильтрация состава перед созданием Заданий

`AssignmentService.issueToGroup` получает состав Группы, отбрасывает
выбывших **до** проверки «Группа пуста» и создания Заданий: пустой
результат после отбора обрабатывается тем же путём, что пустая Группа,
с отдельным текстом причины («ни одного действующего Ученика»). Раздача
создаётся только если после фильтрации остался хотя бы один Ученик.

### Глоссарий

Термин «выбытие» / состояние «выбыл» новый и добавляется
в `openspec/context/glossary.md` в блок «Личный контур» строкой
у термина «Ученик» — это правка формулировки словаря вслед за принятым
решением, не отдельный цикл (`CLAUDE.md`, «Документы проекта —
исходники»).

## Risks / Trade-offs

- [Забытое место, где список Учеников должен, но не будет фильтровать
  выбывших] → единственный сервисный метод `StudentService.all()`
  используется в форме выдачи и в списке; оба перечислены выше, других
  потребителей нет (`find_referencing_symbols` перед правкой сигнатуры
  подтвердит это на шаге реализации).
- [Прямой POST выдачи выбывшему в обход формы] → закрыт проверкой
  в `AssignmentService`, а не только в контроллере (симметрично тому,
  как уже проверяется владелец).

## Migration Plan

Одна миграция Liquibase `0010-student-withdrawal.yaml`: `addColumn`
`withdrawn boolean not null default false` на `student`. Отката назад
не требуется сверх стандартного (ADR-0023, откатных скриптов нет).
Существующие Ученики получают значение по умолчанию — все остаются
действующими, поведение списков не меняется для уже заведённых карточек.
