## Context

Метод очереди сейчас разнесён по трём местам, и ни одно не проверяется:

- личный навык `~/.claude/skills/backlog-maintenance/SKILL.md` версии 1.1 —
  метод для очереди дефектов библиотеки: ключ «класс → стоимость → связи →
  ломающесть» (`SKILL.md:48`), связи прозой в карточке (`SKILL.md:103`),
  один статус ✅ (`SKILL.md:113`), поля «Доказательство», «Цена», «Подходы»
  (`SKILL.md:94–99`). Номеров у элементов в нём уже нет (§5) — эта часть
  карточки снята раньше;
- `openspec/backlog.md`, разделы 1–2 — фактический метод Локуса: две колонки
  дуг, порядок как система ограничений, семь значений «Статуса», таблица
  «Чем эта очередь отличается от типовой» с пятью адаптациями;
- `CLAUDE.md`, «Ведение бэклога», — пересказ тех же дуг одним абзацем
  с объявлением, что навык — «единственный источник правил».

Вторая копия навыка, `~/projects/opentest-skills/.claude/skills/backlog-maintenance/`,
разошлась с первой (номера элементов, раздел про `backlog-grooming`). Каталог
личных навыков не под контролем версий.

Ограничения, найденные при разведке:

- **Личный навык перекрывает проектный с тем же именем.** Документация
  Claude Code (`code.claude.com/docs/en/skills`, «Resolve skills that share
  a name»): «Enterprise over personal, and personal over project. With
  `deploy` in both `~/.claude/skills/` and the project's `.claude/skills/`,
  `/deploy` runs the personal one».
- **Хуки не останавливают ни правку, ни сессию.** Документация хуков
  (`code.claude.com/docs/en/hooks`): у `PostToolUse` код 2 «Shows stderr
  to Claude; the tool already ran»; у `SessionStart` код 2 «Shows stderr
  to user only», а обычный вывод (stdout) при коде 0 «adds plain-text stdout
  as context that Claude can see». Корень проекта — `$CLAUDE_PROJECT_DIR`.
- **Таблицу порядка разбирает по позициям колонок** пусковой скрипт батча
  (`.claude/backlog-batch/locus-backlog`, функция `next_item`): восемь
  колонок, ID — первая, «Зависимость» — третья, «Статус» — восьмая,
  заголовок раздела — `## 3. Таблица порядка`. Формат таблицы менять нельзя
  без правки скрипта; он и не меняется.
- **Сессия батча ссылается на раздел 1 бэклога** за правилом выбора
  и значениями «Статуса» (`.claude/backlog-batch/task-prompt.md:41`,
  `:172`, `:195`).
- Разведка прототипом проверялки на текущем файле: 51 строка и 51 карточка,
  ID совпадают; порядок карточек расходится с таблицей начиная
  с `back-link-gaps` (карточка `problem-form-unsaved-warning` стоит раньше
  `back-link-gaps` и `intake-tabs`); у двенадцати строк со статусом ✅
  карточка не начинается отметкой о закрытии (у части её нет вовсе,
  у `schedule` выше неё стоит пометка о возврате, у `silent-failure-principle`
  она «Закрыто», а не «Выполнено»); в заголовке `deployment-backup` стоит
  статус «отменено».

## Goals / Non-Goals

**Goals:**

- метод очереди записан в одном месте — личном навыке, общем для проектов,
  и это место описывает и очередь Локуса, и очередь дефектов;
- навык не предписывает хранить порядок дважды, а его правило даёт
  проверяемый результат на очереди с ничьими: проверяется не «почему именно
  здесь», а «не нарушена ли дуга»;
- навык, начиная работу, узнаёт, совместим ли с ним бэклог, и не правит
  несовместимый без согласия пользователя;
- раздел инвариантов позволяет проверить чужой `backlog.md`, не зная его
  истории;
- сломанный формат в Локусе виден в тот же ход правки и в начале сессии.

**Non-Goals:**

- проверка в сборке `mvn` — решение владельца от 08.09.2026 (карточка,
  «Связи»): проверка уведомляет, но не запрещает;
- миграция бэклога `opentest-skills` и правка тамошней копии навыка:
  это другой проект, миграцию там предложит сам навык при первой работе;
- перенос в навык раздела про `backlog-grooming` из копии `opentest-skills`:
  парного навыка груминга среди личных нет;
- уборка выполненных элементов (§6 навыка) по всей таблице — остаётся
  обычной процедурой при закрытии элементов;
- изменение колонок таблицы порядка Локуса.

## Decisions

### Один универсальный навык вместо проектной копии

Решение владельца 26.10.2026 (ответ на гейте): навык доработать
и сделать универсальным. Прежний вариант предложения — проектный форк
`locus-backlog-maintenance` — отклонён им и записан в ADR-0062 среди
отвергнутых. Правится `~/.claude/skills/backlog-maintenance/SKILL.md`,
версия навыка 1.1 → 2.0, в шапке `metadata.format: 2`.

Универсальность выражена так: очередь дефектов без дуг — частный случай
очереди с дугами (колонки дуг пусты, порядок задают ключи предпочтения);
карточка — одного из двух видов, а поля, общие для обоих (доменный
инвариант, связи, признак готовности), обязательны всегда; колонка
доменного инварианта называется по проекту, проверялка её содержимое
не читает.

### Номер формата и миграция по согласию

Номер — строка `<!-- backlog-format: N -->` в шапке файла: Markdown её
не показывает, а скрипт находит одной регуляркой. Формат 1 — всё, что
без строки (как и бэклог Локуса до этого изменения). Процедура старта
навыка: прогнать `check_backlog.py`; по коду возврата — работать,
предложить миграцию или остановиться. Миграция записана в навыке шагами
1 → 2 и выполняется отдельным коммитом, не смешиваясь с правкой,
ради которой навык позвали. Нарушения инвариантов при совпадающем номере
миграцией не считаются — они чинятся обычной правкой (с тем же вопросом
пользователю, если их много).

Батч Локуса работает без человека, но вопрос миграции в нём не возникнет:
этим изменением бэклог Локуса переводится в формат 2. Если формат когда-то
поднимется снова, правило вопросов батча и так велит спросить владельца,
когда навык требует согласия.

### Заголовок карточки — зеркало строки таблицы, истина — таблица

Развилка карточки: что делать с заголовком, дублирующим класс, стоимость
и ломающесть, — убрать поля, объявить истиной таблицу или оставить как есть.
Предпочтительный в карточке не помечен; выбор сделан по правилу вопросов
батча. Выбрано **«истина — таблица, заголовок — зеркало, сверяемое
проверялкой»**. Довод: дубль вреден, пока он молчит; проверялка делает
расхождение видимым, а заголовок сохраняет то, ради чего он есть, —
карточку можно читать, не возвращаясь к таблице. Убрать поля — значит
переписать пятьдесят один заголовок и потерять эту читаемость ради
дефекта, который проверка и так закрывает. «Оставить как есть» не годится:
без сверки дубль разъедется. Номера в заголовке нет уже сейчас.

Соответствие зеркала: класс `—` в таблице — класса в заголовке нет; «Ломает»
`нет` — `не ломает`, `**да**` — `**ломает**`; после этих полей допустима
пометка о том, что элемент затрагивает (`· тексты и состав меток`).

### Отметка о закрытии — первая строка карточки, двух видов

В файле встречаются «> ✅ Выполнено ДД.ММ.ГГГГ. Change: …», «> ✅ Закрыто
ДД.ММ.ГГГГ — отклонено…», отметка ниже пометки о возврате и её отсутствие.
Выбрано: **строка со статусом ✅ — карточка начинается блок-цитатой
«✅ Выполнено ДД.ММ.ГГГГ. Change: [ссылка на архив]» либо, для закрытого
без изменения, «✅ Закрыто ДД.ММ.ГГГГ без изменения»**; прочие пометки
идут после неё; у строки без ✅ отметки о закрытии нет. Два вида оставлены
потому, что закрытие без изменения — законный исход: такая карточка —
единственная запись решения, и ссылки на архив у неё нет. Недостающие
отметки дописываются датой и ссылкой по папке архива; резюме подхода
желательно, но обязательной частью конвенции не делается — восстанавливать
его задним числом по двенадцати архивам значит сочинять, а не записывать.

### Значения «Статуса»

В навык переносятся все семь значений Локуса: пусто, `отложено`,
`ждёт условия`, `построено`, `на стенде`, `отменено`, ✅. `построено`
и `на стенде` описываются в общем виде — «слито, признак готовности —
приёмка на стенде; не выкачено / выкачено»; кто и когда переводит строки
в Локусе (управляющая сессия после выкатки), остаётся фактом очереди
в разделе 1 бэклога. Проект без стенда эти значения просто не использует.

### Инварианты: что проверяет скрипт, что — чтение

| Инвариант | Кто проверяет |
| --- | --- |
| каждый ID в дугах — строка таблицы или изменение в архиве | скрипт |
| «Зависимость» на строку таблицы — выше, «Не позже» — ниже | скрипт |
| строки и карточки взаимно однозначны и в одном порядке; заголовок — зеркало строки | скрипт |
| статуса в заголовке нет; отметка о закрытии — по конвенции выше | скрипт |
| ни одна дуга не записана прозой | чтение |
| вычислимое не хранится: «Статус» — одно из семи значений, колонок восемь | скрипт |

Дуга, указывающая на ID вне таблицы, законна, если у этого ID есть архив:
это выполненная и уже убранная работа (`project-skeleton`, `agent-runner`,
`interface-focus`) — так же её понимает `next_item`. Дугу прозой скрипт
не ищет: «Связи» вправе называть элементы по содержанию, а образцы фраз
ловили бы и законное. Номер формата скрипт проверяет первым и при
несовпадении дальше не идёт.

### Проверялка и хуки

Скрипт — `~/.claude/skills/backlog-maintenance/check_backlog.py`, рядом
с навыком: метод и его проверка правятся вместе, номер формата записан
в обоих. Образец — `build_index.py`: только стандартная библиотека Python,
путь к бэклогу аргументом (по умолчанию `openspec/backlog.md` от текущего
каталога), коды возврата: 0 — чисто, 1 — нарушения, 3 — формат младше
навыка или не указан, 4 — формат старше.

Хуки Локуса (`.claude/settings.json`) зовут скрипт по пути
`$HOME/.claude/skills/backlog-maintenance/check_backlog.py`.
`PostToolUse` с сопоставителем `Edit|Write|MultiEdit|Bash` — режим `--hook`:
скрипт читает вход хука и проверяет файл, только если в `tool_input`
встречается `openspec/backlog.md` (так ловится и правка через оболочку);
нарушения — в stderr с кодом 2, Claude видит их сразу. `SessionStart`
без сопоставителя — режим `--session-start`: нарушения в stdout с кодом 0,
чтобы попасть в контекст Claude. Чистый файл — ни слова. Нет скрипта
по этому пути — хук говорит об этом, а не молчит. Под вопросом было,
держать ли хуки при проверке на старте навыка; оставлены: старт навыка
ловит несовместимость, а не опечатку в правке, сделанной без навыка.

## Граница общего и личного

Не затрагивает. Данных у изменения нет: правятся навык, документ очереди,
`CLAUDE.md` и оснастка Claude Code. Фильтра по владельцу, прав на изменение
и места хранения в общей библиотеке или личном контуре здесь не возникает.
Доменная модель и архитектура (`domain-model.md`, `architecture.md`)
не меняются; антипаттерны (`antipatterns.md`, «Оснастка и среда») прямо
не задеты, но решение следует их духу: «записанное дважды разъезжается»
и «то, что не роняет сборку в момент причины».

## Risks / Trade-offs

- **Хук не запрещает** — сломанный формат можно закоммитить, если не читать
  вывод. Принято владельцем 08.09.2026; роняет работу только тест сборки,
  а его не берём.
- **Навык вне контроля версий** — правка `~/.claude/skills/` не попадает
  в историю Локуса и не откатывается `git`. Прежняя редакция 1.1 сохранена
  в копии `opentest-skills` (почти совпадает) и в выводе этой сессии;
  в коммитах Локуса правка названа словами.
- **Хуки Локуса зависят от файла вне репозитория** — на машине без навыка
  проверка не идёт, но хук это называет.
- **Навык меняется для всех проектов** — бэклог другого проекта формата 1
  при первой работе получит вопрос о миграции, а не молчаливую правку.
- **Хук на каждый вызов оболочки** — запуск Python на каждой команде `Bash`.
  Скрипт выходит сразу, если в вызове нет `openspec/backlog.md`; цена —
  десятки миллисекунд.
- **Дуга прозой проверяется только чтением** — инвариант, который скрипт
  не ловит, может сломаться тихо. Записан в навыке явно как проверка
  чтением, чтобы не создавать видимости автоматической проверки.
