# Design

## Context

Мотив — proposal.md, «Why». Сейчас:

- Форму выдачи `/assignments/new` строит `AssignmentController.renderForm`
  (`AssignmentController.java:185-191`): Задачи — `ProblemService.problems`
  (`FoundProblem`, номер и разметка именами), Ученики — `StudentService.active`,
  Группы — `GroupService.all`. Шаблон `templates/assignment/form.html:44-56`
  выводит у каждой Задачи номер, Часть и три строки разметки `.marks`.
- Задания лежат в `assignment` (Ученик, Раздача или `null`, дата выдачи
  `issued_on`), состав — в `assignment_problem`, владелец записан в каждой
  строке обеих таблиц. Раздача (`assignment_batch`) помнит имя Группы
  текстом `group_name` и свою дату выдачи (ADR-0016, ADR-0035): Группа
  удаляется в любой момент, имя на момент выдачи — исторический факт.
- Ученик с Заданием не удаляется (ADR-0035), поэтому имя Ученика
  у личной выдачи всегда есть; выбывший Ученик остаётся в базе с именем
  (ADR-0040).
- Единственный метод `AssignmentRepository` без владельца —
  `countByProblem` (класс ADR-0036, ответ библиотеке); для подсказки
  он не годится: посчитал бы Задания всех Учителей и ничего не сказал бы
  об адресате.

Где живут данные: **личный контур**. Подсказка читает Задания и Раздачи
вошедшего Учителя и ничего не пишет; менять их по-прежнему может только
он сам прежними операциями. Фильтр по владельцу — в каждом SQL нового
метода (ADR-0027). Задачи формы — общая библиотека, их выборка прежняя
и без владельца.

## Goals / Non-Goals

**Goals:**

- У каждой выбранной Задачи на форме выдачи — кому и когда её выдавал
  вошедший Учитель; выдача Раздачей — одной строкой, сколько бы в ней
  ни было Учеников.
- Ничего не видно о выдачах других Учителей — ни имён, ни числа.

**Non-Goals:**

- Отказ или подтверждение при повторе — отклонено владельцем в карточке.
- Показ только выбранному адресату — адресат выбирается на той же форме,
  без скрипта до отправки неизвестен (карточка, «Развилки»).
- Подсказка на странице поиска `/problems` и на странице Задачи —
  карточка называет только форму выдачи.
- Ссылки на прежние Задание и Раздачу из строки — повтор лечится
  удалением Раздачи на её странице, а дойти до неё можно из сводки;
  ссылки удлинили бы строку на телефоне. Если окажутся нужны — дефект
  по отзыву.

## Decisions

### 1. Прежняя выдача — запись области `PriorIssue`, один запрос на форму

Новый тип `ru.locus.assignment.PriorIssue` — запись «Задача, дата выдачи,
адресат текстом, Раздача ли это». Новый метод
`AssignmentRepository.findPriorIssues(UserId owner, Collection<ProblemId> problems)`
отдаёт их одним запросом на все Задачи формы, двумя ветками `union all`:

- выдачи Раздачей — `assignment_problem` → `assignment` → `assignment_batch`,
  сгруппированные по паре «Задача × Раздача»: Раздача на двенадцать
  Учеников — одна выдача, а не двенадцать; адресат — `group_name`,
  дата — `issued_on` Раздачи;
- личные выдачи — `assignment` без Раздачи → `student` по составному
  ключу `(id, user_id)`; адресат — имя Ученика, дата — `issued_on`
  Задания.

В каждой ветке `user_id = ?` на каждой таблице. Порядок — дата выдачи
по убыванию, затем идентификатор по убыванию (Раздачи и Задания нумеруются
разными последовательностями, поэтому сначала вид, затем номер — порядок
внутри дня устойчив от чтения к чтению, этого достаточно).

*Отвергнуто:* читать `AssignmentRepository.find` по владельцу и фильтровать
в сервисе — читает все Задания Учителя ради нескольких Задач; запрос
на каждую Задачу — N запросов на форму. Имя Ученика брать у
`StudentService` по идентификатору — запрос на каждую личную выдачу,
а составной ключ и так даёт соединение без чужих строк.

### 2. Сжатие — три новейшие и «и ещё N»

Учитель смотрит строку, чтобы заметить случайный повтор, а случайный
повтор — почти всегда недавний (сеанс 25.10.2026: семь минут между
Раздачами). Поэтому строка называет **три новейшие** выдачи и число
остальных: «Уже выдана: «9Б» — 25.10.2026; Иванов Пётр — 20.10.2026;
«А+У» — 12.10.2026 и ещё 2». Группа — в кавычках «», как в сводке
(`list.html:62`), Ученик — без кавычек: так их различает глаз без слов
«Группе»/«Ученику» и без склонения имён.

Сжатие считает сервис: `AssignmentService.priorIssues(List<ProblemId>)`
отдаёт `Map<ProblemId, PriorIssues>`, где `PriorIssues` — запись
«показанные (до трёх) и сколько ещё». Предел — константа сервиса.
Шаблон только выводит.

*Отвергнуто:* свёртка `<details>` со всеми выдачами — лишнее нажатие
ради редкого случая и ещё один раскрывающийся блок в форме, где их нет;
все выдачи без предела — у регулярно выдаваемой Задачи строка
разрастается на телефоне.

### 3. Где проверяются права

`AssignmentService.priorIssues` — `@PreAuthorize("hasRole('TEACHER')")`,
как вся область; владелец — `CurrentUser`, из запроса не читается.
Контроллер зовёт её в `renderForm` после того, как Задачи прочитаны,
и кладёт в модель `priorIssues` как есть, с ключом `ProblemId`: шаблон
берёт строку `priorIssues.get(problem.problem.id)` — запись сравнивается
по значению, и перекладывать ключи в контроллере незачем. Подпись одной
выдачи («9Б» — 25.10.2026) собирает `PriorIssue.label()`, чтобы шаблон
выводил строку одним `th:text`, а не склеивал её из кусков.
Пустой список Задач — пустой ответ без запроса.

### 4. Вид строки

`<p class="marks marks--repeat">` под строками разметки: цвет
`--warn`, как у `badge--warn`, — строка должна заметиться, но это
не ошибка. Правило — в `locus.css` (ADR-0041), своих стилей шаблон
не заводит.

## Risks / Trade-offs

- **Две Раздачи одного дня одной Группе выглядят одинаково** — «9Б» —
  25.10.2026» дважды. Это и есть сигнал повтора, ради которого строка
  заведена; время выдачи не хранится (`issued_on` — дата), и заводить
  его ради подсказки — не в объёме.
- **Удалённая Группа** называется прежним именем — так же, как на странице
  Раздачи; это исторический факт, а не ошибка.
- **Выбывший Ученик** называется в строке без пометки: выдача ему была,
  а пометка «выбыл» — забота его карточки и сводки.
