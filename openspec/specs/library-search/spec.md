## Purpose

Поиск Задач по разметке: отбор по узлу рубрикатора с обходом поддерева,
по Методам, Характеристикам и Части. Текста Задачи система не знает, поэтому
разметка — единственный вход в библиотеку, а поиск по ней — единственный
способ найти Задачу, не обходя дерево руками.

## Requirements

### Requirement: Поиск отбирает Задачи по четырём условиям

Система SHALL отбирать Задачи общей библиотеки по четырём условиям:

| Условие | Значений | Что отбирает |
| --- | --- | --- |
| Узел рубрикатора | не более одного | Задачи, размеченные Темами поддерева этого узла |
| Метод | любое число | Задачи, размеченные выбранными Методами |
| Характеристика | любое число | Задачи, размеченные выбранными Характеристиками |
| Часть | не более одной | Задачи этой Части |

Каждое условие необязательно. Заданные условия соединяются по «и»: Задача
попадает в результат, только если удовлетворяет всем заданным сразу.
Переключателя у соединения **разных** условий нет: они отвечают за разные
измерения разметки.

Узел и Часть берут не более одного значения
([ADR-0031](../../context/adr/0031-uslovija-poiska-po-biblioteke.md)):
множество Тем поддерева вычисляет система, а не набирает учитель, а у Задачи
ровно одна Часть.

#### Scenario: Условия соединяются по «и»

- **WHEN** заданы Метод и Часть
- **THEN** возвращаются только Задачи, размеченные этим Методом **и**
  относящиеся к этой Части
- **AND** Задача, у которой совпало лишь одно из двух, не возвращается

#### Scenario: Одно условие

- **WHEN** задана только Характеристика
- **THEN** возвращаются все Задачи библиотеки, размеченные этой
  Характеристикой, независимо от их Тем, Методов и Части

#### Scenario: Условий не задано

- **WHEN** поиск запускается без единого условия
- **THEN** возвращаются все Задачи библиотеки

#### Scenario: Ничего не найдено

- **WHEN** условиям не удовлетворяет ни одна Задача
- **THEN** результат пуст
- **AND** сообщается, что по этим условиям Задач нет

### Requirement: Способ соединения значений внутри условия выбирает учитель

Система SHALL позволять указать в условии по Методу и в условии
по Характеристике **любое число** значений и SHALL для каждого из этих двух
условий отдельно принимать способ их соединения:

| Способ | Значение | Отбирает |
| --- | --- | --- |
| все сразу | `ALL` | Задачи, размеченные **каждым** выбранным значением |
| любое из | `ANY` | Задачи, размеченные **хотя бы одним** выбранным значением |

Способ SHALL быть виден на экране рядом со своим условием, и по умолчанию
SHALL быть выбрано «любое из». Умолчание выбрано расширяющее: оно может
показать лишнее — это видно и поправимо, — тогда как сужающее показало бы
меньше, чем есть, и это не видно вовсе.

Способ выбирается для каждого из двух условий **независимо**: у Методов
может стоять «все сразу», у Характеристик — «любое из».

Условие с **пустым** набором значений условием не является и на отбор
не влияет — независимо от выбранного способа. Разница между «условия нет»
и «условие из пустого набора» MUST разбираться системой: понятое буквально,
«все сразу» из нуля значений истинно для всякой Задачи, а «любое из» из нуля
значений — ложно для всякой, и учитель этой разницы не видит
([ADR-0031](../../context/adr/0031-uslovija-poiska-po-biblioteke.md)).

#### Scenario: Все сразу

- **WHEN** выбраны два Метода со способом «все сразу»
- **THEN** возвращаются только Задачи, размеченные обоими Методами
- **AND** Задача, размеченная лишь одним из них, не возвращается

#### Scenario: Любое из

- **WHEN** выбраны два Метода со способом «любое из»
- **THEN** возвращаются Задачи, размеченные любым из этих Методов
- **AND** Задача, размеченная обоими, возвращается один раз

#### Scenario: Способы у Методов и Характеристик независимы

- **WHEN** у Методов выбрано «все сразу», а у Характеристик — «любое из»
- **THEN** возвращаются Задачи, размеченные всеми выбранными Методами
  и хотя бы одной из выбранных Характеристик

#### Scenario: Одно выбранное значение

- **WHEN** выбран ровно один Метод
- **THEN** результат одинаков при «все сразу» и при «любое из»

#### Scenario: Ни одного выбранного значения

- **WHEN** не выбрано ни одного Метода
- **THEN** условие по Методу на отбор не влияет ни при «все сразу»,
  ни при «любое из»
- **AND** результат совпадает с результатом поиска, где условия по Методу
  нет вовсе

#### Scenario: Способ по умолчанию

- **WHEN** экран поиска открывается впервые
- **THEN** у обоих условий выбрано «любое из»

### Requirement: Отбор по узлу идёт с обходом поддерева

Система SHALL при отборе по узлу рубрикатора возвращать Задачи, размеченные
любой Темой поддерева этого узла на **любой** глубине, включая сам узел, если
он Тема (инвариант 10, [domain-model.md](../../context/domain-model.md)).

Обход обязателен, а не желателен: без него чем глубже размечено, тем меньше
находится, и учитель перестаёт размечать глубоко
([antipatterns.md](../../context/antipatterns.md), «Поиск без обхода
поддерева»).

Выбор узла ничем не ограничен: и Раздел, и Тема — законное условие поиска.
Это не противоречит правилу «Задачи несут только Темы»: Раздел здесь
не носитель Задач, а способ назвать их множество.

#### Scenario: Отбор по Разделу находит Задачи дальних потомков

- **WHEN** отбор идёт по Разделу, а Задача размечена Темой, лежащей на три
  уровня ниже него
- **THEN** Задача попадает в результат

#### Scenario: Отбор по Теме

- **WHEN** отбор идёт по узлу без потомков
- **THEN** возвращаются Задачи, размеченные этой Темой
- **AND** Задачи соседних Тем в результат не попадают

#### Scenario: Соседняя ветвь не попадает

- **WHEN** отбор идёт по Разделу, а Задача размечена Темой из другой ветви
  дерева
- **THEN** Задача в результат не попадает

#### Scenario: Задача, размеченная двумя Темами, возвращается один раз

- **WHEN** Задача размечена двумя Темами одного поддерева и отбор идёт
  по корню этого поддерева
- **THEN** Задача присутствует в результате ровно один раз

#### Scenario: Узла не существует

- **WHEN** условием поиска указан узел, которого в дереве нет
- **THEN** результат не показывается
- **AND** сообщается, что такого узла нет

### Requirement: Результат поиска показывает Задачи целиком и полностью

Система SHALL показывать каждую найденную Задачу её номером, подписью,
Частью, Темами, Методами и Характеристиками, и SHALL давать перейти
от строки результата к самой Задаче. Порядок — по номеру.

Система SHALL показывать число найденных Задач и SHALL возвращать все
найденные Задачи. Молчаливое усечение выдачи MUST NOT применяться: учитель
не отличает «больше нет» от «показано не всё», и решает он при этом, чего
в библиотеке не хватает
([ADR-0031](../../context/adr/0031-uslovija-poiska-po-biblioteke.md)).

Разметка показывается именами, а не идентификаторами, а Темы — полными
путями от корня: одинаковые имена под разными родителями законны, и в списке
результатов они были бы неразличимы.

Заданные условия SHALL оставаться видимыми вместе с результатом — выбранные
значения выбранными, выбранные способы соединения отмеченными. Иначе,
увидев тридцать строк, учитель не знает, каким прочтением он их получил.

#### Scenario: Строка результата

- **WHEN** Задача попала в результат
- **THEN** видны её номер, подпись, Часть, Темы, Методы и Характеристики
- **AND** из строки можно открыть саму Задачу

#### Scenario: Задача без подписи

- **WHEN** в результат попала Задача без подписи
- **THEN** она различима по своему номеру

#### Scenario: Размер результата назван

- **WHEN** поиск вернул Задачи
- **THEN** показывается, сколько их найдено
- **AND** показаны все найденные, без усечения

#### Scenario: Порядок результата

- **WHEN** поиск вернул несколько Задач
- **THEN** они идут по возрастанию номера

#### Scenario: Условия видны вместе с результатом

- **WHEN** поиск выполнен с двумя выбранными Методами и способом «все сразу»
- **THEN** вместе с результатом видно, что выбраны именно эти Методы
- **AND** видно, что выбран способ «все сразу»

### Requirement: Ищут все вошедшие, фильтра по владельцу нет

Система SHALL допускать поиск любому вошедшему Пользователю независимо
от ролей и SHALL возвращать двум разным Учителям по одним и тем же условиям
один и тот же результат.

У операции поиска нет и не может быть параметра «чей»: Задачи — общая
библиотека ([ADR-0004](../../context/adr/0004-mnogouchitelskaya-rabota.md),
[ADR-0027](../../context/adr/0027-mehanizm-granicy-obshchego-i-lichnogo.md)).
Фильтр по владельцу, применённый здесь, сделал бы библиотеку невидимой,
а выдачу заданий — невозможной, и произошло бы это молча.

Поиск ничего не меняет, поэтому роль Администратора для него не требуется.

#### Scenario: Учитель ищет

- **WHEN** вошедший Пользователь с ролью Учителя ищет Задачи
- **THEN** поиск выполняется и возвращает результат

#### Scenario: Два Учителя видят одно и то же

- **WHEN** два разных Учителя ищут по одинаковым условиям
- **THEN** оба получают один и тот же набор Задач, независимо от того, кто
  и когда их завёл

#### Scenario: Невошедший не ищет

- **WHEN** поиск запрашивается без входа в систему
- **THEN** результат не возвращается
