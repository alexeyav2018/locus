## Purpose

Сборка PDF условия или решения Задачи из картинок и диапазонов страниц
загруженных PDF — вместо того, чтобы Администратор готовил PDF вне системы.
Исходники живут временными черновиками сборки загрузившего и убираются
попутно; в хранилище ложится только собранный PDF, содержащий лишь то, что
нужно взятым страницам
([ADR-0041](../../context/adr/0041-sborka-pdf-zadachi.md)).

## Requirements

### Requirement: PDF слота Задачи собирается из картинок и страниц PDF

Система SHALL давать Администратору у каждого из двух слотов Задачи —
условия и решения — собрать PDF из источников вместо того, чтобы приложить
готовый. Инструмент доступен при заведении Задачи и при замене файла,
пока Задача не заморожена (сценарий С1
[scenarios.md](../../context/scenarios.md),
[ADR-0041](../../context/adr/0041-sborka-pdf-zadachi.md)).

Источник — картинка (JPEG или PNG) либо PDF с указанием диапазона **целых**
страниц «с … по …». Источников у одного результата может быть несколько;
страницы результата идут в порядке, заданном Администратором, а внутри
диапазона — в порядке сборника. Один и тот же загруженный исходник может
дать несколько диапазонов, в том числе одному слоту условие, другому решение.

Картинка MUST становиться ровно одной страницей, размер которой задан
самой картинкой, без подгонки под формат листа. Картинка MUST NOT
ужиматься до предела сканов Работ, и её ориентация MUST сохраняться такой,
какой её видел снимавший.

Система MUST NOT интерпретировать содержимое источников: страница PDF
переносится целиком, с тем, что нарисовано в её содержимом; текст
и формулы не распознаются и не хранятся. Пометки поверх страницы — ссылки,
комментарии — не переносятся.

На одном слоте MUST приниматься либо готовый PDF, либо порядок сборки,
но не оба сразу.

#### Scenario: Задача из трёх картинок

- **WHEN** Администратор заводит Задачу, собрав PDF условия из трёх картинок
  в заданном порядке
- **THEN** PDF условия Задачи содержит три страницы
- **AND** страницы идут в заданном порядке

#### Scenario: Страницы из большого сборника

- **WHEN** Администратор собирает PDF из 300-страничного PDF, указав
  страницы 47–49
- **THEN** результат содержит ровно три страницы — 47-ю, 48-ю и 49-ю
  сборника

#### Scenario: Несколько источников в одном результате

- **WHEN** Администратор собирает PDF из диапазона сборника, затем картинки,
  затем другого диапазона того же сборника
- **THEN** страницы результата идут в этом порядке

#### Scenario: Один сборник на условие и решение

- **WHEN** Администратор заводит Задачу, собрав условие из страниц 47–48
  загруженного сборника, а решение — из его страницы 210
- **THEN** Задача заведена с двумя собранными PDF
- **AND** сборник для этого загружен один раз

#### Scenario: Снимок, сделанный повёрнутой камерой

- **WHEN** в сборку входит снимок, у которого ориентация задана
  сведениями о съёмке, а не порядком пикселей
- **THEN** страница результата показывает его в той ориентации, в какой
  его видел снимавший

#### Scenario: Диапазон за пределами сборника

- **WHEN** Администратор указывает диапазон, выходящий за число страниц
  загруженного PDF, или начало диапазона позже его конца
- **THEN** PDF не собирается
- **AND** сообщается, какой источник указан неверно и сколько в нём страниц

#### Scenario: Готовый PDF и сборка на одном слоте

- **WHEN** Администратор на одном слоте и прикладывает готовый PDF,
  и задаёт порядок сборки
- **THEN** Задача не сохраняется
- **AND** сообщается, что нужно выбрать один способ

#### Scenario: Замена файла сборкой

- **WHEN** Администратор заменяет PDF решения ещё не использованной Задачи
  собранным из картинок
- **THEN** PDF решения Задачи заменён собранным
- **AND** прежний файл решения удалён из хранилища

#### Scenario: Замена файла сборкой у замороженной Задачи

- **WHEN** Администратор пытается заменить PDF выданной Задачи собранным
- **THEN** замена отклоняется так же, как замена готовым PDF

### Requirement: Результат содержит только взятые страницы

Система SHALL складывать в собранный PDF только то, что нужно взятым
страницам. Картинки, шрифты и прочие ресурсы страниц, которые не брались,
MUST NOT попадать в результат — в том числе когда страницы сборника делят
общий словарь ресурсов. Объём результата соразмерен взятым страницам,
а не исходнику.

Исходник у Задачи MUST NOT храниться: в хранилище ложится только
собранный PDF.

#### Scenario: Страницы с общим словарём ресурсов

- **WHEN** из сборника, где все страницы делят один словарь ресурсов,
  а каждая рисует свою крупную картинку, собираются три страницы
- **THEN** в результате ровно три картинки — тех трёх страниц
- **AND** объём результата соразмерен трём картинкам, а не всем

#### Scenario: Шрифты не взятых страниц

- **WHEN** из сборника, где разные страницы набраны разными шрифтами,
  собирается страница, набранная одним из них
- **THEN** в результате нет шрифтов, которыми набраны только не взятые
  страницы

#### Scenario: Ссылка на соседнюю страницу

- **WHEN** на взятой странице есть ссылка на страницу, которая не бралась
- **THEN** не взятая страница в результат не попадает

### Requirement: Исходник — черновик сборки загрузившего

Система SHALL хранить загруженный для сборки исходник как **черновик
сборки** — временный, принадлежащий загрузившему Пользователю — до тех пор,
пока из него не собран PDF. Загружать черновики MAY только Администратор:
Задачи ведёт он.

Чужого черновика Пользователь MUST NOT видеть и использовать ни одним
запросом: обращение к нему отклоняется так же, как к несуществующему.

Исходник, который не является картинкой JPEG или PNG либо разбираемым PDF,
MUST отклоняться при загрузке, а не при сборке. PDF, закрытый паролем
на открытие, отклоняется с объяснением.

Собранный PDF ложится в слот Задачи; черновики, из которых он собран,
MUST удаляться после того, как Задача сохранена. Если Задача не
сохранилась — отказом правила или ошибкой, — черновики MUST оставаться,
чтобы Администратор мог исправить форму, не загружая сборник заново.

#### Scenario: Загрузка сборника

- **WHEN** Администратор загружает для сборки PDF
- **THEN** создаётся его черновик сборки
- **AND** Администратору показывается число страниц, чтобы указать диапазон

#### Scenario: Чужой черновик

- **WHEN** Администратор указывает в порядке сборки черновик, загруженный
  другим Администратором
- **THEN** PDF не собирается
- **AND** ответ не отличается от ответа на несуществующий черновик

#### Scenario: Учитель загружает исходник

- **WHEN** Учитель без роли Администратора загружает исходник для сборки
- **THEN** загрузка отклоняется

#### Scenario: Неподходящий исходник

- **WHEN** Администратор загружает для сборки файл, не являющийся ни
  картинкой JPEG или PNG, ни PDF
- **THEN** черновик не создаётся
- **AND** сообщается, какие исходники принимаются

#### Scenario: Черновики уходят после сборки

- **WHEN** Задача сохранена с собранным PDF
- **THEN** черновики, из которых он собран, удалены

#### Scenario: Отказ формы не теряет черновики

- **WHEN** Администратор заводит Задачу с собранным PDF, но без Метода
- **THEN** Задача не создаётся
- **AND** форма показывает тот же порядок сборки с теми же черновиками

### Requirement: Брошенный черновик убирается попутно

Система SHALL убирать черновики, из которых так и не собрали PDF, без
расписания и фоновых процессов
([ADR-0017](../../context/adr/0017-net-uvedomlenij.md)): при каждом
открытии инструмента удаляются черновики всех Пользователей старше срока,
заданного настройкой; при старте приложения удаляются все черновики.

Уборка MUST NOT возвращать и показывать черновики: она только удаляет.

#### Scenario: Брошенный черновик при следующем открытии

- **WHEN** черновик загружен и не использован, срок прошёл, и кто-либо
  открывает инструмент
- **THEN** черновика больше нет

#### Scenario: Свежий черновик при открытии во второй вкладке

- **WHEN** Администратор загрузил черновик и, не завершив форму, открывает
  инструмент ещё раз до истечения срока
- **THEN** черновик на месте и из него можно собрать PDF

#### Scenario: Черновик после перезапуска

- **WHEN** приложение перезапущено
- **THEN** ни одного черновика нет

### Requirement: Предел загрузки поднят только для инструмента

Система SHALL принимать исходник для сборки крупнее общего предела
загрузки — сборник весит десятки мегабайт. Предел инструмента задаётся
настройкой.

Прочие загрузки — готовые PDF Задачи, файлы Теории, файлы Работ — MUST
держать общий предел: 20 МБ на файл и 100 МБ на запрос, тоже из настройки.

#### Scenario: Крупный сборник

- **WHEN** Администратор загружает для сборки PDF крупнее общего предела,
  но в пределах инструмента
- **THEN** черновик создаётся

#### Scenario: Работа того же объёма

- **WHEN** Учитель принимает Работу с файлом того же объёма
- **THEN** приём отклоняется сообщением о пределе, как и прежде
