## Purpose

Задача — единица общей библиотеки и то, ради чего заводились рубрикатор,
словари и хранилище файлов. Описывает состав Задачи (два PDF, разметка,
номер и подпись), её заведение и разметку Администратором, просмотр,
список Задач Темы, выборку уже встречавшихся в Теме Методов и правила
правки и удаления. Текста Задачи система не знает, поэтому разметка —
единственный вход в неё.

## Requirements

### Requirement: Задача состоит из двух PDF и разметки

Система SHALL хранить Задачу как два файла PDF — условие и решение — вместе
с разметкой. Оба файла обязательны: Задача без любого из них не сохраняется.
Формулы система не хранит, не разбирает и не отображает самостоятельно —
они живут внутри PDF
([ADR-0008](../../context/adr/0008-zadacha-dva-pdf.md)).

Обязательность обоих файлов — прочтение ADR-0008 буквально: Задача без решения
обнаружит свою неполноту только в момент проверки Работы ученика, когда
решение понадобится, а искать его будет поздно.

Задача принадлежит общей библиотеке и существует независимо от того, кому
и когда она выдавалась.

#### Scenario: Задача заведена

- **WHEN** Администратор заводит Задачу, приложив PDF условия и PDF решения
  и указав разметку
- **THEN** Задача появляется в библиотеке
- **AND** оба файла доступны при её просмотре

#### Scenario: Нет PDF решения

- **WHEN** Администратор заводит Задачу, приложив только PDF условия
- **THEN** Задача не создаётся
- **AND** сообщается, какого файла не хватает

#### Scenario: Нет PDF условия

- **WHEN** Администратор заводит Задачу, приложив только PDF решения
- **THEN** Задача не создаётся

### Requirement: Разметка Задачи — Темы, Методы, Характеристики и Часть

Система SHALL размечать Задачу по четырём измерениям с разной обязательностью
([ADR-0009](../../context/adr/0009-razmetka-zadachi.md)):

| Измерение | Кратность | Роль |
| --- | --- | --- |
| Тема | 1..n, только листья дерева | поиск и ось измерения владения |
| Метод | 1..n, минимум один обязателен | поиск и ось измерения владения |
| Характеристика | 0..n | только поиск |
| Часть | ровно одна | только поиск и подбор |

Задача без Темы или без Метода MUST NOT сохраняться. Минимум один Метод
обязателен потому, что отметка Владения живёт на паре «Тема × Метод»
([ADR-0011](../../context/adr/0011-otmetka-na-pare.md)): Задача без
Методов не порождает ни одной ячейки и остаётся немой для статистики.
Обнаружилось бы это через полгода, по пустым ячейкам.

Привязка Задачи к Разделу MUST отклоняться: Задачи несут только Темы —
листья дерева (инвариант 1,
[domain-model.md](../../context/domain-model.md),
[ADR-0006](../../context/adr/0006-rubrikator-derevo.md)).

#### Scenario: Разметка несколькими Темами и Методами

- **WHEN** Администратор размечает Задачу двумя Темами и тремя Методами
- **THEN** Задача сохраняется
- **AND** при просмотре видны все указанные Темы и Методы

#### Scenario: Задача без Темы

- **WHEN** Администратор сохраняет Задачу, не указав ни одной Темы
- **THEN** Задача не сохраняется
- **AND** сообщается, что нужна хотя бы одна Тема

#### Scenario: Задача без Метода

- **WHEN** Администратор сохраняет Задачу, не указав ни одного Метода
- **THEN** Задача не сохраняется
- **AND** сообщается, что нужен хотя бы один Метод

#### Scenario: Попытка привязать Задачу к Разделу

- **WHEN** Администратор указывает Задаче узел дерева, у которого есть потомки
- **THEN** Задача не сохраняется
- **AND** сообщается, что Задачи несут только Темы

#### Scenario: Характеристики необязательны

- **WHEN** Администратор сохраняет Задачу, не указав ни одной Характеристики
- **THEN** Задача сохраняется

#### Scenario: Часть указывается ровно одна

- **WHEN** Администратор сохраняет Задачу, не указав Часть
- **THEN** Задача не сохраняется
- **AND** указать обе Части одновременно невозможно

### Requirement: Задача различается номером и подписью

Система SHALL показывать Задачу её **номером** — монотонно возрастающим
значением, которое Задача получает при заведении и больше не меняет, —
и **подписью**: короткой строкой свободного вида, которую Администратор
задаёт по желанию («Сборник Ященко, вариант 12, № 8»). Подпись
необязательна; пустая подпись — законное состояние Задачи.

Имени у Задачи нет, а предпросмотр первой страницы PDF — отдельная работа
([ADR-0008](../../context/adr/0008-zadacha-dva-pdf.md), «Последствия»).
Без номера и подписи три десятка задач одной Темы с одинаковой разметкой
дают в списке три десятка одинаковых строк, и отличить их можно только
открыв каждый файл ([ADR-0029](../../context/adr/0029-nomer-i-podpis-zadachi.md)).

Номер SHALL быть виден Администратору и Учителю: по нему Задача называется
в разговоре и находится в списке.

#### Scenario: Номер выдан при заведении

- **WHEN** Администратор заводит Задачу
- **THEN** у Задачи появляется номер
- **AND** номер больше номера Задачи, заведённой раньше

#### Scenario: Задача без подписи

- **WHEN** Администратор заводит Задачу, не заполнив подпись
- **THEN** Задача сохраняется
- **AND** в списке она различима по своему номеру

#### Scenario: Подпись показывается в списке

- **WHEN** у Задачи задана подпись
- **THEN** список Задач показывает её рядом с номером

### Requirement: Ведёт Задачи только Администратор, читают все вошедшие

Система SHALL допускать заведение, правку и удаление Задачи только
Пользователю с ролью Администратора. Просмотр Задач доступен любому вошедшему
Пользователю независимо от ролей.

Задачи — общая библиотека. Они **не фильтруются по владельцу**: у операций
чтения нет и не может быть параметра «чей»
([ADR-0004](../../context/adr/0004-mnogouchitelskaya-rabota.md),
[ADR-0027](../../context/adr/0027-mehanizm-granicy-obshchego-i-lichnogo.md)).
Фильтр, применённый к библиотеке, сделал бы её невидимой, а выдачу заданий —
невозможной.

#### Scenario: Учитель читает библиотеку

- **WHEN** вошедший Пользователь с ролью Учителя открывает Задачу
- **THEN** показываются её разметка, номер, подпись и оба файла

#### Scenario: Учитель пытается изменить библиотеку

- **WHEN** Пользователь без роли Администратора пытается завести, изменить
  или удалить Задачу
- **THEN** операция отклоняется
- **AND** библиотека остаётся прежней

#### Scenario: Задачи, заведённые другим Пользователем

- **WHEN** библиотеку открывают два разных Учителя
- **THEN** каждый видит все Задачи, независимо от того, кто и когда их завёл

#### Scenario: Невошедший к Задачам не допускается

- **WHEN** Задача запрашивается без входа в систему
- **THEN** ни разметка, ни файлы не показываются

### Requirement: Файлы Задачи отдаются только по временной подписанной ссылке

Система SHALL отдавать PDF условия и PDF решения исключительно по временным
подписанным ссылкам, выдаваемым хранилищем
([file-storage](../file-storage/spec.md)). Постоянного адреса
у файла Задачи нет.

Требование обязательно, а не желательно: PDF с решениями не должны попадать
к ученикам, а угаданный или переданный дальше постоянный адрес обошёл бы
вход в систему целиком
([ADR-0021](../../context/adr/0021-hranilishche-fajlov.md)).

PDF MUST сохраняться байт в байт: пережатие применяется к изображениям
и не применяется к PDF.

#### Scenario: Просмотр Задачи

- **WHEN** вошедший Пользователь открывает Задачу
- **THEN** оба файла доступны по ссылкам, действующим ограниченное время

#### Scenario: Ссылка после истечения срока

- **WHEN** обращение по ссылке на файл Задачи происходит после истечения
  её срока
- **THEN** содержимое не возвращается

### Requirement: Методы, уже встречавшиеся в Теме

Система SHALL по указанной Теме возвращать Методы, которыми размечена хотя бы
одна Задача этой Темы. Выборка идёт **по разметке Задач**, а не по словарю:
у записи словаря нет и не может быть принадлежности Теме
([ADR-0010](../../context/adr/0010-slovar-metodov-ploskij.md)).

Форма разметки SHALL при выборе Метода показывать сначала эту выборку,
а полный словарь SHALL быть доступен отдельным действием
([ADR-0009](../../context/adr/0009-razmetka-zadachi.md), «Последствия»;
[scenarios.md](../../context/scenarios.md), С1). Словарь Методов —
общий и плоский, и на сотне записей выбор из полного списка превращается
в перебор, при котором Администратор заводит смысловой дубль вместо того,
чтобы найти существующую запись.

Выборка не ограничивает выбор: любой Метод словаря можно указать Задаче
независимо от того, встречался ли он в этой Теме раньше.

#### Scenario: Методы Темы

- **WHEN** запрашиваются Методы Темы, в которой размечены две Задачи —
  одна двумя Методами, другая одним из тех же и ещё одним
- **THEN** возвращаются все три Метода, каждый один раз

#### Scenario: Тема без Задач

- **WHEN** запрашиваются Методы Темы, в которой Задач нет
- **THEN** выборка пуста
- **AND** полный словарь Методов остаётся доступным

#### Scenario: Метод из другой Темы

- **WHEN** запрашиваются Методы Темы, а тот же Метод употреблён только
  в Задачах соседней Темы
- **THEN** этот Метод в выборку не попадает

#### Scenario: Разметка Методом, в Теме не встречавшимся

- **WHEN** Администратор размечает Задачу Методом, которого в этой Теме
  ещё не было
- **THEN** Задача сохраняется
- **AND** этот Метод входит в выборку Темы при следующем обращении

### Requirement: Задачи показываются на выбранной Теме

Система SHALL показывать Задачи выбранной Темы списком: номер, подпись,
Методы, Характеристики и Часть каждой Задачи. Сортировка — по номеру.

Выбранный **Раздел** SHALL сообщать, что Задачи живут только на Темах,
и MUST NOT показывать вместо этого пустой список. Задач на Разделе не бывает
никогда (инвариант 1), и пустой список выглядел бы как ответ «здесь ничего
нет» — из которого Администратор делает вывод, что Тему надо наполнять,
и заводит дубли уже существующих Задач.

Поиска здесь нет: обход поддерева и фильтры по Методу, Характеристике и Части
появятся отдельно (`library-search`). Этот список отвечает на вопрос «что
лежит на этой Теме», а не «где во всей библиотеке есть такие Задачи».

#### Scenario: Список Задач Темы

- **WHEN** Администратор выбирает Тему, на которой размечены Задачи
- **THEN** показываются все её Задачи
- **AND** у каждой видны номер, подпись и метки

#### Scenario: Тема без Задач

- **WHEN** выбирается Тема, на которой Задач нет
- **THEN** список пуст
- **AND** завести Задачу на этой Теме всё равно можно

#### Scenario: Выбран Раздел

- **WHEN** выбирается узел, у которого есть потомки
- **THEN** список Задач не показывается
- **AND** сообщается, что Задачи несут только Темы

#### Scenario: Задача, размеченная двумя Темами

- **WHEN** Задача размечена двумя Темами и открывается каждая из них
- **THEN** Задача показывается в списке обеих

### Requirement: Задача правится и удаляется только до первого использования

Система SHALL позволять Администратору изменить любую часть Задачи — разметку,
подпись, любой из двух PDF — и удалить Задачу целиком, **только пока Задача
не использована**. Использованной считается Задача, вошедшая хотя бы в одно
Задание или имеющая хотя бы одну Работу.

Заданий и Работ в системе сейчас не существует, поэтому условие выполняется
всегда и действующих ограничений на правку и удаление нет. **Появление
Заданий обязано пополнить эту проверку**: правка разметки выданной Задачи
меняет основание ячеек владения задним числом, а удаление Задачи стирает
у чужого учителя смысл его Работы — оба события тихие и невосполнимые
([ADR-0030](../../context/adr/0030-zadacha-zamorazhivaetsya-posle-vydachi.md)).

Номер Задачи MUST оставаться неизменным при любой правке.

#### Scenario: Разметка изменена

- **WHEN** Администратор добавляет Задаче ещё один Метод
- **THEN** Задача показывается с новым набором Методов
- **AND** её номер не меняется

#### Scenario: Правка не снимает обязательности

- **WHEN** Администратор убирает у Задачи последний Метод
- **THEN** правка отклоняется
- **AND** разметка Задачи остаётся прежней

#### Scenario: Задача удалена

- **WHEN** Администратор удаляет Задачу, не вошедшую ни в одно Задание
- **THEN** Задача исчезает из библиотеки
- **AND** её номер не достаётся другой Задаче

#### Scenario: Разметка соседних Задач не задета

- **WHEN** Администратор удаляет Задачу
- **THEN** прочие Задачи той же Темы остаются на месте
- **AND** записи словарей и узлы дерева не меняются

### Requirement: Файлы Задачи не остаются в хранилище без Задачи

Система SHALL удалять из хранилища PDF, переставший принадлежать Задаче:
оба файла при удалении Задачи и заменённый файл при замене.

Кроме кода Задачи, распознать ненужный файл некому: хранилище не знает,
чьё содержимое лежит по ключу и что это вообще такое
([file-storage](../file-storage/spec.md)). Оставленный файл
уже ничем не адресуется — ссылки на него нет нигде, — и отличить его
от нужного впоследствии невозможно.

#### Scenario: Удаление Задачи уносит оба файла

- **WHEN** Администратор удаляет Задачу
- **THEN** ни условие, ни решение больше не отдаются по ранее выданным
  ссылкам

#### Scenario: Замена PDF

- **WHEN** Администратор заменяет PDF решения другим файлом
- **THEN** Задача отдаёт новое решение
- **AND** прежний файл в хранилище не остаётся

#### Scenario: Второй файл при замене не задет

- **WHEN** Администратор заменяет PDF решения
- **THEN** PDF условия остаётся прежним, байт в байт
