# Батч бэклога

Периодический прогон `openspec/backlog.md`: таймер раз в десять минут
пытается поднять сессию Claude Code, та работает над **одним** элементом
очереди — доводит его до слияния в `develop` либо продвигает настолько,
насколько хватает контекста, — и завершается. Оркестратора нет: сессия сама
решает, что делать, по таблице порядка и состоянию репозитория.

## Управление

```bash
.claude/backlog-batch/locus-backlog start    # включить периодические запуски
.claude/backlog-batch/locus-backlog stop     # выключить расписание
.claude/backlog-batch/locus-backlog status   # что сейчас происходит
.claude/backlog-batch/locus-backlog attach   # подключиться к живой сессии
.claude/backlog-batch/locus-backlog kill     # прервать текущую задачу
```

`stop` останавливает **расписание**, а не текущую работу: начатая задача
доигрывает до конца. Прервать именно её — `kill`, и тогда незакоммиченное
останется в рабочем дереве как есть.

История запусков — `journalctl --user -u locus-backlog.service`.

## Как это устроено

| Часть | Где | Что делает |
| --- | --- | --- |
| расписание | `~/.config/systemd/user/locus-backlog.timer` | `OnCalendar=*:2/10`, круглосуточно |
| запуск | `~/.config/systemd/user/locus-backlog.service` | зовёт `locus-backlog run` |
| скрипт | `locus-backlog` | управление и подъём сессии в tmux |
| задание | `task-prompt.md` | что сессия делает; версионируется вместе с проектом |

**Замок — имя tmux-сессии `locus-backlog`.** `tmux new-session` отказывается
создать сессию с занятым именем, и очередной запуск таймера выходит на первой
же команде: Claude при этом не стартует, ни токена не тратится. Отдельного
файла-замка нет и не нужно — имя освобождается ровно тогда, когда процесс
закончился.

Служба `Type=oneshot` завершается сразу, а сессия продолжает жить в tmux.
Это не ошибка: замок держит tmux, а не systemd.

**`KillMode=process` в юните обязателен.** По умолчанию systemd после
завершения `ExecStart` гасит всё, что осталось в контрольной группе, —
включая только что порождённый tmux-сервер. Отказ выглядит как успех:
служба рапортует «запущена задача», в журнале ни одной ошибки, а сессии
нет. Первый запуск батча 10.09.2026 умер именно так.

## Принятые решения

Все — решения владельца, принятые при постройке 09.09.2026.

| Что | Как |
| --- | --- |
| расписание | круглосуточно; квоту батч делит с владельцем |
| остановка, обязательная | гейт `propose → apply`: владелец видит доменные решения до кода |
| остановки прочие | любая развилка, на любом шаге; уведомление приходит в браузер |
| после обрыва по квоте | продолжать с первого `[ ]` в `tasks.md`, **без** предварительной сборки |
| нарезка реализации | один раздел `tasks.md` за сессию, без оценок контекста |
| ломающие строки бэклога | брать как обычные, не спрашивая заранее |
| ветка | `backlog/<id>`, **не удаляется** — архив того, как задача решалась |
| коммит и пуш | перед **каждым** вопросом владельцу, снимками `wip: …` |
| уведомление | явным вызовом `PushNotification`, а не в надежде на харнесс |
| слияние | одним коммитом в `develop` при архивации |

Смысл пуша перед вопросом: владельцу приходит уведомление, он открывает
GitHub с телефона и смотрит артефакты. Не отправлено — уведомление бесполезно.

Смысл нарезки: главный расход — не холодный старт, а длина контекста,
помноженная на число ходов. В `apply` ходов сотни, и каждый платит долю
от всего накопленного; переполнение вдобавок вызывает сжатие, которое
обнуляет кэш. Резать по разделам `tasks.md` дешевле, чем тянуть одну
сессию до конца, и — в отличие от нарезки по фазам с одобрением через
Pull Request — не стоит ни одного живого вопроса владельцу: гейт и все
развилки остаются диалогом в живой сессии.

Порога по заполненности контекста нет намеренно. Изнутри сессии контекст
измерить нечем: `/context` набирает человек, а размер собственного
транскрипта (`$CLAUDE_CODE_SESSION_ID`) — мера косвенная, байты к токенам
относятся по-разному в зависимости от доли вывода команд. Правило «один
раздел за сессию» от измерений не зависит вовсе. Плата — холодный старт
на каждый раздел; она меньше, чем экономия на коротком контексте.

Отсюда же частое расписание: раз в десять минут вместо двадцати. Пустой
тик ничего не стоит — имя tmux-сессии занято, и Claude не стартует, —
а простой между разделами сокращается вдвое.

## Разовая настройка

Две вещи делаются руками один раз и в репозитории не живут.

**Deploy key.** Батч пушит ключом `~/.ssh/locus_backlog` — отдельным, без
пароля, потому что таймер срабатывает и тогда, когда владелец не залогинен
и GNOME keyring не поднят. Ключ надо добавить в репозиторий с правом записи:

```bash
gh repo deploy-key add ~/.ssh/locus_backlog.pub \
   --title "locus-backlog" --allow-write -R alexeyav2018/locus
```

Именно deploy key, а не аккаунтный ключ: утечка файла даёт запись в один
приватный репозиторий, а не доступ ко всему GitHub.

**Linger.** Без него пользовательские таймеры не работают, пока владелец
не залогинен, и круглосуточность окажется мнимой:

```bash
loginctl enable-linger vorotovalexey
```
